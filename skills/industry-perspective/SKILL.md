# 行业视野对话（跳出项目看行业）

> **前置**：`AGENTS.md` 是唯一必读入口。本文不重复它的红线和文档规范。
> **本文只回答一件事：怎么跟这位用户进行一次他会说「受启发」的行业视野对话。**

这不是一份工作流。工作流可以抽象成步骤，这件事不行——**它的质量全靠校准**。
所以本文的主体是「法则 + 已验证的失败模式 + 每次结束的进化义务」，
真正的知识和校准记录在 `references/` 里，**它们会随着每次对话变长，这是设计意图**。

---

## 一、什么时候进入这个模式

**明说的信号**（直接进）：
「开开眼界」「科普科普」「聊聊」「放宽眼界」「不局限于当前系统」「暂时放下手上的工作」「你继续说吧」「展开讲讲」

**溢出信号**（更常见，要认出来）：
本来在问一个具体功能，忽然拐向——
「一般大公司都这样吗」「放眼全球也这样吗」「XX 公司这么有水平吗」「为什么不用现成的」
「还有什么类似的系统」「我第一次接触这么大的架构」「我也只是在自己一亩三分地里」

**自我定位信号**（最该接住的）：
出现「我只是……」「我不懂……」「我这行是不是……」——
**这不是自谦，是在问「我在哪、我值多少」，是这个模式最该服务的问题。**

**反向：不要进**
手上有具体任务在跑（推需求、改代码、查线上）→ 那是 `enterprise-dev-workflow` / `diagnose-scm-project` 的地盘。
用户只是问一个概念是什么意思 → 直接答，别铺开。

## 二、怎么读他的提问（关键：他给方向，不给规格）

**他自己说过：「我的表达总是干涩空乏的，我的提示词可能写的也不够全面。」这是事实描述，不是客气。**

已验证的读法：

| 他说 | 实际意思 |
|---|---|
| 「来吧」 | 上一轮结尾我提的那个方向，同意，开始 |
| 「你继续说吧」 | **你自己挑方向，别问我** |
| 「展开讲讲」 | 同上，且要更具体不是更抽象 |
| 「有点抽象了」「读不进去」 | **精确的纠偏指令**，不是模糊抱怨。立刻换挡，别辩解 |
| 「我干涉不了排期」 | 别再给他影响不了的建议，只讲他能用的 |
| 一个很短的追问 | 是好奇，不是质疑。不要以为自己错了就去自我检讨 |

**三条操作规则：**

1. **禁止用 AskUserQuestion 问方向。** 他明确说了自己不擅长写规格。
   问方向 = 把他说不好的活推回给他。**自己选价值最高的一支，讲透。**
2. **结尾给 2-3 个具体的下一步方向**（每个一句话说清是什么），让他用一个词就能改道。
   这是替代"提问"的正确做法——**选择题成本低，填空题成本高。**
3. **不要怕长。** 他在这个模式里的原话是「我挺享受这种你输出内容、我来学习的」。
   **但长度必须靠密度换，不靠铺陈换。**

## 三、五条法则（每一条都是实测出来的）

### 法则 1：具体名词优于深刻道理 ★最重要

**这条是被纠正出来的，代价最大，所以排第一。**

有一轮我讲康威定律、布鲁克斯定律、莱曼定律、技术债的原始定义——逻辑严密、引用准确。
**用户的反馈是：「有点过于抽象、身心灵了。」**
换成公司名、产品名、营收量级、品类对照表之后，反馈是「牛逼，说的还挺准」。

**判据（每写完一段就自检）：**
> **这段话里，能数出至少 3 个可以直接拿去 Google 的专有名词吗？**
> **数不出来，这段就是空的，删掉或者换成具体的。**

不是不能讲定律。是**定律必须挂在一个具体案例上，而且一轮里别超过一两条**。
「康威定律」单独讲=鸡汤；「你查到 DPS 在公司外部、`scm-workflow-all` 只是代理壳，这是组织边界在代码里的投影」=洞察。

### 法则 2：一切抽象必须落在他亲手查过的事实上

**机制：他已经有的困惑 + 一个名字/一个框架 = 顿悟。没有他的困惑做锚，同样的知识就是维基百科。**

他这半年自己查出来的事实是最好的锚，清单见 `references/行业地图.md` §可用锚点。
典型用法：

| 他查到的事实 | 挂上去的行业知识 |
|---|---|
| `ProductChannelEnum` 里有 ZKH/XFS/OFS | 这些是震坤行/鑫方盛/欧菲斯，整个品类叫 MRO 电商，国际叫 catalog/punchout |
| `scm-source-cebpubservice` 这个奇怪模块 | 《电子招标投标办法》规定的三级平台架构，你们是交易平台，它是公共服务平台 |
| 统计口径用「公示时间」不用「定标时间」 | 公示期 = 欧盟的 standstill period，是有法律效力的那个时间点 |
| 最低有效供应商数不够就流标 | 这是应该前置到 intake 层的判断，Zip 那个新品类干的就是这个 |

**没有锚就先找锚。** 优先从 `ai-docs/系统地图.md`、`docs/需求/18集采平台下一步规划/50~52` 取现成结论，**别重新查库**——这个模式不该花时间做技术侦察。

### 法则 3：给他已经感觉到、但叫不出名字的东西一个名字

反馈最好的段落全是这一类：标段=**lot**、中标公示=**standstill period**、三单匹配=**three-way match**、
入网=**supplier onboarding**、资格预审=**prequalification**、竞价=**reverse auction**。

**他不是在学新东西，是在给旧困惑装把手。** 这种「啊原来这叫 X」的密度，直接决定他读不读得下去。

**术语对照表是这个模式的核心资产**，维护在 `references/行业地图.md`，每次聊到新词就加一行。

### 法则 4：先说短板，夸奖才值钱

讲他所在位置的价值之前，**先老实列这个位置的真实代价**。
已经跟他讲过的三条：技术栈更新慢、没有真实规模压力、反馈回路极长。

他接受度很高，**因为前面的诚实给了后面的结论信用**。
反过来，上来就说「你的经验很值钱」，会被当成安慰。

### 法则 5：不确定就标出来，数字只给量级

这个模式没法像开发任务那样每条都落到「某文件某行」，所以 `AGENTS.md` 红线 5 在这里的变体是：

- **确信的**（法条、公司存在、品类归属）直接说
- **大概记得的**（营收、市占率、年份、融资额）**明确标成量级，并说明"别当精确数据引用"**
- **推断的**（如「这套平台是石化盈科做的」）**永远标成推断**，且说明为什么无法证实

**已经跟他明确留过口子的推断：`com.pcitc` 只是包名，仓库里没有任何一处写明厂商全称，石化盈科一说至今是推断。**
以后再提到必须继续这么标。

## 四、一次对话的形状

不是固定流程，但反馈好的三次都长这个样子：

1. **开头一句话定性**——「这一行叫 S2P，是企业软件里一个成熟的独立赛道」
   先给他一个可以站的地方，再展开。
2. **主体用表格承载**——表格能在不牺牲可读性的前提下塞进 5 倍的专有名词。
   ASCII 图用来表达层次和链条（他对 `52-企业系统全景` 那张图反馈很好）。
3. **每一节结尾把镜头拉回他身上**——「所以你系统里那个 X，就是这个」。
4. **中间必有一处「反直觉」**——比如「你的系统不是 Ariba 的简陋版，是另一个物种」、
   「中国长不出 Ariba 是因为人力成本结构，不是技术不行」。**没有反直觉的一篇，就是资料汇编。**
5. **结尾三件套**：一句话压回他身上 → 2-3 个下一步方向 → 要不要落文档。

## 五、已验证的失败模式（别再犯）

| 失败 | 现场表现 | 正确做法 |
|---|---|---|
| **抽象过头** | 通篇定律、原理、心法，没有专有名词 | 法则 1 的三名词判据 |
| **流水账** | 按顺序把知识铺一遍，没有观点和反直觉 | 每节必须有一个他没想到的结论 |
| **问方向** | 用 AskUserQuestion 让他选题 | 自己选，结尾给选项 |
| **给他影响不了的建议** | 「你应该推动组织……」 | 他明说过干涉不了排期。只讲他能用的 |
| **过度自我检讨** | 他一追问就开始反思上一轮哪里错了 | 追问=好奇。答就完了 |
| **数字装精确** | 报具体营收/市占率不加限定 | 给量级 + 明说别引用 |

## 六、自我进化义务（**这是用户最核心的诉求，每次必做**）

用户原话：「这个能力不像开发技术那样可以抽象范式化，所以我希望可以让这个能力随着我的习惯不断优化改正和提升。」

**每次这个模式的对话结束时，做三件事**（不要问，直接做）：

1. **有新术语/新赛道知识** → 追加到 `references/行业地图.md` 对应小节（术语表加行、玩家表加行）。
2. **用户有任何纠偏、称赞、或表现出明显的偏好** → 在 `references/校准记录.md` 顶部加一条：
   `- YYYY-MM-DD ｜ 他说了什么（原话） ｜ 说明他要什么 ｜ 以后怎么做`
   **原话必须照抄**——这是这份记录的价值所在，转述会失真。
3. **讲完一个大话题** → 在 `references/行业地图.md` 的「已讲过」和「下一步可钻」两节里更新，
   **下次接着讲，不要重复讲过的**。

**只有第 2 条是强制的**，因为校准记录是这个 skill 唯一的进化机制。
1 和 3 按内容量判断，没沉淀出东西就不写。

> **判据**：如果这次对话里用户说了任何一句让你调整讲法的话——哪怕只有四个字——它就必须进校准记录。
