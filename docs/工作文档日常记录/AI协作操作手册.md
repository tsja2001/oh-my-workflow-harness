# AI 协作操作手册（写给我自己）

> 每次和新 session 的 AI 交手时怎么开头、怎么验收、怎么把整个工作流越用越顺。
> 2026-08-07 按新的文档结构更新过一次。

## 一、开场公式：读什么 + 干什么 + 产出到哪

任何新 session，开场白只需要三件事。**模型越便宜，越要写死这三样。**

**万能开场（复制就用）：**

```text
先读 AGENTS.md，照里面的规矩干活。
任务：<一句话说清楚>
产出：<写到哪个文件 / 改哪个主题文件夹>
```

现在只需要点名 `AGENTS.md` 一份——它自己会告诉 AI「遇到什么事去翻哪一份」，AI 不用也不该开工前把 `ai-docs/` 通读一遍。

**按阶段开场（更省事）：** 打开 `skills/enterprise-dev-workflow/references/prompts.md`，
里面有现成提示词（P0 快速任务 / P1 拆解 / P2 开发 / P3 测试 / P4 评审 / P5 临时文档 / P6 复盘 / **P7 线上排查**），
整段复制，把 `<主题名>` 替换掉就行。它们已经把"读什么、产出什么文件名、禁止做什么"全写死了，便宜模型也不容易跑偏。

**小任务**（找个东西/改几行）：用 P0 开场——AI 会按分级来：只查不改不留档；小改会记一条到 `ai-docs/工作日志.md`
（这是所有 AI 的共享流水账，你想知道"之前的 AI 都干了啥"看这一个文件就够）。

**线上出问题**（页面报错、没数据、任务失败）：用 P7，它会走 `diagnose-scm-project` 那套只读排查命令，
不会上来就猜，也不会顺手改东西。

**各工具的差别：**
- **Claude Code**：skill 会自动触发（`.claude/skills/` 里有加载器），理论上说句"做 XX 需求"就行；但保险起见开场白照贴。
- **Codex / OpenCode / 其他**：不会自动读，**必须**贴开场白或阶段提示词。

**中途换 AI 接力时**，多加一句：

```text
前情都在 docs/需求/<主题名>/ 里，按文件编号从小到大读完再动手，不要问我之前发生了什么。
```

## 二、放行前的验收（我不懂 Java 也能查）

动手前让它过一关：**"复述一下你打算做什么、改哪些文件、怎么算做完"**——复述不对就不放行。

干完后看四点：

1. 它的结论有没有证据（文件:行 / 数据库查询结果）？只有"我认为"没有证据的，让它去核实。
2. 有没有按规范写交接文档（`<段号>-<中文短名>-<工具>.md`）？没写不算完。
   段号只有六个：`00` 输入 / `10` 想清楚 / `20` 动过之后 / `30` 别人来验 / `50` 交还理解 / `90` 其它。
3. `git status` 是不是只有它该改的文件？有没有偷偷 push（**push 必须我点头**）？
4. 需要我做的事有没有攒成一个清单？零碎打断我的，让它改。

## 三、效率方法论

- **智力分层**：贵模型干"定义问题"（拆解、方案、踩坑排雷），便宜模型干"执行清晰指令"（照文档开发、测试、评审）。给便宜模型的任务永远带验收标准。
- **文档即记忆**：交接文档写得好，换任何 AI 都能无损续跑；依赖聊天记录 = 又贵又乱。session 拖太长（感觉变笨/变慢）就果断开新的，开场让它读交接文档。
- **一次给全上下文**：开场把截图、curl、同事的答复一次性全贴上，别挤牙膏——来回追问烧的是 token 和时间。
- **并行开工**：互不相干的活可以两个工具同时跑（一个开发 A，一个测试 B），反正靠文档交接不打架。
- **验收驱动**：布置任务时说清"怎么算做完"（"删除后列表查不到才算通过"），AI 会自己测到达标为止。
- **小步提交**：每个能验证的小里程碑就让 AI 提交一次，出错好回退，也方便换 AI 接手。
- **让系统自己变聪明**：收工问一句"这次学到什么？该写进哪一份？"
  ——公司规矩进 `ai-docs/团队规矩.md`，会再犯的坑进 `ai-docs/经验教训.md`，代码库事实进 `ai-docs/代码库地图.md`。
  **注意**：如果一件事"做第二遍还要翻文档"，正确答案是让它做成 `scripts/` 里的脚本，不是再写一条笔记。
- **定期复盘我自己**：偶尔问 AI"这次哪里卡住了？我开场该多给你什么？"
- **别心疼提要求**：缺工具让 AI 直说，装一个工具往往省几十次绕路。

## 四、常见坑速查

| 现象 | 原因 / 处理 |
|---|---|
| AI 说接口 401 / 要我给 token | **不该发生了**——`scripts/auth.sh` 会自动登录。真出现就是账号密码变了或测试环境重新开了验证码，让 AI 跑 `bash scripts/auth.sh doctor` 看是哪种 |
| 要查数据 | 库：`bash scripts/dbq.sh "SQL"`；ES：`bash scripts/esq.sh`。全部工具见 `ai-docs/工具箱.md` |
| 找不到某个功能对应的前端页面 | `bash scripts/fe.sh find <中文关键词>`。**别让 AI 全树 grep**，52 个前端仓必踩错仓 |
| AI 命令报错 `$变量` 是空的 | wsl 边界吞变量 → 提醒它"复杂命令先写脚本文件再执行"（AGENTS.md §4） |
| AI 说全量编译失败 | 正常！SNAPSHOT 漂移，同事也不编译 → 让它用 `bash scripts/jc.sh` 单独验自己的文件 |
| 部署后功能没变化 | ① Jenkins 是不是真的重新构建了（两段式：`-all` 发 jar、`-web` 打镜像）；② 是不是有开关/字典没配 |
| AI 开始瞎猜表名/字段 | 让它"先 `dbq.sh` / `esq.sh` 查了再说"，规矩是核实不猜 |
| AI 把上一版文档覆盖了 | 违规。规矩是**只增不覆盖**，重做要新建带轮次后缀的文件 |

## 五、每天收工习惯（两分钟）

1. 让当前 AI 更新主文档顶部进度块 + 写好交接文档。
2. 问一句"有没有新规矩要写进 `ai-docs/`？有没有该做成脚本的？"
3. 顶层 git 提交一下文档（让 AI 做）：留痕、可回溯。**远程 push 我自己点头才行。**
