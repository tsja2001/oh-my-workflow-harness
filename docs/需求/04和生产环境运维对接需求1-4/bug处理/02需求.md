## 结论

1. 测试同事说“test 没有导出模板”是修复前的情况，现在已经不是：test 和 UAT 当前都有 `centralPurchaseStatistics` 11 列、`priceTrend` 9 列模板。
2. 导出列不是 Java 代码写死的。后端只开启导出能力，运行时根据 `exportTemplateCode` 到 UBM 的 `scm_simple_template`、`scm_simple_template_sub` 读取列名、顺序和响应字段名。
3. UAT 也不是完全没问题。实际下载发现 UAT 和 test 的日期都曾显示成 `Thu Jul 16 00:00:00 CST 2026` 这种 Java 默认格式，只是列数正常。
4. 两处根因不同：
   - 集采日统计接口返回的 `statisticsDate`、`createTime` 没有 Fastjson 格式定义，需要改 order 后端并部署。
   - 价格趋势接口已经生成正确的 `publishTimeStr`，但模板第 8 列错误地读取原始 Date 字段 `publishTime`；改模板即可，无需 source 发版。
