# 第一批（9/11）· 集采台账改造

今天的台账只能表达一句话：**"这个东西归集团管，全集团都得听。"**

1. **"这个东西归谁管"**——集团 / 二级集团 / 区域·企业，三档

表头   → 层级取最小、强管控有强取强

**所以这个接口必须改签名**，而**三个前端页面接收返回值的那段代码（复制粘贴的三份）都要跟着改**。

# 3. 两批的关系

## 3.1 能不能拆开上线？

**能。** 第一批做完之后，三个采购页面的**行为跟今天一模一样**——还是只盖一个"是否集采"的章、还是写死只读，只是不会崩。**可以独立上线、独立验证。**

## 3.2 但第一批内部不能再拆

**A（台账本体）和 B（4 处保命改造）必须一起上线。**

只上 A 不上 B 的话：台账一放开多行和末级类目，
**采购计划、采购方案、非平台录入三个页面会当场提交不了。**

> 📌 **这句话必须跟产品讲明白**——他那句"这块是【集采台账改造】部分"里没有 B，
> 因为他不知道底下有 `selectOne` 这回事。不讲的话，他会以为第一批就是改个列表页。

## 3.3 建议的推进顺序

```
本周      把 Q1、Q2、P1、P2、P3 五条问出来（前两条卡第一批，后三条卡第二批）
          同时把变量名表发给华姐 —— 她可以立刻开画，不用等我
   ↓
9/8~9/11  第一批：A + B 一起做、一起提测、一起上线
   ↓
9/12~9/18 第二批：接口改造 → 算值 → 前端 → 递变量
   ↓
上线      我的代码先发版，华姐后切流程图
```

# 4. 一页速查

| | 第一批（9/11） | 第二批（9/18） |
|---|---|---|
| **改什么** | 规矩怎么记 | 规矩怎么用 |
| **页面** | 集采范围台账（1 个） | 采购计划 / 采购方案 / 非平台录入（3 个） |
| **表** | `sc_plan_product_range` 加 4 列 + 改索引 | 4~5 张单据表各加 2 列 |
| **接口签名** | **不变**（这是关键，前端一行不动） | 🔴 判集采接口**要改** |
| **最大的一块** | 6 处读表加"状态=生效"（漏一处是静默故障） | 接口返回结构 + 三个前端跟着改 |
| **工作量【估】** | 5~6 人天 | 7~9 人天 |
| **卡在** | `10q` Q1、Q2 | `10r` P1、P2、P3 |
| **最阴的坑** | B2 漏一处不报错，只是悄悄不对 | P1 上线当天不暴露，等业务配了二级集团才炸 |
| **别人的活** | 无 | 华姐画分支图（可并行，越早给变量名越好） |

**合计【估】12~15 人天**，产品给的是 **9/8~9/18 共 9 个工作日**。

> 排期本身偏紧，但**真正的风险不是工时，是那 5 个待定问题**——
> 它们不定，前面几天的活是白做的（索引和优先级都得推倒重来）。
