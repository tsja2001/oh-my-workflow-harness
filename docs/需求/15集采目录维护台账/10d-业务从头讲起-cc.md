# 第一章 · 先搞清楚：这套系统到底在干嘛

## 1.1 金隅集团是个什么公司

北京金隅集团，底下**几百家公司**。你在库里能查到的就有 **854 个组织、613 家是"企业级"**。

它们分成十几个**板块**（系统里叫 BU）：

| 板块 | 干什么的 | 底下有多少家企业 |
|---|---|---|
| 冀东水泥 | 造水泥 | 194 |
| 投资物业 | 管楼、管物业 | 110 |
| 新材产业化 | 新型建材 | 74 |
| 地产 | 盖楼卖楼 | 78 |
| 混凝土 | 搅拌站 | 62 |
| 冀东集团 | 水泥+装备 | 46 |
| 天津建材 | 建材 | 23 |
| 其余（财务、研究院、京才、党校、国贸…） | | 40 左右 |

**记住这个"两层结构"，后面全靠它**：

```
        金隅集团（总部）
              │
    ┌─────────┼─────────┬─────────┐
  冀东水泥   地产集团   物业集团   …      ← 第二层，叫「二级集团」/「BU」
    │          │          │
 194 家企业  78 家企业  110 家企业        ← 第三层，叫「企业」
```

⚠️ **系统里就只有这两层，是平铺的，没有"区域"这一层**。这一点后面会反复咬人，先记着。

## 1.2 这套系统解决什么问题

这几百家公司每天都要买东西——买煤、买钢材、买轴承、买办公用品、买工程服务。

集团怕三件事：

1. **买贵了**——你从谁那儿买的？凭什么是他？
2. **买脏了**——是不是有人吃回扣？
3. **说不清**——审计来查，拿不出证据链。

于是有了这套 **招采平台**（"招"= 招标，"采"= 采购）。
它管的不是"要买什么"（那是生产系统的事），**它管的是"怎么把东西干净地买回来"**。

## 1.3 一笔采购在系统里要走哪几步

```
① 采购计划   →  ② 采购方案  →  ③ 挂公告  →  ④ 供应商投标
   "我要买"        "打算怎么买"    "招标了"      "我来报个价"

→ ⑤ 开标  →  ⑥ 评标  →  ⑦ 定标  →  ⑧ 合同 → 订单 → 收货 → 付款
   "拆封"      "专家打分"   "定谁中标"
```

**这次需求只碰最前面那两步**，而且只碰它们**点"提交"的那一瞬间**。
后面的开标评标定标合同，一个字都不动。

再补两个你会在文档里反复看到的名词：

- **采购计划**：采购员填的"我要 200 吨螺纹钢，什么时候要，大概多少钱"。这一步的意义是**给集团一个汇总的机会**——一百家厂各报 200 吨，攒在一起就是 2 万吨，才有资格去跟钢厂谈价。
- **采购方案**：计划批了之后，填"这 2 万吨打算怎么买"——公开招标还是询比价、分几个标段、评分怎么打。**这是整个平台最核心的一张单子。**

# 第二章 · "集采"是什么，为什么需要一张清单

## 2.1 分散买 vs 集中买

回到 1.1 那张图。**如果每家公司各买各的钢材**：

- 唐山那家买 200 吨，去找供应商谈；
- 石家庄那家买 300 吨，也去找供应商谈；
- 内蒙那家买 150 吨，再谈一次。

**几百家分头谈，谁都谈不出好价钱**，而且谁都可能被人吃回扣。

所以集团说：**钢材这类东西，你们不许自己买了。统一由集团指定的一家单位去买。**

这就叫 **集采**（集中采购）。

被指定去统一采购的那家单位，叫 **集采执行单位**——比如"唐山冀东机电设备有限公司"（俗称机电公司），
它就是集团指定的、专门负责统一采购轴承润滑油钢材电缆这几类的单位。

## 2.2 于是就必须有一张清单

集采要落地，系统就必须能回答一个问题：

> **"我现在要买的这个东西，是不是必须走集采？"**

这张清单，就是系统里的 **《集采范围台账》**。
在菜单里的位置是「**运维中心 → 集采范围台账**」。

**整个需求，从头到尾，只围绕这一张清单。**

## 2.3 这张清单长什么样

它就是一张表格，一行是一条规矩。今天有这么几列：

| 集采类目编码 | 集采类目名称 | 集采物料编码 | 集采物料名称 | 影响范围编码 | 集采执行单位 | 创建时间 |
|---|---|---|---|---|---|---|
| 2502 | 轴承及备件 | 250201xxxx | 深沟球轴承 | BU001/BU002/... | 唐山冀东机电 | 2025-12-25 |

- **类目** = 物料的分类（"轴承及备件"、"电线电缆"）
- **物料** = 具体某个东西（"深沟球轴承 6205"）
- **影响范围** = 这条规矩管哪些板块
- **集采执行单位** = 谁去统一买

⚠️ **这张页面上没有"新增"按钮**。清单是**靠导 Excel 维护的**——
下载模板 → 填好 → 导入。这一点很重要，后面讲工作量时会用到。

# 第三章 · 这张清单今天是怎么用的（讲个故事）

**唐山冀东水泥的采购员小王，要买 200 吨螺纹钢。**

他在系统里填一张**采购计划**，选好物料"螺纹钢"，填好数量，点 **提交**。

就在点下提交的那一瞬间，系统干了一件事：

> 拿"螺纹钢"去《集采范围台账》里翻一翻——找到了吗？
> 找到了 → 在这张单子上盖一个章：**「是否集采 = 是」**
> 没找到 → 盖另一个章：**「是否集采 = 否」**

然后单子就往下走审批流程了。**故事结束。**

就这么简单。**这个章是系统自动盖的，小王自己改不了**（页面上那个选项是灰的，点不动）。

盖完这个章之后，它有两个用处：

1. **审批流程会看它**——是集采的单子，可能要多走一道审批；
2. **报表会数它**——领导要看"集采做了多少钱"，就是数这个章。

# 第四章 · 这张清单跟别的模块是什么关系 ⭐

这是你问的重点。一张图先看全貌：

```
                     ┌──────────────────────┐
   谁往清单里写 ───→ │                      │
   （人工导 Excel）  │   《集采范围台账》    │
                     │   一行 = 一条集采规矩 │
                     └───────────┬──────────┘
                                 │  提交单据的那一瞬间，去这里查一次
              ┌──────────────────┼──────────────────┐
              ▼                  ▼                  ▼
      ① 采购计划编制      ② 采购方案编制     ③ 非平台采购业务录入
      （提交时盖章）      （提交时盖章）      （提交时盖章）
              │                  │                  │
              └──────────────────┼──────────────────┘
                                 ▼
                        ④ 审批流程平台
                （拿"是否集采"当分支条件，决定审几级）
                                 │
                                 ▼
                        ⑤ 各种集采报表 / 驾驶舱
                （数有多少张单子盖了"是集采"的章）

   旁边还站着三个提供基础数据的：
   ⑥ 物料主数据（那棵类目树：金属材料 → 黑色金属 → 型材 → 螺纹钢）
   ⑦ 组织主数据（哪家公司属于哪个板块、哪个区域）
   ⑧ 云采商城（另一套系统，有一张一模一样的清单，玩法比我们先进）
```

下面一个个说。

## ① 采购计划编制 —— 消费方之一

采购员填"我要买什么"的地方。**提交时去清单里查一次，盖章。**

## ② 采购方案编制 —— 消费方之二

采购员填"打算怎么买"的地方。**提交时也去清单里查一次，盖章。**

这里还多一条规矩：如果整张单子都是集采物料、而且每一行都有对应的计划，
系统会拦住你，提示"**集采物资采购且有计划，请联系集采执行单位组织采购**"——
意思是"这活不该你干，该机电公司干"。

## ③ 非平台采购业务录入 —— 消费方之三

这个名字很怪，解释一下：

**有些采购根本没走这个平台**（金额太小、太紧急、或者在别的系统里做的）。
但集团要看全集团的采购总盘子，**这些"平台外"的业务也得补录进来**。

这个页面就是干这个的：把在外面已经做完的采购，事后录进系统。
它同样要盖"是否集采"的章。

> ⚠️ 一个细节：这三个页面盖的章，**字段名居然还不一样**——
> 前两个叫 `是否集采`，第三个内部叫另一个名字。做的时候容易漏掉第三个。

## ④ 审批流程平台 —— 章盖完之后谁在看

这套系统的审批流程**不是写在代码里的**，是在一个叫**工作流平台**的地方，
由人**画流程图**画出来的——像画流程图一样拖节点、连线、设条件。

后端要做的只有一件事：**把几个字段的值"递"给工作流平台**，
画流程图的人就能在分支条件上引用它们（"如果是否集采=是，就多走一级"）。

**今天已经在递的**："是否集采"、"标的预估金额"、"采购方式"等。
**这次要加的**："集采目录层级"、"是否强管控"。

> 💡 这就是会上产品反复念叨的那句话：
> "你把这个字段值给到流程里边，流程搭建的时候可以引用到这个字段"。
> **说白了就是：你把变量传过来，剩下的我自己画。**

## ⑤ 集采报表 / 驾驶舱 —— 最后消费这个章的人

菜单里有一大家子：集采管理业务统计报表、集采日金额统计台账、集采日计划统计台账、集采物资报表、驾驶舱……
它们都在数同一个东西：**盖了"是集采"章的单子有多少、多少钱**。

⭐ **这里藏着这次需求最大的一个"白捡的好处"，第七章会讲。**

## ⑥ 物料主数据 —— 那棵类目树

系统里所有物料都挂在一棵**四层的分类树**上：

```
金属材料              ← 第一层（一级类目）
└─ 黑色金属           ← 第二层（二级类目）   ← 台账现在只能填到这一层
   └─ 型材            ← 第三层
      ├─ 方钢         ← 第四层
      ├─ 圆钢
      └─ 螺纹钢
```

树上一共 **1445 个节点**：一级 27 个、二级 228 个、三级 624 个、四级 562 个。

⚠️ **不是每根树枝都长到第四层。** 有的到第二层就没了，有的到第三层就没了。
所以"**末级**"（最底下那一层）**每根枝都不一样**——全树一共 **1166 个末级**。

## ⑦ 组织主数据 —— 哪家公司属于哪个板块

就是 1.1 那张两层结构图的数据来源。
每家企业身上记着"我属于哪个板块（BU）"，还有一个"**我属于哪个区域**"的标签。

⚠️ **"区域"只是贴在企业身上的一个标签，不是组织树上的一层节点。**
你没办法像选公司那样"选一个区域"，只能反过来查"哪些公司贴了这个区域标签"。

## ⑧ 云采商城 —— 隔壁那套系统

金隅还有一套**云采**（网上商城，买标准品用的，像京东企业购）。
云采那边**也有一张一模一样的集采范围清单**，而且比招采这边先进：

- 它早就有"**是否强管控**"这个标签了；
- 它早就能**按强不强管控走两套不同的审批流程**了。

### 📍 想去看的话，地址在这（都是 test 环境的云采）

| 看什么 | 地址 |
|---|---|
| **《采购范围配置》**——云采版的集采范围台账，**这个最值得看** | `http://10.0.54.16:30370/productMgt/index.html#/procurementScopeConfig` |
| 《采购范围查询》——同一张表的只读版 | `http://10.0.54.16:30370/productMgt/index.html#/procurementScopeQuery` |
| 《后台类目管理》——产品会上给你看的那棵类目树 | `http://10.0.54.16:30370/productMgt/index.html#/productCategoryMgt/ProductCategoryList` |

菜单路径：**品类管理 → 采购范围配置 / 后台类目管理**。

**打开《采购范围配置》你会看到这几列**（跟招采那张几乎一样，注意第 7 列）：

> 类目编码 ｜ 类目名称 ｜ 物料编码 ｜ 物料名称 ｜ 供应商范围 ｜ 供应商名称 ｜ **是否强控** ｜ 操作人 ｜ 操作时间 ｜ 操作

页面上的按钮也一模一样：**导入 / 下载导入模板 / 导出 / 批量删除**，同样**没有"新增"按钮**。
（它页面上还多一行提示："维护到采购范围配置表里的物料编码和类目编码将作为商城采购计划的判断依据，请谨慎维护"。）

**去看的时候重点看两件事**：
1. **「是否强控」这一列长什么样**——这就是我们这次要加的「是否强管控」，直接照抄；
2. **它跟招采那张表结构上有多像**——像到可以说这次就是"把云采跑通的做法搬过来"。

⚠️ 一个实情：云采那边 **244 条数据的"是否强控"全都是"否"**，这个字段云采自己也还没真正用起来。
所以能抄的是**字段和做法**，抄不到"业务上怎么用"的经验。

**所以这次需求本质上是：把云采那边已经跑通的玩法，搬到招采这边来。**
需求文档里"（同云采）"那三个字就是这个意思。

> ⚠️ 但会上产品澄清了一句很重要的话：**参考云采只是参考"类目的层级关系"，
> "这个功能云采没有"**。所以别指望去云采整套抄，只有"强管控"这一个字段能抄。

# 第五章 · 今天这张清单有五个说不通的地方

（这五条就是这次改造的全部动机，一条对一条）

### 说不通之一：清单太粗了

台账里现在写的不是"螺纹钢"，而是"**黑色金属**"。
黑色金属底下有方钢、圆钢、扁钢、槽钢、螺纹钢、钢轨……十几种，**写一条全部一网打尽**。

可业务上未必需要这样。也许集团真正想管的只有螺纹钢，其他各家自己买就行。
**现在做不到——要么整块管，要么全不管，没有中间档。**

（实测：全公司 7343 条台账数据，**全部是"黑色金属"这种第二层的粗颗粒**，一条细的都没有。）

### 说不通之二：清单不说话是谁定的

台账里每条规矩，到底是**集团总部**定的、**冀东水泥**定的、还是**唐山区域**自己定的？
**看不出来**，所有规矩挤在一起长得一模一样。

带来的实际麻烦：领导问"集团层面集采做了多少钱？二级集团层面多少？"——**答不上来**。

### 说不通之三：清单没有"松紧"之分

有些东西是死规矩，谁也不许绕（水泥、钢材这种大宗）。
有些是软要求，特殊情况可以变通（某个小类目集采渠道正好断货）。

**现在这两者长得一模一样**——都是自动盖章、都改不了。
结果：真遇到特殊情况，采购员只能在系统外面想办法。**规矩看着很硬，实际很虚。**

### 说不通之四：删一条规矩就像它从没存在过

某个类目今年不集采了，管理员一删——**数据直接消失**。
以后没人查得到"这条规矩什么时候废的、为什么废的"。

### 说不通之五（最要命）：清单上写了"管哪些公司"，但系统看都不看

台账里有一列叫"影响范围"，写着 `BU002/BU004/BU006` 这种东西
（意思是"这条规矩管冀东水泥、冀东集团、地产集团这三家"）。

但是——**系统盖章的时候，这一列一个字都不看。**

也就是说：哪怕一条规矩写明"只管冀东水泥"，
物业集团的人来买同样的东西，照样被盖上"是集采"的章。**这一列现在纯粹是个摆设。**

# 第六章 · 所以这次要做什么

## 6.1 改完之后，小王那个故事会变成什么样

还是小王，还是 200 吨螺纹钢，还是点提交。系统这次要**连问四句话**：

### 第一句："这条规矩管不管你？"

系统看一眼台账写的影响范围，再看一眼小王是哪家公司的。

- 写"管全集团" → 管你，继续
- 写"只管冀东水泥" → 小王正好是，管你，继续
- 写"只管地产集团" → **不管你，这条规矩跳过**

**这一句是全新的，今天完全没有**（就是"说不通之五"那个摆设）。

### 第二句："这条规矩是谁定的？"

系统在单子上盖**第二个章**：「集采目录层级」，三选一——

| 层级 | 意思 |
|---|---|
| **集团集采** | 总部定的，全集团几百家都得听 |
| **二级集团集采** | 冀东水泥这一级定的，只管自己底下的企业 |
| **区域/企业集采** | 唐山区域自己定的，只管本区域那几家厂 |

**这一句也是全新的**，它是"说不通之二"的解药。

### 第三句："这条规矩硬不硬？"

台账每条规矩要标明 **强管控** 还是 **弱管控**。这个标签决定小王能不能"抗命"、以及代价：

> **今天**：章是灰的，根本改不了。规矩看着硬，实际很虚。
>
> **以后**：章能改了——小王确实可以把"是集采"改成"不是"。**但改是有代价的：**
>
> - **强管控** → 想改？行，但这张单子要**往上多爬一级审批**。
>   企业发起的，二级集团批；二级集团发起的，总部批。**改是能改，但领导会看见。**
> - **弱管控** → 想改？改就改了，走原来的流程，不惊动上面。

**这是整个需求里思路最巧的一处**：不是把门锁死，而是**给你钥匙，但用钥匙会留下记录**。

### 第四句："这条规矩还有效吗？"

以后删除一条规矩，**它不会消失**，而是变成：**状态 = 失效** + 记下**失效时间**。
失效的规矩不再参与盖章，但永远查得到。

需求里那句「**管后不管前**」就是说：规矩变了只影响**以后**的新单子，
已经在走流程的老单子不受影响、不追溯。

## 6.2 还有一件："管到末级"

台账现在卡在类目树的第二层，只能填"黑色金属"。改完之后可以一直填到最底下——**直接点名"螺纹钢"**。

配套的是一条**找规矩的顺序**（这是新需求文档里唯一保留下来的那句）：

> 先拿**物料编码**去找 → 找不到，拿它的**末级类目**去找 → 还找不到，**往上一级**再找 → 一直往上。

打个比方：查"螺纹钢"有没有被管——
先查有没有专门点名"螺纹钢"的规矩，没有就查"型材"，再没有就查"黑色金属"，再没有就查"金属材料"。
**从具体找到笼统，一层层往上问。**

## 6.3 一句话总结这次要干的活

> **把《集采范围台账》从一张"名单"，升级成一套"分级管理制度"。**

| # | 干什么 | 好比 |
|---|---|---|
| 1 | 清单能填得更细（管到末级） | 从"管所有钢材"细化到"只管螺纹钢" |
| 2 | 每条规矩标明是谁定的（三个层级） | 每份文件盖上发文单位的公章 |
| 3 | 每条规矩标明硬不硬（强/弱管控） | 硬的能破例但要惊动领导，软的自己看着办 |
| 4 | 规矩废止要留痕（失效时间 + 状态） | 文件作废归档，不是撕掉扔了 |
| 5 | 下单时真正按"影响范围"判断该不该管你 | 让那一列不再是摆设 |

# 第七章 · 一个白捡的好处（值得主动跟产品说）

还记得之前做的**集采统计报表**和**驾驶舱**吗？领导想在报表上看：

> "集团集采做了多少钱？二级集团集采多少？区域集采多少？"

**当时做不出来。** 因为系统里虽然**有**这么个字段（叫"采购业务分类"，取值正好是
集团集采 / 二级集团集采 / 区域集采 / 分散采购），
但是**没有任何地方让人填它**——17075 张采购方案里**只有 5 张有值**。

当时那期的结论原话是："**技术上没有第二条路**"，就卡死在这儿了。
现在报表那边是**硬编码兜底**的：是集采就写"集团集采"，不是就写"分散采购"——**只有两档，因为真字段没人填**。

**这次的"集采目录层级"正好把这个洞堵上。**
因为第六章第二句——系统要在每张单子上自动盖「集采目录层级」这个章，
而它的三个取值跟那个没人填的字段**几乎一模一样**。

> **也就是说：这次改完，那个报表缺的数据自动就有了，不用再单独做一期需求。**
>
> （一个提醒：只有**以后的新单子**才有值。历史那 17000 多张补不了，没有可靠依据能倒推。）

# 第八章 · 还没定的事（这才是你要去问产品的）

我把它们分成三类。**每一类的性质不一样，处理方式也不一样。**

## 第一类：产品自己在会上说"我得去确认"的（3 件）

这三件他自己都说了要去确认，**你去问等于帮他交作业，不是添麻烦**。

### ① 一张单子里，物料属于不同层级怎么办？

**问题在哪**：「是否集采」和「集采目录层级」这两个章，都是盖在**单据的表头**上的——
一张单子只有一个值。但规矩是**按每一行物料**判断的。

一张单子里，螺纹钢是集团集采、办公用品是二级集团集采——**表头这个章到底盖哪个？**

产品会上原话："假如说它多行物料均属于不同的集采目录层级，这个怎么办呢？这块是我之前没想到的……这个是我忽略了。"

**我建议的答案（把开放题变判断题）**：按**最高的**算——只要有一行是集团集采，整单按集团集采走最严的。
理由：管控口径宁严勿松，而且实现最简单。

### ② 同一个类目，集团配了一条，二级集团还能不能再配一条？

**问题在哪**：螺纹钢集团配了一条管全集团，水泥集团想再配一条只管自己——这两条能不能并存？
**这直接决定"清单允不允许重复"，以及"两条都命中时听谁的"。**

产品会上原话："假如说这个物料我选择了集团级，那么还允许二级集团再单独的配吗？……这个唯一性上是否有要求，我去确认。"

**我建议的答案**：允许并存，但匹配时按"**越具体越优先**"——
先看有没有专管我这家公司/我这个区域的，没有再看管我这个 BU 的，最后才看集团那条。

### ③ 区域到底怎么玩

需求正文里产品自己就写了"（要想一下区域怎么玩）"。会上他讲清楚了玩法：
**在企业身上贴"所属区域"标签，台账里填区域码，系统去反查哪些企业贴了这个标签。**
玩法没问题——**问题是数据（见下面第三类）。**

## 第二类：文档前后对不上、或者跟系统对不上的（3 件 + 1 件已澄清）

这几件产品**多半没意识到**，你不问他就过去了。

### ④ 老那 5 条校验规则作废之后，留下了两个洞

**先更正一件事**（我上一版写错了）：老文档第 6 条底下那五小条，在原件里是**划线删除**的，
说明产品**有意作废了旧思路**，不是漏抄。

**而且这个改动方向是对的、变简单了**：

| | 作废的老设计 | 现在的新设计 |
|---|---|---|
| 思路 | **不许你填出歧义**（导入时严格约束） | **允许重叠，提单子时按"越具体越优先"化解** |
| 业务维护者要干什么 | 想管螺纹钢，就得把型材下面方钢圆钢扁钢**全部一条条列出来** | 想管螺纹钢就只填螺纹钢 |
| 现实可行吗 | **几乎没法遵守**（现有 7343 条数据一条都不符合） | 好用 |

新设计是自洽的：二级配一条管一片、三级再配一条管更细——
查的时候先找三级那条（更具体），找到就停，不会再往上撞到二级那条。**重叠不再产生歧义。**

**但作废顺手带走了两样东西，这两样必须补：**

**🕳 洞一：判重规则没了。** 老 6.5 说的是"类目、物料、层级、影响范围四个字段全一样才算重复，且只跟生效的比"。
现在没这条了 → **完全不判重了吗？**
⚠️ 这不是理论问题：现在提单子那个功能是按"**只可能查到一条规矩**"写死的，
**查到两条会直接报错，采购计划 / 采购方案 / 非平台录入三个页面全部提交不了。**

**🕳 洞二：横向多条命中听谁的。** 新那句话解决的是**纵向**（螺纹钢找不到往上找型材）。
**横向没解决**：同一个螺纹钢，集团配了一条、水泥集团配了一条、唐山区域配了一条，**三条都命中，听谁的？**

**而这正是产品自己在会上问、说要去确认的那件事**（上面第 ② 条）。
所以这两个洞是同一件事的两面：**能不能并存（判重）、并存了听谁的（优先级）。**

### ⑤ 弱管控到底走"原流程"还是"新流程"

**两版需求文档写的都是"原流程"**，但会上录音里产品说的是"**执行新流程**"。
大概率是口误，但这决定要不要给弱管控也做一套分支。**得确认。**

### ⑥ "启用时间"到底是什么

需求正文里说"加上一个启用时间和失效时间，什么时候启用的、启用以后才生效，失效以后就不管了"
——**听起来是让你配一个生效窗口**。

但下面功能实现那段写的是"失效时间：只读，**记录删除时间**"
——**这是系统自动记的，不是你配的**。

**两种设计完全不一样。** 我先按后者（自动记删除时间）做，但要确认。

### ⑦ "集采执行单位"这一列到底管什么用

产品说这一列"控制集采执行单位在线确认计划"。
**但我把整个后端翻了一遍——这一列除了在页面上显示和导入导出，没有任何地方在读它。**

真正在判断"你是集采执行单位所以放你过"的是另一个地方（一份只配了两家单位的名单：北分、机电公司）。

**需求里说"二级集团和区域层级不用配执行单位"——如果这列本来就没被用，这条规则就没有实际约束力。**

## 第三类：数据没准备好，做出来会是空功能（3 件）

**这一类不是问"要不要做"，是问"什么时候能有数据"。**

### ⑧ 区域数据：产品说他去补，到今天一条没补

| 实测（截至 2026-09-03） | 数值 |
|---|---|
| 组织总数 | 854 |
| **"所属区域"标签是空的** | **622 家（73%）** |
| 系统里"区域级"的组织 | **0 条** |

按板块拆开看更清楚：

| 板块 | 企业数 | 有区域标签的 |
|---|---|---|
| 冀东集团 | 46 | 46（100%）|
| 冀东水泥 | 194 | 129（66%）|
| 新材产业化 | 74 | 16（22%）|
| 投资物业 | 110 | 18（16%）|
| **混凝土 / 地产 / 天津建材 / 建材研究总院** | **177** | **0（0%）** |

而且已经填的那些还有脏数据：邢台区域一会儿叫"邢台"一会儿叫"**刑**台"还有个"邢台区域**测试**"；
有一家公司编码填的是邢台、名称写的却是石家庄；还有几十家直接拿公司编码当区域码用。

**结论：区域集采现在做出来，那四个板块一家企业都命中不了。**

### ⑨ 影响范围里的编码写错了一个、漏了一个

台账 7342 行的影响范围都是同一串 `BU001/BU002/.../BU011/BU0013`。但是：

| 台账里写的 | 系统里真实的 | 后果 |
|---|---|---|
| `BU0013` | 其实是 `BU013` **冀东国贸** | **多打了个 0，永远匹配不上** |
| （压根没写 `BU012`） | `BU012` **党校** | 整个板块被漏了 |

**今天没事，因为盖章时压根不看这一列。**
一旦这次改造让影响范围真正生效，**这两个错立刻变成"某些公司买集采物资却不受管控"的线上问题。**

### ⑩ 生产环境上现在到底管着哪几类，得让产品给一份

产品会上说现在管的是：煤炭、钢材、电线电缆、轴承、办公用品、办公设备、挥发油。
但我在测试环境查到的**只有 7 个类目，而且没有钢材**（有的是润滑剂）。

**生产库按规矩我不能碰**，所以：**"上线那天历史数据怎么补"这件事，得让产品给一份生产上的实际内容。**

# 第九章 · 我的建议（一句话）

> **这一期把"台账本身"做扎实；影响范围和区域按需求把字段和逻辑都写上，但先不打开开关。**

理由很直白：

- 现在打开**影响范围**，那个 `BU0013` 的错码会让冀东国贸 5 家企业**静默脱管**；
- 现在打开**区域**，四个板块 177 家企业**一条规则都命中不了**，业务会当成 bug 报上来。

**代码先到位，数据到位了再开开关**，比"做出来发现没数据可用"强，也完全不耽误 9 月底上线。
