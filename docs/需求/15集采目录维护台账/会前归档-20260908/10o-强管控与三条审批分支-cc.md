# 一、两个"章"分别在说什么

单据表头上要盖两个章：

| 章 | 在说什么 | 谁决定 |
|---|---|---|
| **是否集采** | 这批东西**归不归**集采管 | 系统查台账自动判 |
| **是否强管控** | 归了之后，**能不能商量** | 台账那条规矩上写着 |

## 强管控 vs 弱管控，差在哪

```
强管控 = 硬规定
   你想不走集采？可以，但要多找一级领导签字

弱管控 = 软规定
   你想不走集采？改一下就行，流程照旧
```

**注意：强管控不等于"不许改"。** 它是"改可以，但代价更大"。
真正"不许改"的只有一种情况——见下面分支①。

# 二、三条分支在说什么（用一个场景走一遍）

小王要买柴机油，提交单子时系统查了台账，盖章"**是集采**"。

接下来走哪条路，看**这条规矩是谁定的 + 硬不硬**：

## 分支① 集团定的 + 强管控 → 连改都不让改

> 集团总部的硬规定，谁也别想绕。

- 「是否集采」那个框**是灰的，点不动**
- 审批路线最长：**企业 → 二级集团 → 机电公司 → 总部**

## 分支② 板块/区域定的 + 强管控 → 能改，但改了要多报一级

> 是硬规定，但毕竟不是集团定的，还有商量余地——只是得惊动上级。

- 允许把「是否集采」改成"否"
- 但一改，审批就升级：**企业/区域发起的 → 报到二级集团；二级集团发起的 → 报到总部**

## 分支③ 板块/区域定的 + 弱管控 → 能改，流程不变

> 软规定，改了就改了。

- 允许改成"否"
- 改完**走原来的流程**，跟平时买东西一样

## 一句话记住

> **谁定的规矩越高、越硬，你想绕开就越难。**

| | 谁定的 | 硬不硬 | 想绕开的代价 |
|---|---|---|---|
| ① | 集团 | 硬 | **绕不开** |
| ② | 板块/区域 | 硬 | 多审一级 |
| ③ | 板块/区域 | 软 | 没代价 |

# 三、还有一条容易漏的规矩

`01c` 6.5 第一句：

> **如果"是否集采"默认"否"则不允许修改。**

意思是：**不在集采范围里的东西，你也不能自己勾成"是集采"。**

所以这个框只能往**一个方向**改：

```
是  →  否   ✅ 可以（按上面三条分支决定代价）
否  →  是   ❌ 不行
```

道理也简单：**集采范围是台账说了算，不是采购员说了算。**

# 第二部分 · 实现起来难吗？三个雷

> 追加于 2026-09-04。上面说"活最小"是指**加变量**这件事；但这一块埋了三个雷，都不在加变量上。

## 七、🔴 雷一：那个"混采提示框"是死的，三个页面一模一样

`saveOrSubmit.vue:1592-1603`（采购计划）：

```js
await new Promise((resolve, reject) => {
  this.$confirm({
    title: `${res.data}数据是集采物料，集采和非集采不允许同时采购`,
    onOk() {},        // ← 空的，永远不 resolve
    onCancel() {}     // ← 空的，永远不 reject
  });
});
```

`await` 在等一个**永远不会完成的 Promise**。

**后果：一旦单子里既有集采物料又有非集采物料，弹框出来后点确定、点取消都没反应，提交流程永远卡在这一步，只能刷新页面重来。**

三个页面**完全一样**：

| 页面 | 位置 |
|---|---|
| 采购计划编制 | `saveOrSubmit.vue:1592` |
| 采购方案编制 | `basicInfo2.vue:4314`（`onCancel` 里那句 `this.$message` 的 `this` 还指错了对象） |
| 非平台录入 | `increasedListAdd.vue:499` |

### 为什么这次**必须**修

`01c` 6.3 说「集采目录层级**取物料明细区最小层级**」、6.4 说「**有强取强**」——

**这两句等于官方承认了"一张单子里多行物料属于不同情况"是合法的、要正常处理的。**

而现在的代码遇到这种单子**直接卡死**。不修，新规则根本跑不起来。

---

## 八、🔴 雷二：现在这个接口只给"整单一个结论"，给不出每行明细

后端那个判集采的接口，返回的是**一个字符串**：

| 返回 | 含义 |
|---|---|
| `"0"` | 一行都没命中 → 整单不是集采 |
| `"1"` | 每一行都命中 → 整单是集采 |
| 一串物料名（中文） | **部分命中** → 触发上面那个死掉的弹框 |

**它只回答"是/否/混着"，不回答"哪一行命中了哪条规矩、那条规矩是什么层级、强不强"。**

但新需求要的是：

```
每一行  → 各自命中哪条规矩 → 各自是什么层级、强不强
                    ↓
表头    → 层级取最小、强管控有强取强
```

**所以这个接口的返回结构必须改**——从"返回一个字符串"改成"返回每一行的判定结果"。

改了之后，**三个前端页面接收和处理返回值的代码都得跟着改**。

> ⚠️ 这不是"加两个变量"能解决的，是**接口签名变更**。
> 而且这三个页面里那段处理逻辑（`isChineseString(res.data)` 那一套）是复制粘贴的三份，**要改三遍**。
