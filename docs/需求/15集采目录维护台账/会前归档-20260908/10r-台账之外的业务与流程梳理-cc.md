## 1. 先看整条链（这是理解一切的地基）

**不是三个并列的入口，是一条主线加一个后门：**

```
【主线】
  ① 采购计划          ② 待采购池              ③ 采购方案
  「我要买什么」  ──►  行掉进池子，等人来挑  ──►  「打算怎么买」 ──► 招标/定标/合同
   企业采购员填                                  从池子挑行打包

【后门】
  ④ 非平台采购业务录入
  「这笔买卖压根没走平台，事后补个记录」
```

**集采管控要管的，就是这条链上的四个口子。漏一个，规矩就是废纸**——
尤其 ④，量最小（uat 只有 163 条，前两个是两万多张），**但它是唯一能绕过前面所有管控的路**。

### 集采的单子，本企业不做方案

这是最容易忽略的一环：

```
计划审批通过，每行掉进池子
        │
        ├── 不是集采 → 本企业自己做方案 → 自己招标签合同
        │
        └── 是集采   → 池子上写一笔「这活归机电公司」
                      → 机电公司以【供应商身份】登录，在自己的清单页里筛出来
                      → 由机电公司统一组织采购
```

采购方案页面上有一道拦截：**整单都是集采 + 每行都有计划 → 直接拦住**，
弹「集采物资采购且有计划，请联系集采执行单位组织采购」。

> 「集中」是集中在**机电公司**手里，不是集中在采购方案里。
> 台账上那一列「集采执行单位」的字段名带 `supplier`，就是因为机电公司在这套系统里是以供应商身份存在的。

## 2. 这四个口子今天已经有什么、这次要改什么

**今天已经有的**：四个页面提交时**都已经**会去台账查一次、都会盖一个「是否集采」的章。这部分不是新做。

**这次要改的四件事**：

| # | 改什么 | 说明 |
|---|---|---|
| 1 | **查的口径整个换了** | 今天只按「物料编码」或「二级类目」查；以后要 ①物料码→末级类目→逐级往上 ②加**影响范围**过滤（当前公司在不在管辖内）③加**状态=生效** |
| 2 | **章从 1 个变 3 个** | 今天只有「是否集采」；以后加「集采目录层级」「是否强管控」 |
| 3 | **章可以有条件地改** | 今天写死只读；以后：默认「否」不许改；默认「是」可改成「否」，强管控的改了要多审一级 |
| 4 | **三个章递给审批流** | 华姐用这三个值当分支条件 |

### ⚠️ 一个数据现状：这功能刚上线，几乎没数据

uat 实测「是否集采」的实际盖章率：

| 单据 | 总量 | 盖过章的 |
|---|---|---|
| 采购计划 | 27,151 | **130** |
| 采购方案 | 17,075 | **244** |
| 非平台录入 | 163 | **26** |

**99.5% 是空的。** 所以：① 需求里那句「管后不管前」就是冲这个来的；② **测试别指望拿历史数据验证，得自己造单子跑**。

## 4. 第二批的三个雷（都不在"加变量"上）

### 🔴 雷一：判集采那个接口只给"整单一个结论"，给不出每行明细

现在返回的是**一个字符串**：`"0"`=一行没命中 / `"1"`=全命中 / 一串中文物料名=部分命中。

**它只回答"是/否/混着"，不回答"哪一行命中了哪条规矩、那条是什么层级、强不强"。**

但 6.3「取最小层级」、6.4「有强取强」要的是**每行的判定结果**。
所以这个接口**必须改签名**——从"返回一个字符串"改成"返回每行明细"，
**三个前端页面接收返回值的那段代码（复制粘贴的三份）都要跟着改。**

> 这才是第二批真正的工作量，不是"加两个变量"。

### 🔴 雷二：混采提示框是死的，三个页面一模一样

```js
await new Promise((resolve, reject) => {
  this.$confirm({
    title: `${res.data}数据是集采物料，集采和非集采不允许同时采购`,
    onOk() {},        // ← 空的，永远不 resolve
    onCancel() {}     // ← 空的，永远不 reject
  });
});
```

`await` 在等一个**永远不会完成的 Promise**。后果：单子里既有集采又有非集采物料时，
**弹框出来点确定点取消都没反应，提交流程永远卡死，只能刷新重来。**

三处：`saveOrSubmit.vue:1592`、`basicInfo2.vue:4314`、`increasedListAdd.vue:499`。

**不修，新规则跑不起来**——因为 6.3/6.4 等于官方承认了"一张单子多行物料情况不同"是合法的。
（但"混采到底允不允许"本身还是个待定，见 **P8**。）

### 🟡 雷三：上线顺序反了会卡单

```
✅ 我的代码先发版（开始往工作流递两个新变量）→ 华姐再切流程图
❌ 华姐先切图 → 新起的单子变量是空的 → 分支判断不出来 → 卡在审批里
```

**这句话要提前跟华姐说。** 在途单据走老图，不受影响，不用特殊处理。

## 5. 台账页面还有没有没定的？——有 3 条，不在 `10q` 里

`10q` 那 8 条讲的是**录入规则**（什么能填、什么算重复）。台账**页面本身**还有三件事没定：

### ~~🟡~~ 🟢 T1 台账要不要补「新增 / 编辑」按钮？

> 【订正 2026-09-07：本条初版说「没有新增」，**说重了**。导入是纯追加，一行的 Excel 导进去就是新增；
> 改一条也只要「删那一行 + 导那一行」，不用全表重来。**理由降级为「改完有副作用」，优先级 🟡 → 🟢，不是卡点。**
> 完整说明见 `10s` §0。】

现状：这张表**只有导入和删除，没有新增、没有编辑**（`PlanProductRangeService.java` 一共 5 个方法，没有 save 没有 update）。
改一条规矩只能**先删了再导一遍**。

**我的建议**：这期**补上单条新增和编辑**。理由：加了「集采目录层级」「是否强管控」之后，
业务调整会变频繁（比如把某条从弱管控改成强管控），每次都走"删除→改 Excel→重导"太重，而且软删之后重导还要撞判重。
**成本不大（一个表单页 + 两个接口），但能省掉大量运维摩擦。**

### 🟡 T2 台账列表页要显示哪些列、默认筛什么？

新增 4 列之后列表会变宽；失效的行还留在表里。**默认显示什么、能不能按状态/层级筛？**

**我的建议**：默认只显示「状态=生效」，加「状态」和「集采目录层级」两个筛选条件，导出跟着当前筛选走。

### 🔴 T3 三级层级出来之后，台账谁来维护？

今天是总部统一维护（也只能统一维护，因为只有导入这一个口子）。
**分成三档之后，"二级集团集采"那些行，是板块自己录，还是仍然总部统一录？**

**我的建议**：**这期仍然总部统一录，不下放。**
理由：下放意味着要做数据权限（每个板块只能看到、只能改自己那些行），**那是个独立功能，不在两周排期里**。
先统一录，跑顺了下一期再下放。**但这句话要当场跟产品说明白，别让业务以为上线就能自己维护。**

## 6. 台账之外的待定清单（P1~P11，每条带我的建议）

### 🔴 P1 采购方案那道拦截，在新的三级层级下还成立吗？（最容易被漏、后果最严重）

**问题**：今天的规则是「整单都是集采 + 每行都有计划 → 拦住，让你去找集采执行单位」。
但需求 §5 明说：**「集采目录层级为二级集团、区域/企业的，无需配置集采执行单位」**。

**那二级集团层级的集采单子，本企业到底能不能自己做方案？**
如果照旧拦住——**没有执行单位可交，池子上那个"归谁"的字段是空的，机电公司的清单页也筛不到它，这张单子就没人接了。**

**我的建议**：**拦截只对「集团集采」层级生效。** 二级集团 / 区域层级的，本企业自己做方案。
**理由**：执行单位这一栏本来就是给集团集采用的；不填执行单位又拦住，业务上是个死局。

**不定的代价**：🔴 **上线后二级集团层级的单子会卡死在"提交不了方案、也没人来接"**，而且这种问题上线当天不一定暴露（要等业务真的配了二级集团的规矩才会撞上）。

---

### 🔴 P2 混采到底允不允许？（决定那个死锁弹框是删还是改）

**问题**：现在代码是「一张单子里既有集采又有非集采 → 弹框拦住」（而且弹框是死的）。
但 6.3「取最小层级」、6.4「有强取强」这两句，读起来像是**承认一张单子里可以有多种情况**。

**到底是**：
- (a) 仍然禁止混采，6.3/6.4 只用来处理"多行**都是集采**但层级/强弱不同"的情况？还是
- (b) 允许混采，弹框改成提示或者干脆去掉？

**我的建议**：**(a) 保持禁止混采**，只把死锁修好（弹框改成明确拦截、可关闭）。
**理由**：整单只有一个「是否集采」的章，混采的话这个章说不清楚；而且这是现有行为，不改动静最小。

**不定的代价**：那个弹框是删是改定不了，前端三个页面的改法定不了。

---

### 🔴 P3 弱管控改成「否」，走原流程还是新流程？（文档和会上说的对不上）

**问题**：`01c` 6.5 和 ③ 分支写的都是「弱管控的，是否集采改成否，**按原流程**执行」；
但 9/3 会上产品说的是「**执行新的审批流程（向上一级审批）**」。**两版文档都写"原"，口头说"新"。**

**我的建议**：**以文档为准，走原流程。**
**理由**：弱管控的定义就是「软规定，改了没代价」。如果改了也要多审一级，**弱管控和强管控就没区别了**，三条分支塌成两条。

**不定的代价**：分支③画错，华姐要返工重画。

---

### 🟡 P4 弱管控，和"根本不放进台账"有什么区别？

**问题**：既然弱管控改成否就没代价，那把一条规矩标成弱管控，跟压根不录进台账，业务上差在哪？

**我的理解（要产品确认）**：**有区别，区别在默认值和报表口径**——

| | 系统默认盖什么章 | 采购员要动手吗 | 报表能不能统计到 |
|---|---|---|---|
| 在台账、弱管控 | **是集采** | 要主动改成否 | ✅ 算在这一层的集采盘子里 |
| 不在台账 | **不是集采**，而且**不许改成是** | 不用动 | ❌ 压根没这回事 |

所以弱管控 = **「默认按集采走，但你可以自己退出，不用请示」**。

**不定的代价**：小。但这个理解不确认，业务会问"那我标弱管控图什么"，答不上来。

---

### 🟡 P5 改成「否」的时候，要不要填理由？

**问题**：现在页面上没有这个框。强管控改成否是要**多找一级领导签字**的——
那位领导打开单子只看到一个「是否集采 = 否」，**不知道为什么改，这级审批就是走过场。**

**我的建议**：**要，而且设成必填。** 成本很小（一个文本框 + 一列），
但它是分支②那一级审批**唯一的判断依据**。不加的话，那级审批等于白设。

---

### 🟡 P6 改成「否」之后，「集采目录层级」这个章还留着吗？

**问题**：这直接决定报表口径——他改成非集采了，**这单还算在"集团集采"的盘子里吗？**

**我的建议**：**留着。**
**理由**：层级说的是"这东西归哪一级管"，是台账定的客观事实；"是否集采"说的是"这单最后走没走集采"，是这张单子的结果。**两个是不同的问题。**
留着，报表才能统计出「集团集采范围内，有多少单被改成了非集采」——**这恰恰是做管控最想看的那个数**。

### 🟡 P7 采购计划页面，到底加不加那两个字段？（文档自己写岔了）

**问题**：6.1 说「采购方案、**采购计划**、非平台录入」三个都自动回写三个字段；
但 6.3 / 6.4 只说「**采购方案编制 / 非平台录入**界面增加字段」——**采购计划被漏掉了**。
2.4 状态那条也一样，只提「采购方案提交或非平台录入提交」，又漏了采购计划。

**我的建议**：**三个页面都加、三个入口都判状态。**
**理由**：采购计划是**第一道关**，章就是在计划提交那一刻盖的；而且方案是从池子挑行组的，
计划这里不算值，后面全是空的。**6.3/6.4 漏写采购计划应该是笔误，不是有意的。**

---

### 🟡 P8 待采购池那张表，要不要也带这两个字段？

**问题**：`sc_scheme_to_purchase` 是计划和方案之间的中转站，机电公司的清单页就是从它取数的。

**我的建议**：**要带。**
**理由**：① 机电公司在自己的清单页上要能看出"这条是哪一级定的、强不强"，否则没法排优先级；
② 采购方案是从池子挑行打包的，**值从池子直接带过来，比在方案里重新算一遍可靠**（台账可能中途被改了）。

### 🟡 P9 页面上新加的那两个字段，是只读还是可以改？

**问题**：需求只说「界面增加字段」，**没说能不能改**。

**我的建议**：**只读。** 它们是系统按台账算出来的事实。
采购员能改的只有「是否集采」那一个框（而且只能是→否）。

### 🟡 P10 一张单子多行、层级不一样，"取最小层级"是哪个方向？

**问题**：6.3 那句「取物料明细区**最小层级**属性」，"最小"有两个读法，**做出来完全相反**：
- 按 §2 的编号算：一级=集团集采、二级=二级集团、三级=区域企业 → **最小 = 集团集采**（走最严的流程）
- 按"管辖范围"算：范围最小 = 区域集采 → **方向正好反过来**

**我的建议**：**按编号最小 = 集团集采，宁严勿松。**
**理由**：一张单子里只要有一行是集团管的，整单就按集团那套走，符合管控的初衷。

### 🟢 P11 规矩失效时，单子正在审批中，还按原流程走完吗？
