# 一、先看清「给工作流参数」到底是多小的一件事

起流程的时候，往一个变量清单里塞几个键值对：

```
是否集采      = 是
集采目录层级  = 集团集采
是否强管控    = 是
```

**代码量就是几行**（`10c` §3.3 查过，现成机制，往 `metasList` 里 add 就行）。

**这就是你和华姐的交接面——一条线，线右边是她的，线左边全是你的。**

而线左边那个「= 是」「= 集团集采」的值，**得先有人算出来、存下来**。

# 二、你在这三个单据上，实际要做四层活

## 层 1 · 建表：现在**根本没有地方存**这两个新值

uat 实测，五张相关的表**全都只有"是否集采"一个字段**：

| 表 | 是否集采 | 集采目录层级 | 是否强管控 |
|---|---|---|---|
| `sc_plan` 采购计划头 | ✅ `is_collection` | ❌ **没有** | ❌ **没有** |
| `sc_plan_product` 计划行 | ✅ `is_collection` | ❌ **没有** | ❌ **没有** |
| `sc_scheme` 采购方案 | ✅ `is_collection` | ❌ **没有** | ❌ **没有** |
| `sc_scheme_to_purchase` 待采购池 | ✅ `is_collection` | ❌ **没有** | ❌ **没有** |
| `sc_supplier_green_channel` 非平台录入 | ✅ `is_jc` | ❌ **没有** | ❌ **没有** |

**至少 4 张表要各加 2 列**（池子那张要不要带过去，得看机电公司的清单页要不要显示，待定）。

**加列 = 写 DDL + 改实体类 + 改 DTO + 改 Mapper**。这是纯代码活，跟工作流一点关系没有。

## 层 2 · 后端：三个值都得算出来

| 要算什么 | 依据 | 难在哪 |
|---|---|---|
| **是否集采** | `01c` 6.2 | 判断口径整个换了：先按物料编码 → 找不到取末级类目 → 再往上一级；还要加**影响范围过滤**和**状态=生效** |
| **集采目录层级** | `01c` 6.3 | 一张单子多行物料时"取最小层级"——要把每行各自命中的层级收集起来再挑一个 |
| **是否强管控** | `01c` 6.4 | "有强取强"——任一行是强管控，整单就算强管控 |

**这是这次最核心的代码工作量**，`10e` §十六 列的那 5 处改造全在这一层。

## 层 3 · 前端：三个页面都要改

**① 新增两个字段的显示**（表头上多两个框：集采目录层级、是否强管控）。

**② "是否集采"从锁死改成有条件可编辑**——`01c` 6.5：

> 如果"是否集采"默认"否"则**不允许**修改；默认"是"则**允许**修改；
> 集团集采 + 强管控 → **不允许**修改。

实测三个页面现在**全部写死是只读的**：

| 页面 | 位置 |
|---|---|
| 采购计划编制 | `saveOrSubmit.vue:264` `<a-radio-group v-model="formState.isCollection" disabled>` |
| 采购方案编制 | `basicInfo2.vue:450` 同款 |
| 非平台录入 | `increasedListAdd.vue:62` 同款（注意字段名是 `isJc`） |

**三处都要把 `disabled` 拆掉，换成按上面那套规则动态判断。**

## 层 4 · 递给工作流（这才是给华姐的那一步）

| 入口 | 现状 | 要做的 |
|---|---|---|
| 采购计划 | 已经在往工作流递一批变量 | **加 3 个** |
| 采购方案 | 同上 | **加 3 个** |
| **非平台录入** | ⚠️ 走独立的"绿色通道"流程，**现在只递了 2 个变量，一个集采相关的都没有** | **新加一整组**，不是加 3 个那么简单 |

# 四、为什么容易误判成"只给参数"

因为 `01c` §6 那一整段**读起来像在讲审批流**——尤其 6.5 底下那三条箭头图很扎眼。

但把 §6 逐条拆开看，**只有最后那部分是华姐的**：

| 需求条 | 实际在讲什么 | 谁做 |
|---|---|---|
| 6.1 三个字段自动回写 | **算值 + 存值** | **你** |
| 6.2 是否集采判断逻辑 | **算值** | **你** |
| 6.3 层级取最小层级 | **算值** | **你** |
| 6.4 强管控有强取强 | **算值** | **你** |
| 6.5 前半句（能不能改） | **前端交互** | **你** |
| 6.5 的 ①②③ 箭头图 | 审批分支怎么走 | **华姐** |
| 7 强管控必须类目标准化 | 业务侧要做的事 | 不是开发 |

**7 条里 5 条是你的，1 条是华姐的，1 条不是开发。**

# 六、一句话总结

> **"提供字段"不是"只提供字段"。**
> 字段要先被算出来（后端）、存下来（建表）、显示出来并让人能改（前端），
> 最后才谈得上"提供"给工作流。
>
> **华姐拿到的是终点，你负责的是从起点到终点的全程。**
