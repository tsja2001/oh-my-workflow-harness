# 三、🔴 影响范围那个串，是 **7342 行全中**的错

台账里 7342 行的「影响范围编码」写的是同一个串：

```
BU001/BU002/BU003/BU004/BU005/BU006/BU007/BU008/BU009/BU010/BU011/BU0013
```

三处错：

1. **`BU0013` 这个编码根本不存在**——真实的是 `BU013`（冀东国贸，6 家企业）
2. **漏了 `BU012`**（建材集团党校，2 家企业）
3. 用 `like` 匹配的话，`%BU001%` 会**误命中** `BU0013`

**今天没出事，纯粹因为没有任何判断代码读这一列**（`10g` §五讲过）。

**但这次改造的核心就是让影响范围第一次生效**——一生效，**这 8 家企业立刻脱管**。

> ⚠️ **期初初始化必须把这个串一并修对**，否则功能上线当天就有数据错。

# 五、初始化脚本长什么样（让你心里有数）

技术上就是几条 UPDATE：

```
① 所有行的「状态」= 生效
② 所有行的「集采目录层级」= 产品给的值
③ 所有行的「是否强管控」= 产品给的值
④ 把影响范围那个串修对（BU0013 → BU013，补上 BU012）
⑤ （可选）把那约 600 行失效物料标成"失效"或直接清掉
```

**难的从来不是写这几条 SQL，是第 ②③⑤ 条填什么。**

## 三个必须注意的操作要求

| # | 要求 | 为什么 |
|---|---|---|
| 1 | **脚本必须能重跑**（跑两遍结果一样） | 上线当晚出岔子要能重来 |
| 2 | **跑之前先备份整表** | 公司这套 MySQL 是 PXC 严格模式，**不支持 `CREATE TABLE ... AS SELECT`**，必须写成 `CREATE TABLE 新表 LIKE 原表;` + `INSERT INTO 新表 SELECT ...;` 两句（`ai-docs/经验教训.md` 记过） |
| 3 | **顺序不能反**：先加列 → 再跑初始化 → 最后才开新逻辑 | 反了就是"新逻辑读到空值"，单子卡审批 |

# 七、你只要记住这五句

1. **"新业务自动取值"不用你管**（字段设成必填就自动成立）；**要干的活只有"初始化历史 7343 行"**。
2. **必填字段留空 = 审批分支判不出来 = 单子卡住**，所以上线那一刻必须已经有值。
3. **这 7343 行有 8% 是坏的**（207 行查无此物料、389 行已停用），初始化时值得一并清。
4. **影响范围那个串 7342 行全是错的**（`BU0013` 不存在、漏 `BU012`）——今天没事是因为没人读，**一生效就有 8 家企业脱管，必须一起修**。
5. **uat 的数据不能代表生产**（产品说管钢材，uat 里一条都没有）——**口径必须找产品要**。
