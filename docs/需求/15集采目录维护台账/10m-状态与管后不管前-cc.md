# 零、这一整块，其实只有一个改动

> **今天台账上的"删除"是真删——删了就没了。**
> **这次要改成"作废"——那行还留着，只是被标成"失效"。**

围绕这一个改动，衍生出三样东西：一个**状态**、一个**失效时间**，和一句**"管后不管前"**。

看懂这句，剩下的都是推论。

# 一、今天什么样

台账那张表**总共只有 13 列**，里面**没有任何**表示"状态"或"删没删"的字段。

删除按钮点下去，后端直接执行的就是"**把这几行从表里删掉**"。

## 带来三个麻烦

**麻烦一：查不到是谁取消的。**
半年后有人问"柴机油以前不是集采吗，怎么现在不是了？"——**没有任何记录**。
谁删的、什么时候删的、为什么删，一片空白。

**麻烦二：老单子的依据没了。**
去年 3 月小王那张单子盖了"是集采"的章。今天回头对账，想看看当时是根据哪条规矩盖的——
**那条规矩已经被删掉了，查无此物。**

**麻烦三：删错了没得后悔。**
运维手一抖删了 600 行，只能从备份捞。

# 二、改成什么样

## 2.1 加两个字段

| 字段 | 记什么 | 谁来填 |
|---|---|---|
| **状态** | 生效 / 失效 | 系统自动：新增时默认"生效"，删除时改成"失效" |
| **失效时间** | 这条规矩是什么时候被取消的 | 系统自动：删除那一刻的时间 |

（"创建时间"这一列本来就有，记的是"什么时候开始管的"。）

## 2.2 删除按钮的行为变了

```
今天：  把这几行从表里删掉        → 行没了
以后：  把这几行标成"失效"，       → 行还在，只是灰了
        并记下失效时间
```

页面上默认只看"生效"的，想看历史就切到"全部"。

# 三、「管后不管前」到底是什么意思

**一句话：这条规矩录进台账**之前**已经提交的单子，不追溯。**

## 3.1 用时间线看最清楚

```
9/01   小王提交一张买柴机油的采购计划
       → 这时台账里还没有"柴机油要集采"这条规矩
       → 系统查了一下：没有 → 盖章「不是集采」→ 走普通流程

9/11   运维把「柴机油归集团集采」录进台账

9/12   小李提交一张买柴机油的采购计划
       → 系统查了一下：有！→ 盖章「是集采」→ 走集采流程
```

**小王那张单子不会被回头改成"是集采"。** 这就是"管后不管前"。

## 3.2 为什么这条几乎不用写代码

因为盖章是**提交那一瞬间去查一次、查完就把结果存进单子里**，之后它就是个死值，不会再变。

规矩录进去之前，查也查不到 → 自然就是"不管前"。**这条是白送的。**

# 四、⚠️ 真正要写代码的，是"**失效之后**"

这才是这块的核心工作量。

## 4.1 今天为什么不用管

今天是真删 → 行没了 → 下次查自然查不到 → **自动就不管了**。

## 4.2 改成"作废"之后，问题就来了

**行还在表里。** 如果查台账的代码不管状态，那么：

> **你以为已经取消的规矩，还在管着人。**

运维在页面上明明把柴机油那条标成"失效"了，结果小李提交单子照样被盖"是集采"的章——
**这是最典型的"改了软删除但忘了加过滤"的事故。**

## 4.3 所以每一个读台账的地方，都要加一句"只要生效的"

需求 §2.4 那句话说的就是这件事：

> "对后续影响：采购方案提交或者非平台录入提交时，物料编码属于集采台账 **& 状态属于'生效'**"

⚠️ **但需求只点了那两处，实际有 6 处在读这张表**：

| # | 在干什么 | 备注 |
|---|---|---|
| 1 | 判断"这行物料是不是集采"（三个单据页都调它） | 需求点到了 |
| 2 | 计划转采购时取集采执行单位 | 需求没点 |
| 3 | 同上（审批通过那条分支） | 需求没点 |
| 4 | 导入时查这条规矩存不存在 | 需求没点 |
| 5 | **云采采集链路，空条件全表扫** | 需求没点，**最容易漏** |
| 6 | 同上，另一处 | 同上 |

**第 5、6 处尤其危险**：它把整张表拉回来塞进一个 map，然后拿这个 map 判断集采。
不加过滤，**失效的规矩会继续在这条链路上生效**。

# 五、⚠️ 需求里一个没说清的地方：「启用时间」

需求开头写着：

> "是否强管控、按照bu、进行管控、**启用时间**、失效时间；（根据启用时间，管后不管前）"

但是——

- **§2 正文里只加了"失效时间"和"状态"，压根没有"启用时间"这个字段**；
- 前端那 15 列里也只有「创建时间」「失效时间」「状态」，**没有「启用时间」**。

所以有两种可能：

| | 含义 | 要多做什么 |
|---|---|---|
| **(a) 启用时间 = 创建时间** | 录进去那一刻就开始管 | **什么都不用多做** |
| **(b) 启用时间是独立字段** | 可以填未来日期："今天录，10 月 1 号才开始管"（预约生效） | 多一个字段 + 匹配时多一个时间条件 + 页面上多一个日期选择 |

**我判断大概率是 (a)**——因为正文和前端表格都没给它留位置。

但差别不小，**建议问一句**（这就是 `11b` A5 一直没答的那条）。

# 六、做的时候会撞上的几个边界情况

## 6.1 单子提交了、还在审批中，这时规矩失效了，怎么办？

**按"提交时定章"的口径：照旧走。** 章已经盖在单子上了，不回头改。
——这其实是"管后不管前"的另一面，逻辑自洽。

但**需求没明写**，做之前最好口头确认一句。

## 6.2 失效了的规矩，能不能恢复？

需求只说了"删除 → 变失效"，**没说能不能反过来**。

行既然还在，技术上加个"恢复"按钮很容易。但要不要给，是产品的决定。

## 6.3 判重要不要只跟"生效"的比？

老需求 §6.5 原本写着"**只对状态=有效的数据进行判重处理**"，但那条**被划掉作废了**。

现在的问题变成：一条规矩失效了，能不能再录一条一模一样的？
——**这正是待确认问题③（判重规则）**，不定清楚导入就会出问题。

# 八、你只要记住这五句

1. **这块的全部内容就是：删除从"真删"改成"标记失效"。**
2. **"管后不管前" = 规矩录进去之前提交的单子，不追溯。这条几乎不用写代码，因为章是提交那一刻盖死的。**
