## 0. 先说清两个最容易迷的地方

### 0.1 「表头」是什么

下文到处在说"表头盖章"，指的是这个：

```
┌─ 基本信息 ─────────────────────────────┐
│  计划单号：PLAN20260908001               │   ← 这一整块叫【表头】
│  申请单位：唐山某水泥厂                   │      一张单只有一份
│  申请人  ：小王    日期：2026-09-08       │
│  是否集采：●是 ○否                       │   ← 章盖在这儿
└────────────────────────────────────────┘

┌─ 需求物料 ─────────────────────────────┐
│  1  螺纹钢   2  柴机油   3  轴承  …      │   ← 这些叫【明细行】
└────────────────────────────────────────┘   有几个物料就有几行
```

| | 页面上 | 数据库 | 一张单有几条 |
|---|---|---|---|
| **表头** | 上半部分「基本信息」卡片 | `sc_plan` / `sc_scheme` | **1 条** |
| **明细行** | 下半部分「需求物料」表格 | `sc_plan_product` | 10 行物料就 **10 条** |

**为什么非要区分**：**审批流只看表头**。一张单起一个流程，只能递一组变量过去，
没法跟流程说"我第 2 行是集团集采、第 7 行是区域集采，你看着办"。

```
明细行：每行各自去台账查，各自命中一条规矩，各自有层级和强弱
                    ↓  ⚠️ 表头只能填一个
      6.3「取最小」和 6.4「有强取强」就是干这个用的 —— 汇总规则
                    ↓
表头：三个值各一个 → 递给审批流 → 决定这张单走哪条链
```

> **6.3 和 6.4 存在的唯一原因，就是"明细行有很多份、表头只能有一份"。**
> 如果一张单只准放一个物料，这两条规则压根不用写。

⚠️ **这三个值明细行上也各存一份**（`sc_plan_product` 现在就有 `is_collection`，第二周还要给它加另外两列）。
两边存的东西不一样：

- **明细行存**：这一行物料**自己**命中的规矩是什么 —— 排查问题时看它
- **表头存**：汇总之后的**结论** —— 审批流看它

### 0.2 6.3 的"最小层级"，不是你以为的那个

你在 `12c` 里对 6.3 的理解是：

> "170101010138 是集采，规则里 1701、170101、17010101 都有集采规则，那就按照 17010101 是最小层级"

**这个理解是错的**，而且错得很典型——你把**两个不同的"层级"搞混了**：

```
类目层级      1701 → 170101 → 17010101 → 170101010138     ← 物料分类的粗细
集采目录层级  集团集采 / 二级集团集采 / 区域·企业集采        ← 这条规矩由谁管
```

**6.3 说的"最小层级"，指的是第二个**（谁管），**跟类目粗细一点关系都没有**。

- 你说的"按 17010101 走"——**这句本身是对的**，但那是 **6.2** 的事（哪条规矩管这一行物料）。
- **6.3 是另一件事**：一张单子上有 10 行物料，每行各自命中了一条规矩、各自有一个"谁管"，
  **表头只能盖一个章**，那盖哪个？→ **盖最严的那个 = 集团集采**。

> 📌 **背下来这两句就不会再混**：
> ```
> 一行物料命中两条规矩，听谁的？  → 范围越窄越优先（区域赢）   ← 6.2，纵向/横向匹配
> 一张单子多行物料，表头记哪级？  → 层级越高越优先（集团赢）   ← 6.3，跨行汇总
> ```
> 两句话方向是**反的**。前者问"这条物料归谁管"，后者问"这张单按谁的规矩走审批"。

## 5. 需求 §6 那几句话到底什么意思

### 5.1 「6.1 物料明细行中的类目只要属于集采范围台账，自动回写三个值」

**大白话**：你点【提交】的那一秒，系统自己拿着单子上每一行的物料编码/类目编码，
跑去集采台账里查一遍，查到了就**自己**把三个值填到单子上。

**"自动回写" = 采购员一个字都不用填，也看不到填的过程。**

```
采购员：选物料、填数量、点提交
              ↓
系统：拿 10 行物料去台账查 →  是否集采 = 是
                            集采目录层级 = 集团集采
                            是否强管控 = 是
              ↓
这三个值存进单据表，显示在页面上（只读），并递给审批流
```

> 现在系统只回写**一个**值（是否集采），第二周变成回写**三个**。

### 5.2 「6.3 取物料明细区最小层级属性」

见 §0。补一张表，把"最小"到底怎么比说死：

| 层级 | 数字 | 谁更"小" |
|---|:--:|---|
| 集团集采 | 1 | ← **最小，赢** |
| 二级集团集采 | 2 | |
| 区域·企业集采 | 3 | |

**取数字最小的 = 层级最高的 = 管得最严的那一档。**

**为什么敢这么定**：系统里**已经有先例**——`OrganizationLevelEnum` 就是 `JT(集团)=1, GS=2, BS=3`，
数字越小层级越高。跟着现有约定走，不用问产品（`13` D3）。

### 5.3 「6.4 有强取强」——你说被说蒙了，其实一句话

**一张单子上，只要有任何一行物料是强管控的，整张单就算强管控。**

举个例子，一张方案 3 行：

| 行 | 物料 | 命中的规矩是强管控吗 |
|---|---|---|
| 1 | 螺纹钢 | 否 |
| 2 | 柴机油 | **是** |
| 3 | 轴承 | 否 |

→ **表头「是否强管控」= 是**。

**为什么这么定**：强管控的意思是"这东西必须走集采，想改成不集采得多一级领导批"。
只要单子里有一样东西是强管控的，就不能因为另外两样是弱的就放松——**从严**。

**和 6.3 是同一个思路**：表头只能盖一个章，两条规则都选"最严的那个"。

### 5.4 🔴 「6.5 三条分支」——你的理解基本对，但有一个格子需求没写

**你的理解**：
> 如果不是集采，肯定不能改成集采 ✅ **对**
> 如果是集采 && 强管控，需要审批 ⚠️ **不够准，强管控分两种**
> 如果是集采 && 弱管控，可以直接改成非集采 ✅ **对**

**准确版本（把四种情况摊开）**：

| 是否集采 | 强管控 | 层级 | 那个框能改吗 | 改成"否"之后走什么流程 |
|:--:|:--:|---|---|---|
| **否** | — | — | ❌ **灰的，改不了**（不能把非集采改成集采） | — |
| **是** | 强 | **集团集采** | ❌ **灰的，改不了** | 走分支①：企业→二级集团→集采执行单位→总部 |
| **是** | 强 | 二级集团/区域 | ✅ 能改 | 走分支②：**向上一级审批**（企业/区域发起→二级集团；二级集团发起→总部）<br>＋ **必须填改成否的理由** |
| **是** | 弱 | 二级集团/区域 | ✅ 能改 | 走分支③：**原流程**，不加审批 |
| **是** | **弱** | **集团集采** | 🔴 **需求里没写这一格** | 🔴 **没写** |

> 🔴 **最后一行是我今天新发现的漏洞，而且它不是理论问题——上线第一天全部数据都落在这一格。**
>

> **我的默认**：按弱管控的定义办——**框能改，改成否走原流程**（等同分支③）。
> 理由：弱管控的定义就是"改了没代价"，跟层级无关。而且这样最保守，跟今天的行为一致。
>
> **必须做的事**：跟产品确认这一格，**并且告诉华姐她的分支图要画第四种情况**，
> 否则上线当天七千多条规矩对应的单子会掉进一个流程图上不存在的格子里。

### 5.5 「7、强管控的必须进行物料类目标准化！！！！！」

**这句不是开发的活，是给业务提的要求**（`10k`:131、`10-业务讲解`:137 都已判定过）。
