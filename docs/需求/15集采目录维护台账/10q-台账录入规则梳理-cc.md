## 1. 先说清楚：台账里「一行」是什么

一行 = **一条集采规矩**，意思是「谁买什么，要走集采」。

| 这一格 | 填什么 | 回答的问题 |
|---|---|---|
| 类目编码 / 名称 | 如 `1701 润滑剂` | **管什么**（管一整片） |
| 物料编码 / 名称 | 如 `170101010186 柴机油^18L/桶` | **管什么**（精确到一个货，可留空） |
| 影响范围编码 / 名称 | 板块 BU 码，多个用 `/` 连 | **管谁**（哪些企业受这条规矩约束） |
| 集采执行单位编码 / 名称 | 如 `唐山冀东机电设备有限公司` | **归谁买** |
| 🆕 集采目录层级 | 集团集采 / 二级集团集采 / 区域·企业集采 | **这条规矩是哪一级定的** |
| 🆕 是否强管控 | 是 / 否 | **能不能不遵守** |
| 🆕 状态 | 生效 / 失效（只读） | **这条还算不算数** |
| 🆕 失效时间 | 只读，记删除时间 | **什么时候不算数的** |

表：`sc_plan_product_range`，目前 **7343 行**。

## 2. 现在系统是怎么录的（实测，不是文档）

### 2.1 只有「导入」和「删除」，没有新增/编辑

`PlanProductRangeService.java:10-25` 一共 5 个方法：分页查、导入、删除、单条匹配、批量判集采。
**没有 save，也没有 update。** 也就是说：

- 想加一条 → 只能下模板、填 Excel、导入；
- 想改一条 → 只能**先删了再导一遍**；
- 删除是**物理删**（`deleteBatchIds`），删了就没了。

### 2.2 导入时现在拦这 6 件事

出处：`ProductRangeImportServiceImpl.java` 的 `check()` 方法。

| # | 拦什么 | 行号 |
|---|---|---|
| 1 | 物料编码和类目编码**不能同时为空** | :72 |
| 2 | **影响范围编码不能为空** | :77 |
| 3 | 填了物料编码 → 必须在主数据里**存在**，且**状态可用**（`state=1`） | :82-93 |
| 4 | 没填物料、填了类目 → 类目必须存在，**且必须能取到它的二级祖先** | :94-109 |
| 5 | **跟库里比**：这条已经有了就报「数据已存在」 | :112-119 |
| 6 | **跟本次导入文件内部比**：`类目编码+物料编码` 拼串重复就报「导入数据重复」 | :120-125 |
| 7 | 集采执行单位（供应商编码）**不能为空**，多个用 `/` 分隔，每个都要能查到公司 | :127-142 |

### 2.3 ⚠️ 现在的判重口径（这是最要紧的一条）

第 5 条那个「数据已存在」，走的是 `getPlanProductRange()`（`PlanProductRangeServiceImpl.java:103-117`），逻辑是：

- **填了物料编码** → 只按物料编码去全表查，**类目编码根本不看**；
- **没填物料编码** → 按类目编码查，且要求物料编码为空。

**结论：同一个物料编码，全表只允许存在一行。同一个类目（物料留空），全表也只允许一行。**
**跟影响范围无关，跟层级无关，跟状态无关（现在也没有状态）。**

> 这就是为什么需求 3.3「同一物料可以属于不同的二级集团或区域」现在做不出来——
> 第二条会被这个校验直接顶回去。

### 2.4 ⚠️ 两个现在就在发生的「静默改数据」

**① 你填的类目编码会被改写成二级类目。**
`finish()` :191-192 和 :201-203——不管你填的是三级还是四级，入库前一律换成它的**二级祖先**。
所以现在台账里**只可能有二级类目**，不是因为业务只想管二级，是**代码改的**。
配合 2.2 第 4 条（一级类目取不到二级祖先 → 报错），实际效果是：
**一级填不进去、三四级填进去会被降成二级、只有二级是原样存的。**
【推断】三四级能通过校验（无法直接证实的原因：没跑过 `getClassLine` 拿三四级编码的返回，是从 `midClassDto` 的取值方式推的）

**② 填了物料编码时，你填的类目编码整格作废。**
:190 直接用主数据返回的物料信息覆盖 DTO，类目取主数据里那个物料的二级类目。

> 这两条**本次都要去掉**——新需求要「支持选择到末级」，改写就是跟需求对着干。

### 2.5 ⚠️ 「影响范围」这一列现在是摆设

`bu_code varchar(256)`，多个用 `/` 连（最多约 28 个 8 位编码）。
实测 7343 行里 **7342 行填的是同一个串**（13 个 BU 全列）。

**判「是不是集采」的三处代码，没有一处带 BU 条件**
（`PlanProductRangeServiceImpl:135`、`PlanServiceImpl:2031`、`PlanTaskServiceImpl:684`）。
`bu_code` 全仓库唯一被读的地方是**台账列表页那个搜索框**（`PlanProductRangeServiceImpl:65`）。

> 换句话说：**这一列今天填什么，系统行为都一样。**
> 这次分三级层级之后，它才第一次真正参与判断——**所以口径必须一次定对，这是新逻辑的地基。**

## 3. 新版要变成什么（需求文档已经写死的部分）

来自 `01c今天最终定版需求文档.md`：

1. **加 4 个字段**：集采目录层级（必填）、是否强管控（必填）、失效时间（只读）、状态（只读）。
2. **类目支持选到末级**（3.1）。→ 2.4 那两个改写要去掉。
3. **删除改成标记失效**（2.3 / 2.4）。→ 物理删改逻辑删，所有读这张表的地方都要加「只读生效」。
4. **物料编码可留空、也可填**（3 段整体）：留空 = 管这个类目下所有物料；填了 = 只管这一个。
5. **影响范围按层级填不同东西**（§4）：
   - 集团集采 → 录**所有**二级集团 BU 编码；
   - 二级集团集采 → 录**指定的** BU 编码；
   - 区域/企业集采 → 录**指定区域**的组织编码。
6. **集采执行单位**：层级是「二级集团 / 区域·企业」的**不用填**（§5）。→ 2.2 第 7 条那个必填校验要改成按层级判断。
7. **纵向重叠是允许的**（这条容易看漏）：老 6.1~6.4「三级维护了就得按三级列」那套**已被产品划掉作废**，
   换成 6.2 一句「先按物料编码校验，物料编码不存在取末级类目，末级类目没有取上级」。
   **意思是：允许二级配一条、三级再配一条，提单子时越具体越优先、找到就停。**
   **所以纵向永远不会有「听谁的」的歧义**——这跟 3.2 不冲突，3.2 管的是「集团配过的地方别人别插手」。
8. **§7「强管控的必须进行物料类目标准化」**：这是**对业务的要求，不是开发的活**（`10k`:131 已判定）。

## 4. 我理解的完整录入规则（拿这个去跟产品对）

> 下面 ✅ 是有依据的，❓ 是要产品点头的（详见第 5 节）。

**一条台账数据要通过这些关口：**

| 关口 | 规则 | 状态 |
|---|---|---|
| A 必填 | 类目编码、影响范围编码、集采目录层级、是否强管控 必填 | ✅ |
| B 物料编码 | 可空。填了就必须在主数据存在且可用 | ✅ |
| C 类目编码 | 可选到任意层级（含末级），**不再降级改写** | ✅ |
| D 集采执行单位 | 层级=集团集采 → 必填；二级集团/区域 → 可空 | ✅ |
| E 影响范围 | 层级=集团集采 → 全部 13 个 BU；二级集团 → 指定 BU；区域 → 区域编码 | ❓ Q3、Q4 |
| F 判重 | 类目 + 物料 + 层级 + 影响范围，**四个全一样**才算重复；**只跟「生效」的比** | ❓ Q1 |
| G 纵向重叠 | **允许**（二级一条、三级一条并存），提单子时越具体越优先 | ✅（第 3 节第 7 条） |
| H 横向并存 | 集团配过的 → 下级不许再配（3.2）；集团没配的 → 二级集团和区域**可以各配一条**（3.3） | ✅ 文档已写 |
| I 横向优先级 | 二级集团一条 + 区域一条同时命中一家公司时，听谁的？ | ❓ **Q2（最要紧）** |
| J 3.2 的互斥 | 「已属于集团集采的类目，它和它下级不许再配其他层级」 | ❓ Q5 |
| K 删除 | 标记失效，不物理删；失效的行不参与 F 判重、不参与业务匹配 | ❓ Q6 |

## 5. 待产品定的 8 条（每条都给了我的建议）

### 🔴 Q1 什么算「重复」？

**问题**：老 6.5 定的判重口径（`类目+物料+层级+影响范围` 四个全同才算重复，且只跟生效的比）被产品**划掉了**。
现在文档里**一条判重规则都没有**。而代码现在的口径是「同一物料全表一行」，跟需求 3.3 直接打架。

**我的建议**：**照老 6.5 恢复**——四字段全同才算重复，且只跟状态=生效的比。
**理由**：3.3 要的就是同一物料多行，四字段判重刚好放行「不同 BU 各配一条」、拦住「真的填了两遍」；
「只比生效的」是必须的，否则一条删过的旧规矩会永远占着位置，同样内容再也录不进来。

**定错的代价**：口径松了 → 重复数据进库 → 匹配接口（`selectOne`）直接抛异常，**采购计划、采购方案、非平台录入三个页面全部提交不了**；
口径紧了 → 3.3 做不出来，业务该录的录不进去。

---

### 🔴 Q2 同一个节点上，二级集团配一条、区域也配一条，听谁的？（全场最要紧）

> 【订正 2026-09-07：本节初版举的例子是「集团、二级集团、区域三条都配在柴机油上」——**那个场景 3.2 确实拦死了，例子举错了**。
> 下面是订正后的版本。】

**先把 3.2 到底拦住了什么说清楚。**
原文：「同一类目/物料编码属于**集团集采**，则**此类目及下级/物料**不允许再维护其他层级」。

- ✅ **拦得住**：集团配了 `1701 润滑剂`（二级），冀东水泥就不能再配 `1701`，也不能配它下面的 `170101 润滑油`、`17010101 柴机油`、具体物料。
- ❌ **拦不住**：文档只写了「及**下级**」，**一个字没提上级**。集团配了 `170101 润滑油`（三级），
  冀东水泥去配 `1701 润滑剂`（二级，也就是它的**上级**）——**按文档字面是允许的。**

**而且这种配法不会打架。** 6.2 的匹配是「越具体越优先、找到就停」：

```
柴机油提单 → 查物料码，没有
           → 查末级 17010101，没有
           → 查 170101，命中【集团】那条 → 停，不再往上
```

冀东配的 `1701` 对 `170101` 这一片不生效，只对 1701 下面**集团没管的其他三级**生效（如 `170102`）。
**结论：纵向（上下级）不管怎么配，都不会出现「听谁的」的问题。**

---

**真正会打架的是这一种：同一个节点上，二级集团配一条 + 区域配一条。**

3.3 明写了「集采目录层级不属于集团集采，同一类目/物料**可以属于不同的二级集团或者区域**」，
而 3.2 只管「集团集采配过」的情况，**管不到这里**。

关键在于**板块和区域是两个不同的维度**，一家公司**同时**有一个板块、一个区域：

- 冀东水泥（二级集团）配了 `1701`；
- 唐山区域（区域）也配了 `1701`；
- **唐山那家冀东水泥的公司**——既属于冀东水泥板块、又属于唐山区域，**两条同时命中**。

> 板块 × 板块不会撞（一家公司只属于一个板块），区域 × 区域也不会撞（`所属区域` 是单值字段）。
> **只有「板块 × 区域」这一种会撞，而 3.3 恰恰明确允许它。**

**我的建议**：**越具体越优先——区域 > 二级集团**。
**理由**：跟纵向那条方向一致，一套心智模型；业务上「板块定大方向、区域再收紧」也说得通。

**定错的代价**：这条不定，第 6.3「取物料明细区最小层级」无从算起——连候选有哪几条都没定；
代码那边匹配用的是 `selectOne`，命中两条就抛异常，**必须改成 selectList + 按优先级挑一条**，
而「按什么优先级」就是这一问的答案。**这一条不定，9/11 那批的核心逻辑写不了。**

**顺带把 3.2 的两个小口子一起问了**：

① **3.2 只写了「及下级」，上级是有意放开还是漏写？**
（我的建议：就按字面放开——纵向不会有歧义，拦了反而挡住「集团管细的、板块管粗的」这种合理配法）

② **3.2 的校验方向**：先有集团集采的行、再配它下级 → 拦，这个清楚。
**反过来呢——冀东先配了 `1701`，集团后来要配 `170101`，允许吗？**
（我的建议：允许。集团那条自动「盖住」170101 这一片，正好是 3.2 想要的效果）

### 🔴 Q3 「影响范围」选二级集团时，能填几个板块？

**问题**：§4 只说「录入指定的二级集团BU编码」，**没说能不能填多个**。
比如冀东水泥和混凝土集团联合集采，一条规矩填两个 BU，行不行？
如果能填多个，那第二期分支②「向上一级报到二级集团」——**报给哪一个？**

**我的建议**：**允许填多个**（字段本来就是 `/` 分隔的多值），但**审批上报取「提单企业自己所属的那个 BU」**。
**理由**：字段和存法都现成，不用改表；上报对象按提单人所属板块取，唯一且不会歧义。

**定错的代价**：如果限死只能填一个，联合集采就得录两条，判重口径也跟着变。

### 🔴 Q4 第三档叫「区域/**企业**集采」，「企业」那半边怎么填？

**问题**：§4 只写了区域怎么填（录区域组织编码），**「企业」两个字一句没提**。
业务如果说「我只想管这三家公司」，现在**没有任何字段能表达**。

**我的建议**：**这期只做「区域」，「企业」不做**。
**理由**：① 区域主数据本身就不干净（854 家企业里 622 家没填区域，占 73%；9 个板块一家都没填；36 个区域码里近一半是把公司名当区域填的）；
② 真要按企业列举，`bu_code varchar(256)` 只塞得下约 28 个编码，得先改表。
**顺带建议：区域这一档功能做出来但先不启用**，等主数据补齐再打开——现在开，那 9 个板块一家企业都命中不了，测都测不了。

**定错的代价**：现在不问清楚，这个层级只做出一半；上线后业务提「我要按企业管」就是返工改表。

### 🟡 Q5 3.2 那条互斥校验，拦在哪一步？老数据怎么办？

**问题**：3.2「同一类目/物料属于集团集采，则此类目**及下级/物料**不允许再维护其他层级」。
要做就得在录入时沿类目树**往上往下都查一遍**。两个细节没定：
① 拦在页面保存时，还是导入时报错？② 库里已有的违规数据怎么办？

**我的建议**：**导入时拦（现在只有导入这一条入口），老数据先不动、只管新录的。**
**理由**：现在 7343 行全是集团级、没有第二种层级，所以**今天一条违规都没有**；
真正会撞上是上线后开始配二级集团和区域的时候，管住新录的就够了。

**注意**：3.2 和 Q2 管的**不是同一件事**，两条都要做，不冲突——
3.2 管的是「**集团集采**配过之后，下面不许再插手」；
Q2 管的是「集团**没**配，二级集团和区域各配了一条，撞上了怎么办」。
3.2 拦不到 Q2 那个场景（它只在有集团集采行的时候才起作用）。

### 🟡 Q6 删除改成「标记失效」之后的三件事

**问题**：② 失效的行还占不占判重位置？② 要不要「恢复」按钮？③ 界面上默认还显示失效的行吗？

**我的建议**：
- ① **不占**——判重只跟生效的比（就是 Q1 里那半句）；
- ② **不做恢复**——需要就重新导一条，逻辑最简单，不会出「恢复了之后跟现有的撞车」这种事；
- ③ **列表默认只显示生效的**，加一个「状态」筛选条件让人能翻出失效的；导出跟着筛选条件走。

**定错的代价**：③ 不定前端做不了页面。

### 🟡 Q7 上线那天，7343 条老数据这两个必填字段填什么？

**问题**：「集采目录层级」和「是否强管控」是新增必填，老数据全是空的。空着新逻辑判断不出来，**单子会卡在审批里**。

**我的建议**：**层级统一填「集团集采」；是否强管控统一填「否」。**
**理由**：层级填集团集采是因为今天这些规矩本来就是管全集团的，没有争议。
强管控填「否」是为了**平滑上线**——填「是」的话，这七千多条规矩对应的单子一夜之间全部变成最严那一档
（分支①：企业→二级集团→集采执行单位→总部，且「是否集采」不许改），**上线当天全集团审批链条一起变长**。
先全填「否」，上线当天系统行为跟今天基本一致，之后业务再一批批把该强的调成强。

> ⚠️ `12c开会提问.md` 第 4 条里默认值写的是「强管控全填**是**」，跟这里不一致。**去开会前先自己定一个，别带两个默认值进去。**

**另外必须要到的一份东西**：**生产上现在实际管哪些类目的清单**。
我只能看到 test/uat，UAT 上是轴承、电线电缆、润滑剂、煤炭、办公文具、办公设备，**里面没有钢材**，
但产品说生产上六大类是有钢材的。**拿 UAT 数据推口径，上线就是错的。这份清单要当场敲一个交付日期。**

**顺带一个数据质量问题**：7343 条跟物料主数据比对，**207 条物料编码在主数据里已查不到、389 条物料已停用**，
合计约 600 条占 8%。**要不要趁这次一起清掉？**（我的建议：清掉，反正这些行现在也匹配不上任何单子。）

### 🟢 Q8 「启用时间」这个字段到底做不做？

**问题**：需求开头 §3 写了「启用时间、失效时间；（根据启用时间，管后不管前）」，
但下面 §2 的字段清单里**只有失效时间，没有启用时间**。前后不一致。

**我的建议**：**不加独立字段，就用创建时间当启用时间**——录进去那一刻起生效。
**理由**：「管后不管前」的意思是「新规矩只管以后的单子，不追溯已提交的」，用创建时间完全够；
真要支持「今天录、下个月一号才生效」，那就得加定时任务和「未生效」这个第三种状态，是另一个量级的活。

**定错的代价**：如果产品要的真是「预约生效」，这条现在不问，后面要补状态机和定时任务。
