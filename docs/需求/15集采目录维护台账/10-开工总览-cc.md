# 0. 三十秒：这个需求是什么

金隅冀东有一张表，叫**集采目录台账**（`sc_plan_product_range`，7343 行）。
它记的是一句话：**「哪些物料 / 哪些类目，必须走集中采购，不许各家企业自己买。」**

今天这张表只能表达**一档**：要么全集团统管，要么不管。
这次要把它拆成**三档**，并且给每条规矩加上"强不强制""什么时候失效"：

```
       今天                              改完之后
  ┌──────────────┐              ┌────────────────────────────┐
  │ 在台账里 = 集采 │   ──────►    │ 集采目录层级：集团 / 二级集团 / 区域·企业 │
  │ 不在      = 不管 │              │ 是否强管控：  是 / 否                  │
  └──────────────┘              │ 影响范围：    哪些板块 / 哪个区域        │
                                 │ 状态+失效时间：这条规矩还算不算数        │
                                 └────────────────────────────┘
```

**为什么要拆**：以前只有"全集团统管"一档，太粗——水泥板块想自己管点东西管不了。
拆完之后，**不同层级的规矩走不同长度的审批链**，这才是这次改造真正的目的。

# 1. 四个新字段，一句话业务含义

| 字段 | 业务上是什么 | 影响什么 |
|---|---|---|
| **集采目录层级** | 这条规矩**归谁管**：集团 / 二级集团（板块） / 区域·企业 | 决定审批走几级、要不要派给集采执行单位 |
| **是否强管控** | 采购员**能不能把「是否集采」改成否** | 强管控=改了要多审一级；弱管控=改了照常走 |
| **失效时间 + 状态** | 这条规矩**还算不算数** | 失效后新单子不再受管（**老单子照旧**，"管后不管前"） |
| （已有）**影响范围** | 这条规矩**管哪些板块 / 哪个区域** | 二级集团填板块码；区域填区域组织编码，**判重时要换算成所属板块** |

## 3.4 三个最容易搞混的地方（会前吵了好几轮，这里定死）

| 混淆点 | 定论 |
|---|---|
| **「最小层级」到底哪个方向** | 需求文档说「取**最小**层级」、产品嘴上说「取**最高**层级」，**是同一件事**：取管控最严的 = 集团集采。（`OrganizationLevelEnum` 里集团=1，数字最小=层级最高） |
| **匹配优先级 vs 表头取值，方向相反** | **匹配**（一行物料命中多条规矩用哪条）→ **范围越窄越优先**，区域赢。<br>**表头**（一张单多行物料记哪级）→ **层级越高越优先**，集团赢。<br>前者是"这条物料归谁管"，后者是"这张单按谁的规矩审"。**两个问题两套逻辑。** |
| **二级集团/区域算不算「集采」** | **算**。三档都是 `isCollection=是`，区分靠新增的「集采层级」变量（产品原话，录音 11:45） |
