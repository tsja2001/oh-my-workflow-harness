## 3. 第二周 · 改「规矩怎么用」

### 3.1 业务上的变化：单子上从 1 个章变成 3 个章

```
今天：  提交采购计划/方案 ──► 系统只回写一个「是否集采 = 是/否」 ──► 审批流只认这一个

改完：  提交采购计划/方案 ──► 系统回写三个：
                              是否集采     （判定口径整个换掉，见下）
                              集采目录层级 （一张单多行物料，取最小 = 层级最高 = 集团赢）
                              是否强管控   （多行物料，有强取强）
                          ──► 递给审批流 ──► 华姐按三条分支走：
                              ① 强管控 + 集团集采        → 企业→二级集团→集采执行单位→总部，是否集采不许改
                              ② 强管控 + 二级集团/区域   → 改成"否"要向上一级审批
                              ③ 弱管控 + 二级集团/区域   → 改成"否"走原流程
```

**「是否集采」的判定口径换成**（需求 6.2 + 2.4 + 4）：
先按物料编码 → 没有取末级类目 → 再没有逐级向上；**并且**只看状态=生效的行；**并且**要落在影响范围内。

> ⚠️ **这里有两个方向相反的规则，是整份需求最容易搞混的地方：**
>
> ```
> 一行物料命中了两条规矩，听谁的？   → 影响范围越窄越优先（区域赢）
> 一张单子多行物料，表头记哪一级？   → 层级越高越优先（集团赢）
> ```
> 前者是「这条物料归谁管」，后者是「这张单子按谁的规矩走审批」。**两个问题，两套逻辑**（`13` §1.1 的 D2 / D3）。

| 口径变化 | 报表上的方向 |
|---|---|
| 加了「状态=生效」过滤 | 已作废规矩的物资不再算集采 → **降** |
| 加了「影响范围」过滤 | 不在管辖内的企业不再算集采 → **降** |
| 类目放开到末级 | 原来匹配不到的现在能匹配 → **升** |
| 允许改成"否" | 弱管控的单子会被采购员改掉 → **降** |

> **净效果无法预测，但一定会变，而这些报表是给领导看的。**
> → 必做两件事：**上线前后各跑一次对账**（W2-12）＋ **提前跟报表使用方打招呼**。
