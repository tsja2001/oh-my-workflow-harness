## 零、一句话抓住这两个字段

> **集采目录层级 = 这条规矩是谁定的。**
> **影响范围编码 = 这条规矩管谁。**
>
> **这两个字段必须成对看**，单看任何一个都没意义——层级决定了影响范围那一栏该填什么。

# 一、为什么要加"层级"这个字段

## 1.1 今天的台账：一条规矩 = 全集团，没有第二种可能

uat 实测，7343 行台账的「影响范围编码」只有两种值：

| 影响范围编码 | 行数 |
|---|---|
| `BU001/BU002/BU003/BU004/BU005/BU006/BU007/BU008/BU009/BU010/BU011/BU0013` | **7,342** |
| `1`（脏数据） | 1 |

**全是同一个串。** 意思就是"这条规矩管全集团"——今天的系统里，集采规矩只有这一种。

## 1.2 这带来两个具体的麻烦

**麻烦一：领导问不出数。**
"集团层面集采做了多少钱？冀东水泥自己集采了多少？"——**答不上来**，因为每一条规矩都没记"我是谁定的"。

**麻烦二：一刀切。**
冀东水泥想自己管一批物料（别的板块不用管），今天做不到——一填就是全集团都得跟着走。

## 1.3 加了层级之后

每条规矩带上"出身"：

```
这条螺纹钢的规矩 —— 是集团总部定的  → 全集团 854 家企业都得走集采
这条办公用品的规矩 —— 是冀东水泥定的 → 只有冀东水泥下面 258 家企业走
这条水泥的规矩 —— 是唐山区域定的     → 只有贴了"唐山区域"标签的 8 家企业走
```

报表能分开算，审批流能分开走（`01c` 6.5 那三条分支），这就是这次改造的核心价值。

# 二、先看清组织长什么样（三档就架在这上面）

## 2.1 招采的组织是**两层平铺**

```
北京金隅集团（总部）
    │
    ├── BU001 北京金隅集团股份有限公司 ……… 16 家
    ├── BU002 冀东水泥 ………………………… 258 家   ← 最大的一块
    ├── BU003 混凝土集团 ………………………  86 家
    ├── BU004 冀东发展 …………………………  60 家
    ├── BU005 金隅新型建材产业化集团 ……… 109 家
    ├── BU006 金隅地产开发集团 ………………  96 家
    ├── BU007 金隅投资物业管理集团 ………… 120 家
    ├── BU008 天津建材集团（控股）…………  76 家
    ├── BU009 北京金隅财务 ……………………   4 家
    ├── BU010 北京建筑材料科学研究总院 ……  15 家
    ├── BU011 京才公司 …………………………   6 家
    ├── BU012 建材集团党校 ……………………   2 家
    └── BU013 冀东国贸 …………………………   6 家
                                    合计 854 家
```

**只有两层：BU（二级集团）和企业。中间没有别的节点。**（数据来自 uat `ubm_organization_manage`，实测。）

## 2.2 「区域」不在这张图上——它是**贴在企业身上的标签**

这是最容易搞混的一点：

```
❌ 错误的想象：集团 → BU → 区域 → 企业   （区域是一层节点）

✅ 实际的样子：集团 → BU → 企业
                          └─ 每家企业身上贴着一个标签：所属区域 = "唐山区域"
```

带来的直接后果：**你没办法像"选一个 BU"那样"选一个区域"**，只能反过来查
"哪些公司贴了 `TSQY` 这个标签"。库里对应的是 `ubm_organization_manage.belong_plate_code`。

# 三、三档，一张表说清

| 集采目录层级 | 谁定的规矩 | 管谁 | 影响范围编码填什么 | 集采执行单位 |
|---|---|---|---|---|
| **集团集采**（一级） | 集团总部 | 全集团 854 家 | **所有** BU 编码 | **要填** |
| **二级集团集采**（二级） | 某个 BU 自己 | 该 BU 下属企业 | **指定的** BU 编码 | 不用填 |
| **区域/企业集采**（三级） | 某个区域 | 贴了该区域标签的企业 | **区域编码** | 不用填 |

对照 `01c` 原文 §4：

> 如果选择"集团集采"，"影响范围编码"录入**所有二级集团BU编码**，所有企业均执行集采逻辑；
> 如果选择"二级集团集采"，录入**指定的二级集团BU编码**，指定BU编码的下属企业执行此集采逻辑；
> 如果是"区域/企业集采"，录入**指定的区域的组织编码**，区域编码下的关联企业均执行此集采逻辑。

**举三个具体例子**（用 `10e` 那条润滑剂的链条）：

| 想达到的效果 | 层级 | 类目/物料 | 影响范围编码 |
|---|---|---|---|
| 全集团买柴机油都得走集采 | 集团集采 | `17010101` 柴机油 | `BU001/BU002/…/BU013`（全填） |
| 只有冀东水泥买柴机油要走 | 二级集团集采 | `17010101` | `BU002` |
| 只有唐山区域那 8 家要走 | 区域/企业集采 | `17010101` | `TSQY` |

# 五、今天的「影响范围」这一列，其实是**摆设**

这是本节最反直觉的一条，但很重要：

**今天判断"这条物料是不是集采"的代码，根本不看影响范围。**

三处判断集采的地方，条件里都没有 BU：

| 位置 | 干什么的 | 有没有 BU 条件 |
|---|---|---|
| `PlanProductRangeServiceImpl.java:135` | 采购方案/计划/供应商增补提交时判集采 | ❌ 没有 |
| `PlanServiceImpl.java:2031` | 计划转采购时取集采执行单位 | ❌ 没有 |
| `PlanTaskServiceImpl.java:684` | 同上（审批通过分支） | ❌ 没有 |

`bu_code` 全仓库唯一被用到的地方是 `PlanProductRangeServiceImpl.java:65`——**台账列表页上那个搜索框**。

## 5.1 所以这次改造的本质是

> **让"影响范围"第一次真正生效。**

新逻辑要多问一句：命中台账某行之后，**再看当前这家公司在不在这条规矩的影响范围里**：

```
命中了一条台账规矩
   ↓
这条规矩是什么层级？
   ├─ 集团集采      → 直接算数（所有企业都在范围内）
   ├─ 二级集团集采  → 看当前公司的 belong_bu_code 在不在影响范围串里
   └─ 区域/企业集采 → 看当前公司的 belong_plate_code 在不在影响范围串里
```

## 5.2 顺带：现有数据里那个串是错的

`BU001/BU002/…/BU011/BU0013` 这个串有三个毛病：

1. **`BU0013` 这个编码不存在**——真实的是 `BU013`（冀东国贸）；
2. **漏了 `BU012`**（党校，2 家）和真正的 `BU013`（冀东国贸，6 家）；
3. 一列存多个值、用 `/` 分隔，靠 `like` 匹配——**`like '%BU001%'` 会同时命中 `BU0013`**。

今天没出事，纯粹因为**没人读这一列**。改造之后它开始生效，**这 8 家企业会立刻错**（期初初始化要一起修，见 `11b` A7）。

**我之前写的「这一列代码里根本没人读」是错的。** 今天顺着这次的问题重新追，它是有人读的：


**产品说的"此字段控制集采执行单位在线确认计划"，是对的。**

## 6.2 审批流分支（`01c` 6.5 的 ①②③）

层级 + 是否强管控，一起决定这张单子走哪条审批路线：

| 组合 | 审批路线 | 「是否集采」能不能改 |
|---|---|---|
| ① 集采=是 & 强管控 & **集团集采** | 企业 → 二级集团 → 集采执行单位 → 总部 | **不允许改** |
| ② 集采=是 & 强管控 & **二级集团/区域** | 改成"否"后：企业/区域→二级集团；二级集团→总部 | 可以改，**改了要向上一级审批** |
| ③ 集采=是 & 弱管控 & **二级集团/区域** | 改成"否"后走原流程 | 可以改，不升级 |

**⚠️ 这块是郭小华的活**（群里明说了）。你的边界：**把 `是否集采`、`集采目录层级`、`是否强管控` 三个值算准、存对、传给工作流**，
分支怎么画不用你管。（工作流传参的机制见 `10c` §3.3：起流程时往 `ProcessStartAO.metasList` 塞 `metaCode`+`dataValue`。）

# 七、三档同时存在时的规矩（`01c` 3.2 / 3.3）

产品这版把 `11b` A2「洞二」答了一半：

> **3.2** 同一类目/物料属于"集团集采"，则**此类目及下级/物料不允许再维护其他层级**；
> **3.3** 不属于"集团集采"的，同一类目/物料**可以**属于不同的二级集团或者区域。

翻成人话：

```
❌ 不允许：柴机油 = 集团集采
           柴机油 = 冀东水泥的二级集团集采     ← 集团已经管了，别人不许再插手
           润滑油(它的上级) = 集团集采
           柴机油 = 任何其他层级              ← 上级被集团管了，下级也不许

✅ 允许：  柴机油 = 冀东水泥的二级集团集采
           柴机油 = 混凝土集团的二级集团集采   ← 两个 BU 各管各的，互不冲突
           柴机油 = 唐山区域的区域集采
```

**为什么"横向允许"不会打架**：因为影响范围不重叠——一家企业只属于一个 BU，
所以对某一家具体企业来说，最终只会剩下一条规矩命中。（前提是 §5 那个"按影响范围过滤"真的实现了。）

**但还有一个没答的**：万一同一个 BU 下，二级类目配了一条、四级类目又配了一条，两条都命中怎么办？
按 `01c` 6.2「先按物料编码→末级类目→往上一级」的口径，应该是**越细越优先**。这条建议问一句确认。

|---|---|---|---|
| **台账**「集采执行单位编码」 | **MDM 码**（`srm_company.mdm_code`） | `CN13000363` | 给转采购记录打标，供机电公司在「集采采购计划（集采单位端）」里筛出自己要执行的单子 |
| **字典** `collection_company` | **UBM 组织编码**（`ubm_organization_manage.org_code`） | `12300000` 机电公司、`10010072` 北分 | 提交单据时先看**当前登录用户所在公司**在不在这份名单里，在就**直接判"不是集采"放行** |

同一家机电公司，在台账里叫 `CN13000363`，在字典里叫 `12300000`。
（代码里靠 `SchemeToPurchaseController.java:427-435` 拿当前公司 `companyCode` 去换 `mdmCode` 才对上。）

> 道理很简单：**你自己就是那个负责统一采购的人，你买东西当然不算"绕过集采"**——所以字典那份名单是"豁免名单"。

## 十、为什么二级集团 / 区域档**不用填**集采执行单位

三个角度，指向同一个答案。

### 10.1 最直接的证据：审批流路线里就没有这一环

`01c` 6.5 三条分支，逐字对比：

| 分支 | 审批路线 | 有没有"集采执行单位"这一环 |
|---|---|---|
| ① 集团集采 + 强管控 | 企业 → 二级集团 → **集采执行单位** → 总部 | ✅ **有** |
| ② 二级集团/区域 + 强管控 | 企业/区域 → 二级集团；二级集团 → 总部 | ❌ 没有 |
| ③ 二级集团/区域 + 弱管控 | 按原流程 | ❌ 没有 |

**只有集团集采的流程里，机电公司是一个审批节点。** 不配这个字段，那一环就没人审——所以集团档必须填、另两档填了也用不上。

### 10.2 业务上的道理

"集采执行单位"是**集团层面指定的统一采购方**。
- 集团说"全集团买轴承都得集采" → 得有一家统一去买 → 机电公司；
- 冀东水泥自己说"我们板块买办公用品要集采" → **它自己内部消化**，不需要机电公司代劳；
- 唐山区域自己定的规矩，同理。

### 10.3 代码上会发生什么

`getCollectionSupplierCode`（`PlanServiceImpl:2029`）只在这行是集采时调用，把台账的执行单位写进
`sc_scheme_to_purchase.collection_supplier_code`；「集采采购计划（集采单位端）」再按登录公司的 MDM 码筛它。

**二级/区域档不填 → 这一列是空 → 那些单子不会出现在机电公司的待执行清单里。** 正是业务想要的。

⚠️ **但代码要补一句判空**：现在 `range.getSupplierCode()` 没有 null 检查，`range` 本身为 null 时直接 NPE。

## 十一、二级集团集采：影响范围"岂不是只能填自己的 BU"？

**你这个疑问戳到了需求的一个真空。**

### 11.1 先说清楚一件事：数据模型里**根本没有"谁定的"这个字段**

这次新增的字段只有四个：集采目录层级、是否强管控、失效时间、状态。**没有"制定方"。**

所以严格讲，系统里存的不是"BU 定的规矩"，而是：

```
集采目录层级 = 二级集团集采     ← 这条规矩的"级别"
影响范围编码 = BU002            ← 这条规矩"管谁"
```

**"谁定的"是靠这两个字段隐含表达的**——级别是二级集团、范围是 BU002，那默认就是冀东水泥定的。

### 11.2 所以「只能填自己」这件事，需求**没有规定**

`01c` §4 原文只说："录入**指定的**二级集团BU编码"——
**没说只能填一个，也没说必须是自己**。而且字段 `bu_code varchar(256)` 本来就是用 `/` 分隔存多个的
（今天那 7342 行就存了 12 个）。

所以技术上完全可以出现：

```
层级 = 二级集团集采
影响范围 = BU002/BU003        ← 冀东水泥 + 混凝土集团 联合集采
```

**但这样一来审批往哪个 BU 报？** 分支 ② 写的是"企业/区域发起 → 二级集团"，只有一个二级集团。
**这是需求没覆盖的情况，要问产品。**

### 11.3 「为什么不填企业编码」——这也是个真问题

⚠️ **注意这个层级的名字叫「区域/企业集采」，但 `01c` §4 只说了区域怎么填，"企业"那半边没有对应的填法。**

| 层级名字里有 | §4 说填什么 | 对不对得上 |
|---|---|---|
| 二级集团 | BU 编码 | ✅ |
| 区域 | 区域的组织编码 | ✅ |
| **企业** | **没说** | ❌ **缺** |

如果业务真需要"只管某三家公司"，现在**没有字段能表达**。
技术上也有个小限制：`bu_code` 是 `varchar(256)`，用 `/` 分隔的话最多塞得下约 28 个 8 位编码——
要真按企业列举，字段得加长。

## 十二、区域档：填自己的区域编码？

**是的**，`01c` §4 原文："录入**指定的区域的组织编码**，区域编码下的关联企业均执行此集采逻辑"。

填法就是 `TSQY`（唐山区域）这种，系统再去组织表里捞出所有 `belong_plate_code = 'TSQY'` 的企业。

**但第四节说过的两个坑仍在**：
- 73% 的企业根本没贴区域标签，9 个 BU 覆盖率为 0；
- 36 个"区域码"里近一半是公司码和脏数据（`10000000 冀东发展集团` 就是个公司，却占了 60 家）。
