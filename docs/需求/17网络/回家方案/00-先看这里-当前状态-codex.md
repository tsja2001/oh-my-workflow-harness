## 当前结论

| 项目 | 当前状态 | 用途 |
|---|---|---|
| A 通道：WARP + 家庭 CIDR | 已完整验收 | 像局域网一样访问 `192.168.5.0/24`，适合 Home Assistant、路由器和其他家庭设备 |

| 性能 | 功能可用，但 VS Code 仍可能感觉卡 | B 冷连接没有稳定快于 A；复用后的短命令约 1 秒 |
| 30 分钟稳定性测试 | 按用户要求跳过 | 不是当前上线阻塞项 |

推荐采用“混合使用”，不用二选一：

- SSH、VS Code、WSL/CLI AI：优先 B 的 `home-mac-access`。
- 直接访问家庭 IP 或其他设备：使用 A。
- B 登录异常时，A 的 `home-mac` 是现成回退；不要删除任何一条。

## 当前最重要的限制

- B 只简化了公司侧路径，家庭 Mac 的 `cloudflared` 仍被 Mihomo strict-TUN 捕获并走 `Daily-Reality-443`。
- A、B 在家庭侧共用同一个 `home-lan` Connector；远程改坏 Mac Clash/Connector，会同时断掉两条路。
- 所以当前禁止在没有 Mac 本地控制、自动回退或其他带外恢复手段时，远程试改家庭侧网络。
- 旧 `saturate` Tunnel、现有 VLESS/CDN、Tailscale 禁用状态和公司网络设置都不属于本轮清理范围。
