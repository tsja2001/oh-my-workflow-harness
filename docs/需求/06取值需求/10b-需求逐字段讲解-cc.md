# 第一部分：先把“供应商编码”讲清楚（你问的）

## 1.1 一家公司为什么有好几个“编码”？——用“一个人”打比方

你把“一家公司”想象成“一个人”，那么：

| 编码种类 | 好比一个人的… | 谁发的 | 例子（机电公司） |
|---|---|---|---|
| **统一社会信用代码** | **身份证号** | 国家（工商登记） | `911302300759817983` |
| **SCM 编码**（招采/SRM 系统的 company_id） | **A 公司给他的工牌号** | 咱们这套招采系统内部 | `SCM00002105` |
| **平台码**（company_code，JYJT 开头） | **某平台给他的会员号** | 金隅交易平台 | `JYJT0002472` |
| **MDM 编码**（CN 开头） | **集团统一花名册的工号** | 集团主数据平台（MDM） | `CN13000363` |

**同一个人（公司），在不同系统里被起了不同的号。** 身份证号是国家唯一的、跟人走；工牌号/会员号/花名册号是各家系统自己发的、只在自己系统里认。

## 1.2 为什么产品说“都是 SCM 开头”，你却查到 CN 开头？

两个原因，都不矛盾：

1. **机电公司确实有个 SCM 开头的码**：`SCM00002105`——它就在招采的“供应商主档”里。所以产品说机电是 SCM 开头，**没错**。
2. **但北分没有 SCM 码**：我把库翻遍了，北分**不在“供应商主档”里**（它是金隅自己的单位，是在“煤炭 SAP 数据”里作为供应商出现的），它身上只有一个 **MDM 码 `CN11005095`**。所以你想给北分找个 SCM 开头的号——**根本不存在**。产品那句“都是 scm 开头”对机电对、对北分不成立。
3. **还有一层坑**：就算机电的 SCM 码是 `SCM00002105`，**咱们的数据货架（ES）里这五路数据，没有任何一路存的是这个 SCM 码**——非平台存的是身份证号(统一社会信用代码)、招采存的是会员号(JYJT)、云采存的是花名册号(CN)、煤炭那路啥都没存。SCM 码只躺在“供应商主档”那张表里，没被抄进货架。所以“按 SCM 码去货架里筛”＝**一条都筛不到**。

一句话：**SCM 码是真实存在的（机电有、北分没有），但它不是货架里存的那套；产品说“用 SCM 码”，落到数据上得翻译成“每一路各自存的那套码”。**

## 1.3 这些码是不是唯一、一一对应？

- **统一社会信用代码（身份证号）**：全国唯一，一个法人一个，**分公司有自己独立的一个**（和总公司不同）。最铁的 1:1。
- **SCM / JYJT / MDM**：对**已经进了供应商主档**的公司（比如机电），这几个码都在**同一行记录**上，彼此 1:1 对应，查一个就能带出其他几个。
- **但“覆盖面”不一样**：不是每家公司都进了供应商主档。**北分就没进**，所以它没有 SCM 码、只有 MDM 码。这就是为什么两家公司“能查到的码种类”不一样。
- 极少数情况一家公司可能挂多个 MDM 码（对接了多个主数据系统），但咱们这俩公司目前各是一个，不用操心。

**所以答案：在“同一套系统内”是唯一且一一对应的；跨系统时，同一家公司是好几个号，需要靠主档或 MDM 把它们串起来。**

## 1.4 落到这个需求：到底该怎么用（结论）

你不用纠结“统一成 SCM 码”。因为**每一笔要挑供应商的地方，本来就锁死在某一路来源上**，用那一路自己的码就行：

| 要在哪一路挑哪家公司 | 用什么码（我已查库确认） |
|---|---|
| 非平台(FP) 里挑机电公司 | 机电的**身份证号** `911302300759817983` |
| 云采(YC) 里挑机电公司 | 机电的**MDM 码** `CN13000363` |
| 煤炭(MT) 整路 | 整路就是北分，不用挑；补上北分 `CN11005095` 更稳 |
| 机电台账(JD) 整路 | 整路就是机电公司，不用挑 |

> 🔔 **要问产品的只剩一句**：机电公司这几套码（SCM `SCM00002105` / 身份证号 `911302300759817983` / MDM `CN13000363`），**你们后续对账、看报表习惯认哪一套**？我按你们习惯的那套在页面上显示名字/编号即可。（怎么筛是我技术上的事，我按每路自己的码筛，不用你们管。）

# 第三部分：逐字段讲计算逻辑

## 先讲 4 个通用概念（后面每个字段就不重复了）

1. **金额字段**：每条记录的含税金额叫 `taxTotal`。所有钱最后 **÷10000 变成“万元”，保留两位小数**。
2. **时间字段**：每条记录有个“公示/下单时间” `bookTime`。所有“月/季/年”都是拿它卡时间窗，**统一到“查询日前一天 24:00”结束，不含今天**；起点按指标不同（本月1日 / 本季度1日 / 2026-01-01）。
3. **“是否集采”**：每条记录有个标志 `是否集采(isCentralized)`，1＝是。**“集采交易额”就是只加“是否集采=1”的记录。**
   - ⚠️ 需求里还写了“或采购业务类型属于集团集采/二级/区域集采”，但我查过：**货架上的“采购业务类型”是拿“是否集采”临时翻出来的假字段**，真正的二级/区域集采数据根本不存在。所以现阶段这句就等于“是否集采=1”。（🔔见第四部分）
4. **“扣三笔”＝去重**：同一笔机电/煤炭的钱，企业可能在 FP/YC 录了一遍、官方台账(JD/MT)又录了一遍，货架上就重复了。所以要**保留官方那份(JD/MT)，把 FP/YC 里重复的减掉**。这三笔是：
   - 减：FP 里“机电公司 + 机电四大类”
   - 减：FP 里“北分 + 煤炭”（目前 FP 里没有这种数据，减的是 0，是个防重复的保险）
   - 减：YC 里“机电公司 + 机电四大类”
   - **机电四大类**＝钢材(1501)、润滑剂(1701)、电线电缆(2302)、轴承及备件(2502) 这四类物资。🔔编码待定，见第四部分。

## ① 核心指标（首页最顶上那几个大数字）

### 当月 / 季度 / 年度 集采交易额
**大白话**：这段时间里，集采花了多少钱（去掉重复录入的）。
**怎么算**：
```
集采交易额 = 【时间窗内 & 是否集采=1 的所有来源金额之和】
           − FP里(机电公司+四大类)
           − FP里(北分+煤炭)      ← 目前是0
           − YC里(机电公司+四大类)
```
- 三个指标**算法一模一样，只有时间窗不同**：当月＝本月1日~昨天；季度＝本季度1日~昨天；年度＝2026-01-01~昨天。
- 招采(ZC)会不会算进去？**会**——只要它“是否集采=1”就自然进了第一行的“所有来源之和”，不用单独处理。

### 年度集采率
**大白话**：集采的钱占平台总钱的比例，衡量“集中采购做得好不好”。
**怎么算**：`年度集采交易额 ÷ 平台总交易额 × 100%`，百分比两位小数。

### 平台总交易额
**大白话**：这一年平台上一共成交了多少钱（做集采率的分母）。
**怎么算**：
```
平台总交易额 = 【2026-01-01~昨天 全部交易金额之和（不分是否集采）】
             − 同样那三笔重复（机电四类、北分煤炭）
```
> 🔔 **确认点**：平台总额的“底数”是**所有交易（含非集采）**，但扣减的三笔却是**只扣集采口径的重复**——这是需求原文写的（有点不对称）。请产品确认“分母＝全平台所有成交额、只把重复的机电/煤炭减掉”，对不对。这个数是集采率的分母，领导最看重，别算错。

## ② 各二级集团（集采规模）

**大白话**：把①的“年度集采交易额”按“这笔钱属于哪个子集团”拆开，看每个集团各买了多少、占比多少。

**怎么算**：每条记录都带一个“板块编码 `buCode`”，就按它拆。**算法和①的年度集采交易额完全一样，只是多加一个“板块=某集团”的条件**：

| 集团 | 板块编码 | 交易额算法 | 交易率 |
|---|---|---|---|
| 水泥集团 | BU002 | 年度集采额算法 + 只看 BU002 | 该集团额 ÷ 平台总额 ×100% |
| 地产集团 | BU006 | 同上，只看 BU006 | 同上 |
| 新材产业化集团 | BU005 | 只看 BU005 | 同上 |
| 投资物业集团 | BU007 | 只看 BU007 | 同上 |
| 冀东发展集团 | BU004 | 只看 BU004 | 同上 |
| 天津建材集团 | BU008 | 只看 BU008 | 同上 |
| **直管单位** | 其余所有板块 | **年度集采总额 − 上面六个之和** | 直管额 ÷ 平台总额 ×100% |

- 关键点：扣那三笔重复时，也是**在这个集团内部扣**（比如算水泥集团，就减“水泥集团里的 FP 机电四类”），这样六个集团加起来能和总数对上，不会串。
- 你之前担心的“机电四类分不清属于哪个集团”——不用怕，每条数据自带板块编码，561 条全有。
- 注意：交易率的**分母永远是“平台总额”**，不是“集团自己的额”。

> 🔔 **确认点**：机电台账(JD)那路的板块，是不是可信、就按它自带的板块归属？（会不会出现“机电公司一整笔记在水泥、其实跨了好几个集团”的情况。）
