## 0. 先说清楚三块需求的关系（这是你乱的根源）

```
01 台账需求（2026-07 做）      → 造了 4 张"维护页面"，让人把业务数据录进 MySQL
   ├─ 价格趋势维护          → sc_price_trend
   ├─ 煤炭重点坑口日指标    → sc_coal_pit_daily_indicator(_item)
   ├─ 集采日金额统计台账    → sc_collection_daily_amount_ledger
   └─ 集采日计划统计台账    → order 侧表

03 报表需求（2026-07 做）      → 造了一条"搬运管道"：每天凌晨把业务数据搬进 ES 货架
   └─ 5 路定时任务：FP/ZC/MT/JD（source 服务）+ YC（order 服务同事侧）
       → 统一写入 ES 索引 index_centralized_procurement_report_test

06 取值需求（2026-08 做）      → 造了"展示侧"：门户首页 + 改驾驶舱接口
   ├─ overview（门户首页所有金额类数字）→ 实时查 ES 货架聚合
   └─ kengk/mt/gc（趋势图）           → 实时查 MySQL 台账（改前是死缓存）
```

**你的理解基本对，只有一个关键修正：**
- 台账/业务页面录入 → ✅（01）
- 集采业务统计报表更新（定时任务进 ES）→ ✅ 只对"金额/交易类"成立（03 的同步任务）
- 取值统计页面展示新数据 → ✅ 展示侧实时查（06）
- **但趋势类（煤价/钢价/坑口）不走 ES、不走定时任务**——它直接从台账表实时读，保存即发布（见第 2 节管道A）。这是 06 开发时把"死缓存"换成"台账"带来的特性。

## 3. 管道A 录入实操：价格趋势维护页面

### 3.1 入口

菜单：**采购方案（procurementScheme）→ 集采业务台账 → 价格趋势维护**（路径 `#/businessManagementLedgerJC/maintenancePriceTrend`）
页面上按钮：新增 / 修改 / 删除 / 导出。**没有独立"发布"按钮——保存 = 发布**（add/update 接口自动把 `publish_time` 设为当前时间，代码 `PriceTrendServiceImpl.add/update`）。

### 3.2 页面字段（新增/修改要填的）

| 页面字段 | 对应列 | 必填 | 怎么填 | 备注 |
|---|---|---|---|---|
| 集采执行单位 | `execute_unit_name` | 是 | 下拉选组织（可选编码 `execute_unit_code` 一并保存） | 建议选"机电公司"？否——价格趋势的执行单位没有硬性要求，随意选即可，驾驶舱只看类目+指标+年月 |
| 年度 | `year` | 是 | 手输，格式 `2026` | ⚠️ 必须是**4位数字字符串**，脏数据（如"1"）会被驾驶舱丢弃 |
| 月份 | `month` | 是 | 手输，格式 `07`（两位） | ⚠️ 两位补零；"7"会被解析失败丢弃 |
| 类目 | `category_code/name` | 是 | 选**煤炭**(COAL) 或 **钢材**(STEEL) | 页面若只提供编码，名称按编码存 |
| 指标名称 | `indicator_name` | 是 | 5 个固定值之一（见下表） | 驾驶舱按这个字符串匹配，**写错一个字就查不到** |
| 价格（元） | `price` | 是 | 手输数字 | 驾驶舱只取非空价格 |

**指标名称 5 个固定取值（驾驶舱代码 `PriceTrendCockpitProviderImpl` 硬编码）：**

| 类目 | 指标名称 | 出现在哪 |
|---|---|---|
| 煤炭 | `煤炭月成交价格` | 煤价趋势图的**成交价**线（dataValue） |
| 煤炭 | `煤炭月环渤海价格` | 煤价趋势图的**环渤海价**线（ext02） |
| 钢材 | `钢材月成交价格` | 钢价趋势图的**成交价**线（dataValue） |
| 钢材 | `螺纹月成交价格` | 钢材**螺纹钢月指标**（ext02） |
| 钢材 | `中厚板月成交价格` | 钢材**中厚板月指标**（ext03） |

### 3.3 保存后发生了什么（代码级）

1. `add`：自动生成流水号 `JGQS-日期-序号`，`publish_time=当前时间`，insert。
2. `update`（修改已存在记录）：`publish_time=当前时间`，updateById → **修改即重新发布**。
3. `delete`：逻辑删除（`delete_sign=1`），驾驶舱查询直接过滤掉。
4. 驾驶舱接口 `mt/gc` 每次被调用时：查 `delete_sign=0 & 类目 & 指标名称 & price非空` → 按 `publish_time` 倒序 → **同一个"年+月+指标"只保留发布最新的一条** → 组装成**当前月往前 12 个自然月**的数组（窗口外的不显示，缺的月份/指标返回 null 空点）。
5. 门户趋势图、老驾驶舱趋势图都实时调这个接口 → **刷新页面就变，不需要定时任务、不需要重启**。

| 录入场景 | 预期结果 |

## 4. 管道B 录入实操：三个业务台账页面

### 4.1 煤炭重点坑口日指标页面

- 入口：`#/businessManagementLedgerJC/coalPitDailyIndicator`
- **页面字段**：集采执行单位、发布日期（不填自动=当天）、**坑口1~5：每个坑口=名称+含税价格**（最多 5 个，名称留空则跳过）
- **保存行为**：主表+明细一起存；修改 = 明细全删重插；删除 = 主表明细一起删。**无发布按钮，保存即生效**（`publish_date` 默认当天）。
- **驾驶舱读取规则**：`kengk` 接口取**最新一批**（按 `publish_date/publish_time/create_time` 倒序第一条）的 5 个坑口 → 所以录新一批 = 驾驶舱坑口图整体换成新批次的 5 个坑口价格。
- **坑**：修改"老批次"不会生效（驾驶舱只看最新批次）；要生效请新增一批（发布日期=今天）。

### 4.2 集采日计划统计台账页面（目前是"孤儿"，录了不影响任何页面）

- 入口：`#/businessManagementLedgerJC/dailyPlanStatisticsLedger`
- 数据落在 order 侧表；产品原设计喂老驾驶舱"集采计划分析（响应率/执行率/完成率/滞后率）"，但 source 的 `queryDoRate()` 是**空实现**、没接 order 的 `calculateRates()`，驾驶舱那块仍在读死缓存。
- **结论：这个页面录数据目前只影响台账自己的列表/导出，不影响门户、驾驶舱、报表。**

### 4.3 集采日金额统计台账页面（= JD 机电四大类的源头，管道B）

- 入口：`#/businessManagementLedgerJC/dailyAmountStatisticsLedger`

| 统计日期 | 日期选择 yyyy-MM-dd | JD 同步按这个日期区间扫 |
| 采购企业 | 组织下拉 | 自动带出所属板块（buCode）|

- **保存行为**：新增流水号 `JCRJE-yyyyMMdd-NNN`，保存即写表；修改/删除常规。
- **录入后的流转（重点）**：
  1. 当天任何时刻录入 → 数据停在 MySQL；
  2. **每天 03:40 任务 244**（或手动 `POST /e/business/source/centralizedProcurementReport/syncJd`）把"执行单位=机电公司"且"统计日期在区间内"的台账搬进 ES（`dataSource=JD`，主键=流水号）；

### 4.4 其他四路业务数据（FP/ZC/MT/YC）——不是台账，是业务系统本身

这四路不需要在台账页面录，是**各自业务系统/流程跑出来的数据**，同步任务只是把它们"搬"进 ES。业务上各自的操作位置、进 ES 的条件如下（全部按同步代码逐行核实）：

#### ① FP 非平台录入（绿色通道）

菜单位置（企业端工作台）：**采购寻源 → 非平台采购业务录入 / 非平台采购业务查询**；工作台 → **非平台采购业务审核**

| 项 | 内容 |
|---|---|
| 业务场景与页面 | 不走招采/云采平台的采购业务，业务员在**非平台采购业务录入**页录主单+物料明细（`/procurementScheme/index.html#/supplier/increasedList`）；录完走审批流，在**非平台采购业务审核**页审批（`/procurementScheme/index.html#/approveMgt/increasedListApprove`）；**非平台采购业务查询**页可看全部单（`/procurementScheme/index.html#/dynamicPage/source/fpt`） |

| 进 ES 条件 | `approve_status=101`（**审批通过**）**且** 采购业务分类 ∈ {101 集团集采/102 二级集采/103 区域集采} **或为空**（只排除明确选了"分散采购"的）**且** `update_time`（审批结束时间）在同步区间 |
| 粒度 | 一单 N 条物料 → N 条 ES 记录 |
| 供应商字段 | 主单的**统一社会信用代码** `three_in_one_id_code`（所以机电公司在这路是 911302300759817983） |
| 是否集采 | 主单 `is_jc` 字段（**可为空**——为空就不计入集采，3.6 亿那条测试垃圾就是没勾集采） |

| 坑 | 页面录入时"是否集采"不勾 = 永远不算集采；无独立供应商编码字段，用三合一码 |

#### ② ZC 招采平台

#### 四路共同规则（跨路通用）

1. **同步的时间轴是"业务完成时刻"**：FP=审批结束、ZC=公示、MT=公示、YC=下单。定时任务每晚扫**前一天**的这个时间，所以"今天办完的业务，明天凌晨进 ES，后天门户能看到（因为 overview 还截止昨天）"。
2. **幂等**：主键唯一（FP/ZC/YC=业务编号+物料；MT 额外带日期），同一区间重跑不会重复。
3. **手动补数**：`sync`（FP）/`syncZc`/`syncMt`/`syncJd` 四个接口传时间区间即可补历史；**YC 没有 source 侧手动接口**，补数找同事或等每日任务。
4. **"机电公司"四路四个码**：FP=911302300759817983、ZC=JYJT0002472、YC=CN13000363、JD=12300000——同一家公司，各来源各自筛码（13 定稿 2.7 设计），**不要在 ES 里用单一编码跨来源过滤**。
5. **ES 里同步进来的都带 `isCentralized` 和 `categoryCode` 两个关键筛选字段**：isCentralized 为空/0 的不算集采（不计入门户集采额），categoryCode 不在类目字典的会影响品类卡（门户品类卡精确匹配 CAT4）。

## 6. 容易踩的坑（全部有代码证据）

1. **当月数据不进趋势图**：窗口=当前月之前 12 个月，8 月录的 8 月数据要 9 月才显示。
2. **指标名称是硬编码 5 个**，写错字（含空格/全角）→ 静默查不到，无报错。
3. **年/月脏数据被丢弃**：非 4 位年、非 2 位月、解析失败 → 直接跳过（test 里那条 `year='1'` 就是这么来的）。
4. **修改=重新发布**：改价格也会刷新 publish_time，同月同指标以最后一次保存为准。
5. **日金额台账选错执行单位 → 数据失踪（已定性为 03 bug）**：03 同步条件写死"执行单位名称=机电公司"，但产品定义的机电公司是编码 12300000（唐山冀东机电设备有限公司），页面下拉只有真实组织——**页面录入 100% 进不了 ES**。修复=同步条件改按 `execute_unit_code='12300000'`；待产品确认板块归属和历史假数据清理（话术见 4.3）。
6. **老驾驶舱 4 块旧数据**：centerHeader/categoryAmount/doRate/situA 仍读死缓存（2024-2025），与本次改造无关。
7. **删除是逻辑删除**：delete_sign=1，驾驶舱/报表都过滤，但库里还能查到（方便恢复）。
8. **金额口径**：ES 里 `taxTotal` 是"元"，页面显示"万元"（÷10000 保留 2 位）；负数照算（MT 有退货负额）。
9. **月度刷新**：每月 1 号打开门户，当月/当季金额显示 0（当月窗口未开始），是口径设计。

## 8. 一句话总结

> 趋势/坑口：**录入页面保存 → 台账表 → 驾驶舱接口实时读 → 刷新即见**（不需要定时任务）；
