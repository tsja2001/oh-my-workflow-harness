## 2. 怎么从录音定位到这一页的（排查路径，供下次复用）

录音里没有任何页面名（`00-...md:33` 已写明）。定位靠的是**把目录名拆开对代码**：

1. `云采` 在代码里不是「云采协同」，全库搜 `云采协同` → **0 命中**；搜 `云采` → 命中的是 **`云采平台`**（= 商城，`dataSource='YC'`）和 **`内部协同`**（`dataSource='IN'`）。
2. `交易数据` → 搜出一张报表 `nbxtTransactionDataReport`（页面注释「内部协同-交易数据专栏」，`02zhaocai-front/scm-vue-all-productmgt/src/views/reportMgt/nbxtTransactionDataReport/index.vue:1`），它的**「分平台」就是「数据来源」下拉**：`招采平台 ZC` / `非平台录入 OUT` / `内部协同 IN`（`index.vue:133-137`）——这就是产品说的「分平台看」。**注意这张报表页自己是对的**：标签写「昨日交易额」、绑 `summary.yesterdayAmount`（`index.vue:49-51`）。
3. 再搜「协同交易数据」这个**标题**→ 命中**云采商城首页的「协同交易数据」区块**（`goodsRecommend.vue:69`）——名字和用户起的目录名 `22云采协同交易数据bug` 逐字对上：**云采(商城) + 协同 + 交易数据**。这块就是 §1 出问题的那一页，而且它调的是**同一个接口**。
4. 对照两个页面对同一份返回值的用法 → 报表页字段名对得上、商城页对不上 → 收口。

> ⚠️ 「定时任务」这个方向当时是错的（用户口头猜测，`00-...md:35` 已标注为猜测）。实测调度是正常的，见 §4。

## 3. 第二层：就算把字段名改对，也没有「当日」这个数

这是必须在动手前跟产品敲定的口径问题，否则改完还是"不对"：

- 后端 `getTradeDataSummary()` **压根没有当日窗口**，四格只有 昨日/当月/当年/累计（`SourceMetaQueryServiceImpl.java:1393-1457`，接口无入参，`SourceMetaQueryController.java:226-229`）。
- 写入侧三条同步任务的默认窗口**全是「昨天一整天」**：
  - 招采 `TradeDataReportServiceImpl.java:101-104` → `calculateYesterdayDate()`
  - 非平台录入 同文件 `:280-283`
  - 内部协同 `InOrderReportServiceImpl.java:142-146`
- 而且 **XXL 的参数带不了日期**：参数按 `-` 切割，日期本身含 `-`，所以定时任务只能传 `{}`＝同步前一天（成文记录见 `docs/需求/03采集管理业业务统计报表/20-开发交接-cc.md:183-189`）。
- ⇒ 结论：**「当日下单额」这一格要么按现在的口径改成「昨日」，要么就得新写一条实时/当日取数逻辑**（不能复用这三个 job）。这是**需求决策**，不是代码 bug。

【推断】当年做这一格的人可能是想让前端显示"昨日"但顺手写了 `dailyAmount`（无法证实的原因：`feat:协同交易数据联调` 两个提交的信息里没写口径，也没有对应需求文档）。

### ② test 环境「内部协同交易数据统计」菜单点进去是空白

- 菜单 M614 `menu_url` = `/productMgt/index.html#/internalCollaboration/transactionDataColumnMan`，**正好 70 个字符、停在半截词上**（`ubm_rbac_menu` 该列是 `varchar(255)`，全表**只有这一条**长度=70，所以不是列宽截断，是填的时候漏了字）。

- 【推断】产品当时不是从这个菜单进的（进不去），更可能是从商城首页看到的（无法证实的原因：录音里没有页面路径信息）。

### ③ 招采/非平台两条写入链路有「永久漏采」的口径缺陷
