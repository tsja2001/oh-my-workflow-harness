## 0. 给你的大白话（30 秒看完）

- **能跑起来**，而且**不用改团队仓库里的任何代码**。核心思路一句话：**代码里写死的那些"上线用的地址"，我们不去改文件，而是启动时从外面塞几个参数把它顶掉**。
- 这个 source 服务自己**不带数据库/缓存等配置**，它开机第一件事是去公司的"配置中心（Nacos）"把配置拉下来。代码里默认写的 Nacos 地址是**集群内部的名字**，你的电脑连不上——这是头号障碍，塞一个参数换成能连的地址即可。
- 你的机器**现在就在公司网里**：Nacos 通、测试库通（我刚实测过）。所以最省事的跑法是**连测试环境的配置和数据库**跑（这也是咱们平时开发直连 test 的规矩）。代价：本地跑时读写的是**共享的测试数据**，删改要当心。
- "不改代码还能改配置"有三层手段（从最干净到兜底）：**① 启动参数外部覆盖（首选，零文件改动）→ ② 仓库外放一个本地配置文件 → ③ 真要改跟踪文件时用一条 git 命令让改动永不进提交**。都在 §5。
- 有个天然限制：source 会调别的服务（认证、字典、订单…）。单机本地只能跑通"只碰数据库/ES 的接口"；**要调别的服务的接口在本地会失败**（那些服务注册的是集群内网 IP，你连不上）。这不是配置能修的，是"单机只起一个服务"的固有代价。§7 会说清楚哪些能跑、哪些不能。

## A. 实测跑通版（2026-07-30 已验证，以此为准）

- **中和 Maven http-blocker**：`~/.m2/settings.xml` 加了一条同名覆盖 `maven-default-http-blocker` 的 mirror（`mirrorOf` 指向不存在项＝不拦）。原文件已备份 `~/.m2/settings.xml.bak-20260730-163331`。校验 XML 合法、之前缺的 BOM 能拉下来。

### A.1 源码分支
`scm-source-all` 切到 **`feature/taizhang-yang`**（工作区干净）。`scm-cloud-starters-web` 在 **`test`**。均无跟踪改动。

### A.2 关键：把跨团队依赖对齐到 test 版（本地 .m2 缓存，不动仓库）
本地全量编译会撞**跨团队 SNAPSHOT 漂移**——`feature/taizhang-yang` 源码用到的 operlog/order/srm/ifs/professor 等跨团队 API，plain `1.0.0-JDSN-SNAPSHOT` 坐标里的是**陈旧版**（缺新方法/新类）。Nexus 对每个包并存 4 个版本：plain / `-TEST-SNAPSHOT` / `-UAT-SNAPSHOT` / `-PROD-SNAPSHOT`。解法＝把这些包的 **`-TEST-SNAPSHOT`** 内容装进 plain 坐标：
- 单个：`bash /tmp/align_test.sh <artifactId>`（下载 TEST 版→`install:install-file` 到 plain 坐标，`.orig-bak` 备份）。
- 成批（推荐）：`bash /tmp/comprehensive_align.sh`——从**已打好的 fat jar 的 `BOOT-INF/lib/`** 枚举它**真正捆绑**的跨团队 `com.pcitc` 包（约 120 个），逐个对齐到 TEST（本次成功 **75 个**，其余 45 个无 TEST 版＝框架包，plain 即可，自动跳过），排除本地从源码构建的 `scm-source-*`。
- **两个坑**：①**编译过 ≠ 能启动**——Feign 启动解析**整个接口**，会暴露编译没碰到的"缺类"（本次 `ProfessorDTO`），所以必须对齐"**捆绑的全部**"跨团队包，不能只补编译报错那几个；②对齐是**改本地 .m2 缓存、不是改代码**，可用 `.orig-bak` 回滚。

## 1. 这套项目是怎么启动的（先建立心智模型）

| 事实 | 证据 |
|---|---|
| 启动入口（那个 `main`）在 **启动壳工程**里 | `03zhaocai-start/scm-cloud-starters-web/scm-cloud-source/src/main/java/com/pcitc/scm/source/starter/SourceApp.java` |
| 你正在开发的业务代码在**另一个仓库**，以 jar 形式被启动壳依赖 | `01zhaocai-end/scm-source-all/**`，产物 `scm-source-web-jar` |
| 应用名 / 端口 / context-path | `scm-source-web` / `8110` / `/scm-source-web`（见 `bootstrap.yml`） |
| profile 由环境变量决定，默认 dev | `bootstrap.yml`：`spring.profiles.active: ${APP_PROFILE:dev}` |
| **真正的配置（数据库/Redis/ES/MQ）不在本地文件里**，全在 Nacos | 启动模块 `resources/` 只有 `bootstrap-*.yml` + `logback-spring.xml` + `si.jks`，**没有任何 `application-*.yml`**（实测 `ls` 确认） |
| 启动会**自我注册**进 Nacos，并装配了一堆对别的服务的 Feign 调用 | `SourceApp` 上 `@EnableDiscoveryClient`；`@Import` 里有 Ubm/Order/Srm/Contract/Ifs/Mdm/Template/Pay/Professor… 十几个 FeignConfig；还有 ES/MQ/Cache 的 WebConfig |

**一句话**：`SourceApp` 是个空壳，开机先连 Nacos 抓配置，再把 `scm-source-all` 的 controller/service/mapper（来自 jar）装配进来，同时连数据库/Redis/ES/MQ、注册进服务发现。所以"能不能跑起来"= "这几样后端设施能不能连上"。

## 2. 本地运行的拦路虎（逐条实测取证）

### 🔴 障碍 1：Nacos 默认地址是集群内部 DNS，本机连不上（头号障碍）
- 现象：`bootstrap-dev/test/uat/prod.yml` 里 `server-addr` 默认值都是
  `nacos-headless.default.svc.cluster.local:8848` —— 这是 K8s **集群内部**的服务名，只有 pod 内部能解析，你的 WSL 解析不了。
- 好消息：地址是占位符 `${nacos.ip:...}`，**启动时塞一个 `nacos.ip` 就能顶掉，不用改文件**。
- 实测：外部可达的 Nacos 有两个，且都带 `scm-jdsn-test` 命名空间：
  - `10.0.54.16:30996` → HTTP 200，命名空间列表含 `scm-jdsn` / `scm-jdsn-test` / `scm-jdsn-uat` ✅
  - `10.0.54.19:8848` → 同上 ✅

### 🔴 障碍 2：所有业务配置都在 Nacos，本地没有兜底文件
- 现象：DB 连接串、Redis、ES、MQ、各种开关都在 Nacos 的 `scm-source-web-<profile>.yaml` + 共享的 `global-config.yaml` 里，本地 `resources` 没有。
- 影响：**必须能连上 Nacos 且 profile 选对**，否则连不出配置直接启动失败。
- 破法：`APP_PROFILE=test` 走 `bootstrap-test.yml`（namespace 已默认 `scm-jdsn-test`，账号密码已在该文件里，无需我们提供），配合障碍 1 的 `nacos.ip` 覆盖即可。

### 🟠 障碍 3：Maven 3.8.7 会拦公司的 HTTP 私服（构建/拉依赖会失败）
- 现象：本机 `mvn` 是 **3.8.7**（不是文档建议的 3.6.3）。3.8.1+ 默认内置 `maven-default-http-blocker`，会拦所有 `http://` 私服；公司 Nexus 正是 `http://`。
- 实测：`~/.m2/settings.xml` 存在但 **0 条 `<mirror>`**，没有中和 blocker；对启动壳做离线解析直接报
  `Cannot access maven-default-http-blocker (http://0.0.0.0/)`，缺 `spring-boot-dependencies:2.7.18`、`spring-cloud-alibaba-dependencies:2.2.9` 等 BOM（这些还没缓存到本地）。
- 结论：**第一次拉依赖必须联网，且必须中和 blocker**。两条现成路子（都在 `note/backend-env-setup.md` §3-4、`ai-docs/工作规范与习惯.md` 2026-07-21 条）：
  1. 装 Maven **3.6.3**（3.6.x 不带 blocker，最省心）；或
  2. 保留 3.8.7，在 `settings.xml` 里加一条 mirror 中和 blocker（把公司 http 私服放行）。
- 注意：这是"**改你自己机器的 Maven 配置**"，不是改团队仓库，不违反"不改代码"目标。

### 🟠 障碍 4：会自我注册进测试环境的服务发现（可能污染共享 test）
- 现象：`@EnableDiscoveryClient` + 默认 `register-enabled=true`，本地一起来就把自己作为一个 `scm-source-web` 实例注册进 `scm-jdsn-test`。测试网关会把它当成一台真实节点，**可能把测试流量转发到你的笔记本**。
- 破法（零文件改动）：启动加 `-Dspring.cloud.nacos.discovery.register-enabled=false`。它只关"把自己登记上去"，**不影响本地去发现/调用别的服务**。**强烈建议每次都带上**。

### 🟡 障碍 5：开机就要连的后端设施（Redis / ES / MQ）可达性未知
- 现象：`SourceApp` 装配了 ES 仓库（`@EnableElasticsearchRepositories`，chase / operlog 两个包）、MQ（`MqWebConfig`）、缓存（`CacheWebConfig`→Redis）。这些**在启动阶段**就可能建连；连不上会让启动报错或卡住。
- 已确认可达：Nacos ✅、测试 MySQL ✅。
- **未确认**：Redis / ES / MQ 的地址（在 Nacos 配置里）从 WSL 是否可达。它们大概率也在 `10.0.54.x` 这个已经通的网段，但只有第一次点火才知道。§7 给了每一项的日志信号和兜底开关。

### 🟡 障碍 6：跨服务 Feign 调用在单机本地天然打不通
- 现象：source 要调 auth（校验登录）、ubm（字典）、order、srm、contract…这些通过"服务发现 + Feign"。发现拿到的是它们注册的**集群内网 pod IP（10.x overlay）**，你的机器**路由不到**。
- 影响：**只碰数据库/ES/Redis 的接口能在本地跑通**；**需要串别的服务的接口会在 Feign 这一跳失败**。
- 这是"本地只起一个服务"的固有限制，不是配置 bug。想缓解要把个别 Feign 指到测试**网关**（可达），属于进阶操作，§7.4 给方向，不是启动必需。

## 4. "连测试" vs "全本地"两条路线（为什么选前者）

| | A. 连测试环境（推荐） | B. 全本地自建 |
|---|---|---|
| 你要准备什么 | 几乎不用，机器在公司网即可 | 本地装 Nacos + MySQL + Redis + ES + MQ，并把全套配置灌进去 |
| 数据 | 直连 `scm_source_test`（符合团队"开发直连 test"规矩） | 空库，要自己造数据 |
| 风险 | 读写的是**共享测试数据**，删改要当心（用 §2 障碍4 的开关避免污染服务发现） | 无共享污染，但搭建成本高 |
| 起步速度 | 最快 | 慢，且和线上配置容易漂 |
| 适合 | **"先把 source 跑起来做开发"这个目标** | 需要完全隔离、断网演示时 |

本文只展开 **A**。B 属于"以后真需要隔离环境"再single做，不在当前目标内。

## 5. 不碰仓库代码的三层手段（本需求的核心）

> 目标：本地怎么折腾都行，但 `git status` 在三个公司仓库里保持干净、提交里绝不带本地运行的痕迹。

### 手段 ①：启动参数外部覆盖（首选，零文件改动）
Spring Boot 的取值优先级：**命令行参数 `--key=value`（最高）> 系统属性 `-Dkey=value` / 环境变量 > 配置文件/Nacos**。所以：
- **bootstrap 阶段的占位符**（`nacos.ip`、`APP_PROFILE`、`nacos.namespace`）→ 用 **环境变量或 `-D` 系统属性**（这些在连 Nacos 之前就要被解析）。
- **要顶掉 Nacos 里某个具体值**（比如临时换个数据库、关某个开关）→ 用 **`--key=value` 程序参数**（优先级最高，一定压得住 Nacos）。

本地启动最少只需三个（全是外部参数，不进任何文件）：
```
APP_PROFILE=test                                        # 走 bootstrap-test.yml（namespace/账号已在里面）
-Dnacos.ip=10.0.54.16:30996                             # 顶掉连不上的集群内 DNS
-Dspring.cloud.nacos.discovery.register-enabled=false   # 不把本机注册进测试服务发现
```
可选：`-Dfastjson.parser.safeMode=true`（和线上 SafeMode 缓解口径对齐，见需求 05）。

### 手段 ②：仓库外放一个本地配置文件（需要成组覆盖时）
不想在启动命令里堆一长串 `--key=value` 时，把它们写进一个**放在仓库之外**的文件，例如 `/home/t/local-run/scm-source/application-local.yml`，启动加：
```
--spring.config.additional-location=file:/home/t/local-run/scm-source/
```
文件在仓库外 → 天然不会被 git 看到。适合放一批本地覆盖项。（注意：要压过 Nacos 的同名值，仍建议关键项用手段①的 `--key=value`；additional-location 更适合放 Nacos 里没有、纯本地新增的项。）

### 手段 ③：万不得已必须改跟踪文件时——让改动永不进提交
如果某种情况非改一个已被 git 跟踪的文件不可（尽量避免），用这条把它"锁"成本地私有：
```bash
# 告诉 git：这个文件的本地改动请无视，别显示、别暂存、别提交
git -C 03zhaocai-start update-index --skip-worktree scm-cloud-starters-web/scm-cloud-source/src/main/resources/bootstrap-test.yml

# 需要恢复跟踪时（比如要拉同事对该文件的更新）
git -C 03zhaocai-start update-index --no-skip-worktree <同一个文件>
```
- `skip-worktree` 就是你说的"配置 git 提交方式让本地改动不进提交"，是最干净的兜底。
- 副作用：被锁的文件如果远端有更新，`git pull` 会因本地改动冲突，先 `--no-skip-worktree` 解锁再拉。
- **本地新增的文件**（脚本、外置配置、run 辅助文件）：放仓库外，或写进各仓 `.git/info/exclude`（本地忽略清单，**不改**被跟踪的 `.gitignore`）。

### 关于 IDEA 运行配置 / `.idea` / `target`
- 实测：`03zhaocai-start` 与 `01zhaocai-end` 两个公司仓 **没有根 `.gitignore`**，且 `.idea/`、`*.iml`、`.run/` 目前都**未被 git 跟踪**（`git ls-files` 为空）。
- IDEA 的运行配置默认存在 `.idea/workspace.xml`（属你个人、且未被跟踪）→ **只要你不手动 `git add .idea`，就不会进提交**。
- 建议一次性把噪音挡在 `git status` 之外（本地操作，不改跟踪文件）：
```bash
printf '.idea/\n*.iml\n.run/\ntarget/\nlogs/\n' >> 03zhaocai-start/.git/info/exclude
printf '.idea/\n*.iml\n.run/\ntarget/\nlogs/\n' >> 01zhaocai-end/.git/info/exclude
```

## 6. 两种跑法（照抄即可）

## 7. 第一次点火：看哪些信号、卡住怎么办

启动日志按顺序会经过这几关，对着看就知道卡在哪：

1. **连 Nacos 抓配置**：看到类似 `Located property source` / 加载 `scm-source-web-test.yaml`、`global-config.yaml` = 障碍 1、2 已过。
   - 报 `UnknownHostException nacos-headless...` 或超时 = `nacos.ip` 没生效，检查是不是塞成程序参数了（要用 `-D`/环境变量）。
2. **数据源初始化（Druid）**：看到 Druid/HikariCP 建连日志无异常 = 测试库通（已预验证）。
   - 报连不上 = 确认在公司网/VPN。
3. **Redis / ES / MQ 建连**（障碍 5 的未知项）：
   - Redis（Lettuce）默认懒连，一般不挡启动；真挡就看 Nacos 里 Redis 地址是否可达。
   - ES：`SourceApp` 已 `exclude` 了两个 reactive ES 自动配置，但 `@EnableElasticsearchRepositories` 仍在。若卡 ES，先确认 Nacos 里 ES 地址从 WSL 可达。
   - MQ：`MqWebConfig` 若在启动建 producer/consumer，broker 不可达会报错或重连刷屏。
   - **共性兜底**：某个设施本地实在连不上又不影响你要开发的功能时，可用手段①的 `--key=value` 临时改成可达地址，或在明确知道对应自动配置类的前提下临时 exclude（这属于"改运行参数"，仍不碰仓库文件）。第一次点火拿到确切报错后再定点处理，不提前瞎关。
4. **服务注册**：确认日志**没有**把自己 `nacos registry, scm-source-web ... register` 上去（因为我们关了 `register-enabled`）= 障碍 4 已规避。
5. **起来后**：`http://localhost:8110/scm-source-web/...`。
   - 只读 DB/ES 的接口（如台账、集采驾驶舱读 `sc_collection_data`）→ 应能通。
   - 需要登录态的接口：本机是否认账，取决于 source 是本地用 `si.jks` 验 JWT 还是要回调 auth 服务；第一次拿 test 的 bearer token 打本地 `8110` 试一下就知道。
   - 调 ubm/order/auth 等的接口 → 见障碍 6，Feign 这一跳大概率失败（连不到集群内网 IP）。

### 7.4 想让跨服务接口也能在本地通（进阶，非必需）
把个别 Feign 客户端的地址从"服务发现"改成指向**测试网关**（`10.0.54.x`，可达），让请求走网关再进集群。这需要给对应 FeignClient 配 `url`/`spring.cloud.openfeign...` 覆盖，用手段①的 `--key=value` 或手段②的外置文件实现，仍不碰仓库。**建议等基础启动跑通、确有需要时再做**。

## 开发-运行闭环（改了 source 代码怎么让它生效）

- **IDEA 双工程法（推荐做开发）**：把 `03.../scm-cloud-source`（启动壳）和 `01.../scm-source-all`（业务）都导入同一个 IDEA 工程。因为版本号一致，IDEA 会用 `scm-source-all` 的**编译产物**替代 `.m2` 里的 jar → 你改 controller/service 保存后重启即生效，**不用重打 jar**。
- **命令行法**：改完 source 先 `cd 01zhaocai-end/scm-source-all && mvn -pl <改动模块> -am install -DskipTests` 更新本地 `.m2` 的 jar，再回 §6.1 重跑启动壳。
- 两种都只是"编译 + 本地安装 jar"，**不产生任何要提交的改动**。
