### 数据存在哪 **【实测，来自系统地图】**

> **这套系统是"写 MySQL、查 ES"**：业务表在 MySQL，列表/报表查询走 Elasticsearch，中间靠 XXL-JOB 定时任务同步。
> **对这次计划的直接影响**：凡是"加一个搜索字段""加一个筛选条件""导出多几列"的需求（P6-01、M3-02、P3-05、M2-01），
> 都要先判断这个字段**在 MySQL 有还是在 ES 有**。只改 MySQL 不改 ES 映射和同步任务，页面上什么都不会变。
> **另外：ES 分页/导出默认上限 10000，超了是静默截断** —— M3-01"发票批量下载/对账单批量导出"要盯这一条。

### 前端 **【实测】**

- Vue 2 + Vue CLI，Node `14.21.3`。`02zhaocai-front/` 下 30 个当前仓 + `scm-vue-all/` 下 26 个同名旧仓。
- **找页面一律先 `bash scripts/fe.sh find <中文关键词>`，硬 grep 必踩错仓。**
- 有一类**"动态页"页面定义在后端 JSON 里**（`GET /obs/json/plateform/<module>/<type>`），**前端源码搜接口名永远搜不到**，
  用 `bash scripts/fe.sh json <module>/<type>`。**这次 P3-02（检索状态缓存）要特别注意**——
  如果目标页面是动态页，缓存逻辑要加在动态页的通用渲染组件里，不是某个具体页面里。

## 4. 五个必须提前搞清楚的技术未知数

### 4.1 工作流引擎 DPS —— 影响 P1-01、P1-02、M1-03，以及所有走审批的功能

**【实测】** `01zhaocai-end/scm-workflow-all` 这个仓**不是流程引擎本体**：
- `scm-workflow-springboot/src/main/resources/bootstrap-dev.yml:39-42` 里配着 `dps: url: http://dps.scmflow-dev.jdsn.com/dps-service`
- `scm-workflow-base/.../DPSProcessServiceImpl.java` 全程用 `HttpClient` 调那个地址，还带 HMAC 签名认证
- 系统地图里也记着 test/uat 域名 `dps.scmflow-{test,uat}.jdsn.com` **【实测】**

**结论**：**审批流转的能力上限由 DPS 决定，不由你的代码决定。**
P1-02 要的"直退/逐级退回/回原驳回节点/自定义分支/会签/抢单/撤回"——
如果 DPS 支持，那就是配置活（这解释了为什么只给 8 个开发人天）；如果不支持，**这一项在本代码库里做不出来**。
**这是开工前必须有答案的问题**（`10d` 问题 5）。

### 4.2 帆软 —— 影响 P4-01 + M4-01（129 人天）

**【实测】** `grep -ril "帆软\|finereport\|fine_report"` 全 `01zhaocai-end` → **零命中**。
说明帆软**还没进这套系统**。引入一个 BI 平台涉及：部署、数据源打通（要不要给帆软直连数据库？直连哪个库？test 还是 prod？）、权限对接（帆软的用户体系怎么和平台的单点登录打通）、报表模板开发。
**【推测】** 这是一个**独立的实施项目**，通常由帆软的实施顾问或专职报表工程师完成，开发方式和 Java/Vue 完全不同。

> ⚠️ **对你的特殊风险**：你之前在 `03采集管理业业务统计报表` 和 `06取值需求` 里做的报表，
> 是手写 Java + ES 查询（后端 `SourceQueryBuilderImpl_<Flag>`，前端路由 `#/reportForms/<flag>`）**【实测】**。
> "**全体系**报表重构升级"字面意思是**这些都要推倒重来**。
> 要么你参与迁移（那这 129 人天就有你的份），要么说清楚"老报表保留、只新增帆软报表"。**必问。**

### 4.3 电子签章 —— 影响 P3-01 + P1-04（89 人天）

**【实测】** 代码库里搜"签章"只有 1 处命中，是 `scm-order-all` 一个 DTO 里的字段注释 `@ApiModelProperty("是否可以签章")`；搜"印章"零命中。
**基本可以认定是全新对接。** 需要知道的：用哪家（e签宝/法大大/契约锁/CA 中心）、是 SaaS 还是私有化部署、
证书怎么发给评委和供应商、签完的文件存哪、有没有法律效力的验签要求。**这些全是产品和法务要定的，不是你能拍的。**

### 4.4 AI 底座 —— 影响 P5 全部（295 人天）

原文 3 处写"基于集团统一 AI 底座"，实施阶段写"阶段二(**AI 预研**)"。
**"预研"这个词是计划自己给的免责声明**——说明连计划方也不确定这块能不能落地。

**但有一块是你逃不掉的前置工作，现在就该提出来**：
**P5-01 围串标要的"上传电脑 MAC 地址 / CPU 系列号重合检测"**，
数据必须在**供应商上传投标文件的那一刻**采集并入库。
**浏览器出于安全限制是拿不到 MAC 地址和 CPU 序列号的** **【推测：这是 Web 平台的通用限制】** ——
要么供应商端装一个客户端控件，要么改用别的指纹（IP、浏览器指纹、设备 ID），**这是产品决策，且会显著改变工作量**。
**这一条建议你早点提出来，因为提得越晚越像"开发在找借口"。**

### 4.5 OCR —— 影响 P2-03（40 人天，高优先级）

原文写"纳税/社保 **OCR 识别**自动审核"，但**"涉及接口"列写的是"无"** **【实测】**。
**这是计划表的一个漏项**：OCR 要么买第三方服务，要么走 AI 底座，不可能"无依赖"。
**必问**，否则这一项开工时才发现没依赖可用。

**再加三条纪律**（都是这套代码库上已有的教训，见 `ai-docs/经验教训.md` 和 `代码库地图.md`）：
1. **本地全量 `mvn compile` 本来就编不过**（跨团队 SNAPSHOT 漂移）。报错文件全是别人的 = 与你无关；报错在你的新文件里 = 你的问题。
2. **网关不剥前缀** —— Controller 必须自己写完整路径（`/e/business/...`）。
3. **AIM 跨服务调用在编译期看不见** —— 改接口签名不会报错，只会运行时炸。改任何 `@TypeMapping` 接口前先全库搜调用方。
