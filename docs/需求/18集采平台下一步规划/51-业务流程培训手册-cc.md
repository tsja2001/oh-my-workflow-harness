# 序 · 这套系统到底在跟什么较劲

先别看流程图。先想一个场景。

> 你是金隅冀东集团总部的人。集团下面有一百多家成员企业，一年要花掉**几百亿**买东西——
> 水泥厂要买钢球、耐火砖、煤；地产要买电梯、门窗；物业要买保洁用品。
>
> 现在给你一个权力：这一百多家企业怎么花钱，你说了算。
>
> **你会担心什么？**

大多数人第一反应是"怕买贵了"。但真正管过这事的人会告诉你，要担心的是**三件事**，而且第三件最要命：

### 担心一：买贵了

一百家企业各买各的钢材，每家都是小单，供应商没有让价的理由。
更糟的是——**总部根本不知道自己一年买了多少钢**，连谈判的底气都没有。

### 担心二：买脏了

采购是**最容易出事的岗位**，没有之一。
采购员和供应商吃顿饭、供应商之间私下商量好轮流中标、评委被打点……
出一次事，不是罚款的问题，是纪检、审计、上新闻。

### 担心三：说不清

这是最要命的。审计来了问："这个项目为什么给了这家公司？"
如果答案是"当时王经理定的，他现在离职了"——**这就是事故**。

不是买错了才是事故，**说不清楚就是事故**。

---

## 于是有了这套系统

**这套系统的每一个设计，都能追溯到上面三件事之一。** 记住这个对应关系，后面所有"怪规矩"都解释得通：

| 担心 | 系统的解法 | 你会在流程里看到 |
|---|---|---|
| **买贵了** | **制造竞争** | 公开发公告让更多人来投、必须够几家才能开标、比价、集中采购 |
| **买脏了** | **削减人为操作空间** | 随机抽专家、评委匿名、技术标商务标分开评、多道审批、自动查工商风险 |
| **说不清** | **全程留痕** | 每一步都是一张单据、每一次批准都记名字、结果必须公示 |

> 🔑 **整篇文档你只要记住一句话：**
> **这不是一个"买东西的工具"，是一个"证明我们买东西是干净的、并且能算得清的工具"。**
>
> 采购本身很简单——打个电话就能买。**复杂的全是为了这个"证明"。**
> 你以后看到任何一个觉得"多此一举"的步骤，先问："**它在防什么？它在留什么证据？**"

# 一 · 三个门户 = 三种人

新人最容易犯的第一个错，是把这套系统当成"一个网站"。

**它其实是三个网站**，登录进去看到的东西完全不一样。**【实测】**

## 🏢 企业端 —— 我们自己人

**谁在用**：采购员、各级审批领导、供应商管理岗、平台运营。
**他关心**：我要买东西、我要审批、我要看报表。
**规模**：菜单最多的一个，一百多个页面。审批相关的就有 **21 个**入口 **【实测】**。

## 🚚 供应商端 —— 外面来卖东西的公司

**谁在用**：供应商的业务员。
**他关心**：有什么活能接、我要投标、我中了吗、我的货款结了吗。
**规模**：十几个页面，很清爽。

## 👨‍🏫 专家端 —— 临时请来打分的人

**谁在用**：评标专家（集团内部的技术骨干，或外聘专家）。
**他关心**：有没有叫我去评标、我要打分。
**规模**：最小，几个页面。

---

## 🤔 为什么非要分成三个门户？

**【我的推断】** 三个原因，一个比一个硬：

**① 信息隔离是招投标的命根子。**
供应商绝对不能看到别家的报价，专家不能提前看到采购方的倾向。
**如果是一个门户靠权限控制，总有配错的一天；三个门户从物理上就隔开了。**

**② 三种人的"身份可信度"完全不同。**
自己人是有工号、有岗位、有上级的；供应商是外部企业，得先审资质才能进；
专家是临时角色，用完就撤。**把外人和自己人放进同一个后台，本身就是风险。**

**③ 三种人的使用频率天差地别。**
采购员天天用，供应商一年可能只投两次标，专家可能一辈子就来一次。
**给一年来一次的人看一百个菜单，他会直接放弃。**

> **一句话记住**：看到任何一个需求，先问"**这是给三种人里的哪一种做的？**"
> 比如"评委匿名化"是同时给专家端和企业端做的（专家之间互相看不到名字）；
> "供应商多子账号"是纯供应商端的。

# 二 · 一笔采购要经手多少人

现在认识一下主角们。**这些是系统里真实存在的岗位**（我做了口语化处理）**【实测】**：

| 岗位 | 通俗理解 | 在故事里干什么 |
|---|---|---|
| **企业-采购员** | **主角**，干活的那个人 | 编计划、编方案、发公告、抽专家、编定标方案。**全程最忙的人** |
| **企业-采购主管经理** | 采购员的直接领导 | 审计划、审方案、审定标（金额小的） |
| **企业-采购业务负责人** | 更高一级 | 审方案、审定标（金额大的） |
| **企业-经理 / 执行董事** | 公司领导 | 大额定标的最后一道 |
| **企业-业务监察** | 内部监督 | 只看不动，盯着流程有没有走歪 |
| **企业-供应商维护岗 / 主管经理岗** | 管供应商档案的 | 审入网、审入围、拉黑、解冻 |
| **平台-运营 / 技术运维岗**（集团层）| 总部的人 | 看全集团的数、处理异常，**不替任何一家企业做采购** |
| **监标人** | 纪检式的现场监督 | 开标评标全程在场，不打分，只见证 |
| **专家** | 临时请来的裁判 | 只做一件事：打分 |
| **供应商** | 外面的卖家 | 报名、交保证金、投标、供货、收钱 |

---

## ⭐ 这里有一条铁律，比什么都重要

**编的人和批的人，永远不能是同一个人。**

**【实测】** 我查过系统里的权限配置，这条铁律是**从设计上焊死的**：

- **"企业-采购员"这个岗位，身上一个采购审批权限都没有。**
- **"企业-采购主管经理"这个岗位，身上一个编制权限都没有。**

不是靠制度约束，是**系统里就点不到那个菜单**。

> 🤔 **【我的推断】为什么做得这么绝？**
>
> 因为采购舞弊最经典的形态就是"自己批自己"。只要一个人能同时决定"买什么"和"批准买"，
> 制度写得再漂亮都没用。**这在审计上有个专门的说法叫"不相容职责分离"，是内控的第一条。**
>
> 你会发现系统里**审批类的权限被切得极碎**——"审延期公告"是一个独立权限、"审澄清公告"是另一个、
> "审定标方案"又是一个。**碎到什么程度？有的权限只对应两个页面。** **【实测】**
>
> **为什么要切这么碎？** 因为审批权是**风险权**，必须能精确地、单独地授予某个人，
> 而且**不能顺带给他别的能力**。
> 反过来，"干活"的权限可以很大——**因为干活本身不产生风险，产生风险的是"批准"。**

---

## 还有一条你必须理解，否则会被绕晕

**同一个人在不同公司，身份是不一样的。**

**【实测】** 系统里"岗位"是**挂在公司上**的。同一个账号：
- 在**唐山盾石建筑**，他是**采购员**，能编采购计划；
- 切到**金隅集团阳光招采平台（全集团）**，他就变成**平台运营**，编制菜单全没了，只剩查询和监督。

页面右上角那个公司下拉框，**切的不是数据范围，是身份**。

> 🤔 **【我的推断】这个设计非常聪明。**
> 集团里一个人身兼数职是常态——他可能在 A 公司是采购员，在 B 公司是评审领导。
> 如果按"人"给权限，这个人就会同时拥有两套权限，**回到"自己批自己"的老路**。
> 按"公司 × 岗位"给权限，**他必须先声明"我现在是以哪个身份在操作"**，
> 系统才给对应的菜单——**每一次操作都有明确的身份归属，审计时能说清楚。**

# 三 · 第一幕：从"东西坏了"到"决定要买"

好，故事开始。

> **场景**：沧州临港金隅水泥厂，球磨机的钢球磨损严重，车间报上来：**需要 200 吨钢球**。

---

## 3.1 需求提报 → 采购计划

**👤 你现在是**：采购员
**🖥 打开**：企业端 → **采购计划** → **采购计划编制**
**👀 你会看到**：一个列表，点"新增"，填物料、数量、什么时候要、预估多少钱。

### 🤔 为什么要有"计划"这一步？直接买不行吗？

**【我的推断】** 三个理由：

**① 预算控制。** 计划是要审批的。审批的本质是"这笔钱花得对不对"，
**在还没花钱的时候拦下来，成本最低。** 等东西买回来了再说不该买，晚了。

**② 汇总的机会。** 这是最容易被忽略、但价值最大的一点。
一百家水泥厂各自报"我要 200 吨钢球"，如果直接各买各的，就是一百个小单。
**有了计划池，采购员才有机会把它们捞出来合成一个大单去谈判。**
—— **这就是"集中采购"在系统里真实发生的样子。**

**③ 留下"为什么要买"的证据。** 审计问起来，能翻到最初是哪个车间、哪个人、什么时候提的。

### 💡 一个你需要知道的现实

**【实测】** 系统里的采购计划，**有一半以上不是人在这个页面填的，是从别的系统自动推过来的**——
生产系统里库存低于安全线会自动触发补货，那些计划直接流进来。

> **【我的推断】这说明这个平台的定位是"寻源的执行器"，不是"需求的源头"。**
> "要买什么"是生产系统的事，这个平台负责的是"**怎么把它干净地买回来**"。
>
> 这解释了一个现象：**采购计划相关的功能一直比较薄弱**，而"方案→评标→定标"那一段功能密度极高。
> **因为那一段才是这个平台的立身之本。**

---

## 3.2 计划审批

**👤 换人了**：采购主管经理
**🖥 打开**：企业端 → **审批待办** → **采购计划审批**
**👀 你会看到**：待办列表里躺着刚才那条计划，点进去，通过或退回。

> ⚠️ **新人最容易搞错的地方**：审批不是"点个同意"那么简单。
> **退回**是要写理由的，而且**退回之后计划会回到采购员手里重新改**——
> 这一来一回都留在系统里。**审批的价值一半在"批不批"，一半在"留下批的理由"。**

# 四 · 第二幕：这笔钱打算怎么花

计划批下来了，只解决了"要不要买"。现在要解决"**怎么买**"。

这一幕的产物叫**采办方案**（有的地方叫采购方案），**它是整个招采平台最核心的一份单据**。

**👤 你现在是**：采购员（还是那个人，不用换账号）
**🖥 打开**：企业端 → **采购寻源** → **采购方案编制**

---

## 4.1 方案里要定什么

打开页面你会看到一堆字段，别慌，**本质上只在回答五个问题**：

| 问题 | 页面上对应什么 |
|---|---|
| **① 买什么** | 从已批准的计划里勾物料（可以跨多条计划一起勾）|
| **② 用哪种买法** | 采办方式：招标 / 询价 / 竞争性谈判 / 竞争性磋商 / 单一来源 / 竞价 / 资格预审 |
| **③ 拆成几笔** | 标段划分 |
| **④ 怎么算谁赢** | 评分模板 |
| **⑤ 时间和钱的边界** | 报名截止时间、报价有效期、控制金额（上限）|

---

## 4.2 六种买法，用生活场景理解

这是产品新人最需要建立的直觉。**别背定义，记场景**：

| 买法 | 生活里的样子 | 什么时候用 | 最少要几家来 **【实测】** |
|---|---|---|---:|
| **招标** | **公开摆摊招人来投**，一次性密封报价，当众开标 | 金额大、要求明确、市场上供应商多 | **3 家** |
| **询价（询比价）** | **打电话问三家，谁便宜要谁** | 标准品、金额中等、不需要复杂技术评审 | **3 家** |
| **竞争性谈判** | **边谈边压价，可以来回几轮** | 需求比较明确，但价格要谈 | **2 家** |
| **竞争性磋商** | 谈判 + **允许对方调整方案** | 需求还不完全清楚，要一起把方案磨出来 | **2 家** |
| **单一来源** | **只有这一家能供**（独家专利、原厂配件、唯一授权）| 别无选择 | **1 家** |
| **竞价** | **在线拍卖，价格往下压** | 标准品、拼价格 | **3 家** |
| **资格预审** | **先审资格，合格的才让投** | 项目复杂，想先筛掉不够格的 | **3 家** |

### ⭐ "最少几家"这条规则是硬的，不是建议

**【实测】** 系统里有个定时任务在盯着：到了截止时间，**有效供应商不够这个数，这个标自动作废**，
提示语是"**有效报价供应商不满足 3 家！**"——这在业务上叫**流标**。

> 🤔 **【我的推断】为什么招标非要三家？**
>
> 因为**两家不叫竞争，叫商量**。两家很容易私下说好"这次你中、下次我中"，
> 三家开始，串通的协调成本就明显上升了。
> 这也是国内招投标的通行下限（法规层面对投标人数量有明确要求）。
>
> **单一来源为什么是 1 家？** 因为它本来就只有一家——但代价是：
> **单一来源必须先公示"我打算只找这一家"，接受别人质疑**。
> **【我的推断】这是一个很精巧的平衡**：既然没法用竞争约束你，那就用**公开**约束你。
> 谁要是拿"单一来源"当后门用，公示期一挂出去就有人跳出来说"我也能供"。

> ⚠️ **新人常见误解**："流标"和"废标"不是一回事。
> **流标** = 整个标没招成（来的人不够、都不合格），要重新招。
> **废标** = 某一家供应商的投标被判无效（材料不全、报价超上限、有串标嫌疑），别人还继续。

## 4.3 标段：为什么要把一个项目切开

**页面上**：编方案时可以把物料分成标段 1、标段 2、标段 3。

**举个真实例子** **【实测，系统里的一条真实数据】**：

```
某水泥公司的钢材采购方案
   ├── 标段 1 ── 方钢 32 吨、方钢 54 吨
   ├── 标段 2 ── 钢坯 32 吨、镀锌方钢管 4 吨、镀锌方钢管 54 吨
   └── 标段 3 ── 圆钢 54 吨、圆钢 78 吨、圆钢 98 吨
```

### 🤔 为什么不一次性招给一家，多省事？

**【我的推断】** 三个理由，从技术到政治：

**① 专业不同。** 做钢坯的厂和做圆钢的厂不一定是同一批。
**捆在一起招，等于逼所有人都去凑不擅长的品类，最后要么没人投，要么让中间商转手赚一道。**

**② 分散风险。** 一家供应商出问题（停产、资金链断），不至于三个标段全瘫。

**③ 保持长期竞争。** 这条最重要，也最容易被忽略。
**三个标段可以有三家中标，明年招标时它们互相是对手。**
如果每次都给一家，两年之后市场上只剩这一家愿意伺候你——**你就被绑架了。**

> 💡 **产品视角的提醒**：本次规划里有一项叫"**分标段独立启停、终止**"（工作量不小）。
> 理解了上面这段你就知道它为什么值钱：**现在三个标段是绑在一起走流程的，
> 一个标段出问题（比如只来了两家要流标），可能拖累另外两个已经谈好的标段。**
> 业务方要的就是"**坏一个别连累其他**"。

---

## 4.4 评分模板：整个流程里最该较真的地方

**页面上**：编方案时要选或配一个评分模板——技术分怎么打、商务分怎么打、各占多少权重。

### 🤔 为什么评分规则必须在"发公告之前"就定死？

**这是整套系统里最重要的一条设计原则，没有之一。**

**【我的推断】** 因为**规则一旦可以事后定，整个招标就是假的**。

设想一下：如果先收报价、再定规则，会发生什么？
采购员看到 A 家便宜但技术一般、B 家贵但技术好——他想要谁就把谁的权重调高。
**这时候"招标"就退化成了"我早就想好给谁，走个形式"。**

所以规则必须**先公开、后收标**。这个顺序不能反。

> **一句话记住**：**评分模板是这场游戏的规则书，规则书必须在开赛前发给所有人。**
> 你以后看到任何涉及评分的需求，第一个要问的是："**这个改动会不会让规则能在收到报价之后再动？**"
> 如果会，那就是原则性问题。

---

## 4.5 方案审批

**👤 换人**：采购业务负责人 / 采购主管经理
**🖥 打开**：企业端 → **审批待办** → **采购方案审批**

**【实测】** 这里有**两级**审批权限（一级、二级）。
**【我的推断】** 大概率是**按金额分级**——小额到主管经理为止，大额要到业务负责人。
金额线在哪、谁批多少，是配置出来的，不是写死的，所以**改起来不用改系统**。

# 五 · 第三幕：挂出去

方案批了，现在要昭告天下。

**👤 你是**：采购员
**🖥 打开**：企业端 → **采购寻源** → **招标管理**（选了询价就是"询价管理"，各种买法各有入口）
**👀 你要做的**：把方案转成一个正式的**寻源单**，编招标文件，点发布。

> 🔑 **这是一个重要的分界点。**
> 在此之前，一切都还在"计划怎么买"；从这一刻起，**这笔生意真的开始了**，
> 外面的供应商能看到它了，**你再想改就要走公告流程、要付代价。**

## 5.1 公告一共有八种，每一种都有它存在的理由

**【实测】** 系统里的公告类型：

| 公告 | 什么时候发 | 🤔 为什么需要它 **【我的推断】** |
|---|---|---|
| **招采公告** | 一开始 | 昭告"有这笔生意，谁想做来投" |
| **邀请函** | 定向邀请时 | 有些项目不宜公开，定向发给几家合格供应商 |
| **延期公告** | 报名/投标截止时间往后推 | 报名的人太少、或供应商反映时间不够 |
| **澄清公告** | 招标文件写错了或有歧义 | 补充说明，**必须让所有人同时知道** |
| **结果公告** | 定标之后 | 公示中标结果 |
| **单一来源公示** | 走单一来源时 | "我打算只找这一家"，接受质疑 |
| **终止公告** | 中途不招了 | 预算取消、需求变了 |
| **流标公告** | 没招成 | 来的人不够或都不合格 |

### ⭐ 注意：延期、澄清、终止这三种，每一种都要单独走审批

**【实测】** 系统里有独立的"延期公告审批""澄清公告审批""终止公告审批"三个入口。

> 🤔 **【我的推断】为什么这三个要格外严？**
>
> 因为**它们都能被用来操纵结果**：
>
> - **延期**改变了游戏规则。有人已经在赶工，有人还没准备好——**延一次，输赢就可能换个人。**
>   现实中的经典操作：自己人还没准备好，就找理由延期。
> - **澄清**可能实质性修改招标要求。表面是"解释一下"，实际是"把门槛改成只有某家能过"。
> - **终止**直接取消了所有人的机会。**最常见的滥用是"发现要中标的不是自己想要的那家，干脆废掉重来"。**
>
> **这三件事都是"看起来是程序操作，实际是结果操作"。所以每一件都要单独批、单独留痕。**

> 💡 **一个可以推广的判断法**：
> 在这套系统里，**凡是"人可以自由选择"的地方，去找找是不是有一道审批。**
> 你会发现这条规律的命中率高得惊人。后面开标、评标那两章还会反复看到。

# 六 · 第四幕：供应商那边在经历什么

现在切换视角。**同一件事，从外面看是什么样。**

---

## 6.1 门槛：入网 和 入围，两道不是一道

新人最容易混的两个词。

### 入网 = 进小区大门

供应商第一次来，要提交营业执照、资质证书、财务报表、银行信息……
**我们这边有人审，通过了他才算"平台供应商"。**
**这一道审的是"你这家公司是不是真的、干不干净"。**

**页面**：供应商端 → 用户中心 → **入网申请**；我们这边 企业端 → 审批待办 → **供应商入网审批**

### 入围 = 拿到某栋楼的门禁卡

入了网不代表什么都能卖。想参与"钢材"类的采购，得单独申请"入围"钢材品类，
证明你确实做这个、有业绩、有资质。
**这一道审的是"你有没有能力干这一类活"。**

**页面**：企业端 → 审批待办 → **供应商入围审批**；入围通过的会进入"**公司统一入围供应商目录**"

### 🤔 为什么要分两道？合成一道不行吗？

**【我的推断】**

**① 审的是两件不同的事，标准也不同。** 身份审核（营业执照真不真）是**一次性**的；
能力审核（能不能做钢材）是**按品类**的，一家公司可能能做钢材不能做电缆。
合成一道，就变成"审一次管所有品类"——**风险在于他会去投他根本不擅长的标。**

**② 分开之后可以复用。** 入网审一次，以后扩品类只审增量，供应商体验好很多。

**③ 责任可以分给不同的人。** 身份审核归供应商管理岗，能力审核往往要业务部门参与。

> 💡 **本次规划里有一项"一次入网服务多个二级集团"**——现在的问题是：
> 同一家供应商想服务水泥集团和地产集团，**可能要各入一次网**。
> 业务方受不了了，要求"入一次，全集团通用"。
> **理解了"入网审身份、入围审能力"，你就知道这个改动的边界在哪：
> 身份可以全集团共用，能力（入围）恐怕还得各自把关。** —— 这一点值得和产品确认。

---

## 6.2 报名、买标书、交保证金

**👤 你现在是**：供应商的业务员
**🖥 打开**：供应商端 → **投标管理**
**👀 你会看到**：能参与的公告列表，点进去报名。

然后是两笔钱：

| 钱 | 是什么 | 退不退 |
|---|---|---|
| **标书费** | 买招标文件的钱，几百到几千 | **一般不退** |
| **投标保证金** | 押金，证明你是认真的，通常是项目金额的百分之几 | **要退** |

### 🤔 为什么要收保证金？收了还要还，图什么？

**【我的推断】** 图的不是钱，是**"承诺成本"**。

没有保证金会发生什么？**投标变成零成本行为**。
供应商可以随便乱投——反正中了再说，中了不想干就跑。
**结果是采购方辛辛苦苦走完全套流程，中标人一句"我不做了"，全部白干，还得重招。**

**保证金的作用是：让"我认真的"这句话变得可验证。** 你交了钱，说明你真打算干。
中标后放鸽子，这笔钱就没了。

> 💡 **本次规划里的"保证金线上自动退费"，业务痛点在这里**：
> **【实测】** 现在系统里有一个状态叫"**线下处理**"——意思是这笔保证金没走系统，是财务手工退的。
>
> 🤔 **【我的推断】这个状态的存在本身就说明问题**：
> 它是当初为了"系统处理不了的情况"留的逃生舱。
> **但只要有逃生舱，人就会走逃生舱**——久而久之大量保证金都走了线下，
> 供应商追着问"我的钱什么时候退"，财务对不上账，采购员天天被催。
>
> **所以这个需求的本质不是"做个自动退款功能"，是"把逃生舱堵上"。**
> 这类"兜底状态变成主路径"的现象，在企业系统里非常常见，**看到就要警惕——它往往是下一个需求的来源。**

---

供应商上传投标文件。通常分两部分：

- **技术标**：我的方案、我的资质、我做过什么类似项目
- **商务标**：我报多少钱、付款条件、交货期

**这两份是分开封的**，为什么分开，下一章讲。

# 七 · 第五幕：开标

到点了。

---

## 7.1 开标大厅

**页面上**：系统里有个"开标大厅"，到了开标时间，所有投标人在线，当众解密各自的投标文件。

### 🤔 为什么非要"到点才能解密"？提前看看会怎样？

**【我的推断】** 这是整个招投标制度的**技术基石**。

如果采购方能提前看到报价，会发生什么？
**他可以把 A 家的报价透露给关系户 B，B 只要报低一块钱就能赢。**
—— 这叫"泄标"，是招投标里最严重的舞弊之一。

所以投标文件必须**加密提交、到点统一解密、全程有记录**。
**"到点"这两个字不是流程规定，是防作弊的核心机制。**

> **【实测】** 系统还会记录每个投标人在开标过程中的在线状态，
> 并且有一个专门的状态叫"**违规**"。
> **【我的推断】** 说明系统在检测异常行为——比如同一台电脑登了两家供应商的账号，
> 或者同一个 IP 同时在给两家操作。**这些线索后面评标时会用上。**

---

## 7.2 强制揭示：一个很能说明问题的设计

**场景**：到点了，有一家投标人没上线，文件解不开，开标卡住了。

**系统的解法**：采购方可以申请"**强制揭示**"——强行解密这家的文件。
**但是这个动作必须走审批。**

> 🤔 **【我的推断】为什么一个"技术操作"要走审批？**
>
> 因为它**在打开别人的密封文件**。这在物理世界里等同于"当众拆别人的信"。
> 虽然业务上确实需要（不然一个人不来就能瘫痪整个招标），
> **但这个权力太大，必须有人签字背书。**
>
> 这就是我在第五章说的那条规律的又一次印证：
> **凡是"人可以自由选择"的地方，必有一道审批。**

---

## 7.3 监标人：一个容易被忽略的角色

**【实测】** 系统里有"监标人列表""设置监标人""监标任务"这几个页面，
而且监标人有个状态叫"**需补选**"——说明**某些项目必须凑齐监标人才能往下走**。

### 🤔 监标人是干什么的？他不打分也不决策

**【我的推断】** 他的价值恰恰在于"**什么都不干**"。

采购员是利益相关方，专家是被采购员抽来的——**这个房间里全是局内人**。
监标人是唯一的**局外人**：他不参与任何决定，只负责"在场"和"留痕"。

**这在治理上叫"第三方见证"。** 它防的不是某个具体的作弊手法，
而是**"大家都是自己人，那就好说话"这种氛围本身**。

# 八 · 第六幕：评标

**这一章是整套系统最敏感的地方，也是本次规划里改动最密集的地方。**
如果你只有时间读一章，读这一章。

---

## 8.1 先抽专家

**👤 你是**：采购员
**🖥 打开**：企业端 → **专家|监标人管理** → **专家抽取**
**👀 你要选**：需要什么专业、从哪个范围抽（本企业 / 区域 / 外部）、抽几个。

**【实测】** 专家是**分专业的**，而且专业名一看就是水泥行业的：
高低压电气、自动化仪表、烧成、粉磨、矿山、环境能源、质检、机械、发电、经济、法务与审计……

### ⭐ 抽取方式有两种，待遇完全不同

| 方式 | 要不要审批 **【实测】** |
|---|---|
| **随机抽取** | **不要** |
| **指定专家** | **要，而且有专门的"专家抽取审批"入口** |

### 🤔 这个差别是整套系统的价值观缩影

**【我的推断】**

**"随机"本身就是一种防腐设计。** 机器抽的，谁也操纵不了，所以不需要额外监督。

**一旦人可以挑，就出现了寻租空间**——挑一个跟某家供应商有交情的专家，
不需要明说什么，评标结果自然就有了倾向。

所以系统的态度是：**能随机就随机；你非要挑，可以，但必须有人批准，并且永久留痕。**

> 💡 **这条规律你可以拿去当"预测器"用**：
> 以后看到任何一个功能，问自己"这里人能不能自由选择？"
> 如果能，去找找有没有配套的审批。**找不到的话，那可能就是个待补的缺口。**

---

## 8.2 技术标和商务标，为什么要分开评

**页面上**：专家登录专家端 → **评审响应**（接受邀请）→ **项目评审**（打分）。

打分是按评分模板一项一项打的。而**本次规划有一项重要改动：分阶段评标**——
先评技术标，技术不过关的直接淘汰，**根本不看他的报价**。

### 🤔 为什么要费这个事？一起看不是更快？

**【我的推断】** 因为**人一旦看到价格，技术判断就回不去了**。

这是有心理学依据的：你先看到 A 家报 100 万、B 家报 120 万，
再去评技术方案时，你会不自觉地为便宜的那家找理由。
**这不是道德问题，是认知问题——专家自己都察觉不到。**

所以正规的做法是：**技术评审阶段，专家根本不知道谁报了多少钱。**
技术过关的名单定下来、锁死，才拆商务标。

> **一句话记住**：**分阶段评标不是为了流程好看，是为了让技术评审的结论"干净"。**

---

## 8.3 评委匿名化

**本次规划的另一项改动**：评委之间只显示"专家 1 号""专家 2 号"，互相不知道对方是谁。

### 🤔 专家们坐在一个房间里，还匿什么名？

**【我的推断】** 匿名要防的不是"认不认识"，是**"权威压制"**。

评标组里如果有一位是行业里德高望重的老专家，或者是某个人的领导——
他一开口说"我觉得 A 家更好"，**其他人的分数会不自觉地向他靠拢**。
这叫"锚定效应"，在群体决策里几乎必然发生。

**匿名化 + 独立打分 + 分数汇总**，是为了让每个人的判断**尽可能独立**。
独立的五个判断加起来，才比一个人的判断更可靠。**否则五个人只是一个人的回声。**

> 💡 **同一逻辑还解释了另一个需求**："汇总得分与评分表顺序一致、按序排序"。
> 听起来是个格式问题，其实是**防止顺序暗示**——
> 如果汇总表默认按分数从高到低排，评委看第二轮时就会被第一轮的排名影响。

---

## 8.4 围串标检测：AI 要来干的活

**本次规划有一个"供应商围串标审核智能体"**，检测手段包括：

- 几家投标单位的**法人/授权人是不是同一个人**
- **股权有没有关联**（互相持股、同一个实际控制人）
- 投标文件的 **Office 文档编辑者是不是同一个人**
- **上传电脑的硬件特征是否重合**
- **文件内容雷同度**

### 🤔 这些手段听起来很"黑客"，其实全是行业成熟套路

**【我的推断】** 围串标的本质是"**几家假装竞争，实际是一伙的**"。
既然是一伙的，就一定会留下痕迹——因为**造三份互不相同的投标文件，成本比想象中高**。

现实中最常见的破绽就是"图省事"：
同一个人做了三家的标书，只改了公司名和报价；三份文件在同一台电脑上传；
文档属性里的作者是同一个。**这些都是真实案例里反复出现的。**

> ⚠️ **产品视角的重要提醒**：
> "检测上传电脑的硬件特征"这条，**在纯网页环境下技术上是拿不到的**（浏览器出于安全限制不允许）。
> 要实现只有两条路：**让供应商装一个客户端控件**，或者**换成别的能拿到的指纹**（IP、浏览器指纹、设备标识）。
> **这是产品要拍的板，而且两条路的成本差很多。建议早点提出来。**

---

# 九 · 第七幕：定标与公示

评分出来了，排名有了。但**排第一不等于中标**。

---

## 9.1 定标方案

**👤 你是**：采购员
**做什么**：根据评标结果编一份"定标方案"——谁中标、中哪个标段、多少钱、为什么是他。

**👤 换人**：有定标审批权限的领导
**🖥 打开**：企业端 → **审批待办** → **定标方案审批**

### 🤔 为什么评标分数出来了，还要再审一道？

**【我的推断】** 因为**评分只是"技术判断"，定标是"商业决策"**。

分数最高的那家，可能：产能排不开、财务状况刚出问题、上一个项目刚出过质量事故。
**这些信息评标专家不一定知道，但采购方知道。**

所以系统的设计是：**专家给出排序，但决定权在采购方，而采购方必须书面说明理由并接受审批。**

> **这里有个平衡**：如果完全按分数走，等于把决定权外包给了临时请来的专家；
> 如果完全由采购方定，那评标就白评了。
> **"专家排序 + 采购方决策 + 逐级审批 + 结果公示"这个组合，是在两者之间找平衡。**

> 💡 **本次规划有一项"发布中标公示按评分排名自动填充"**——
> 它想解决的就是人工誊抄排名容易出错。**看起来很小，但公示写错名字是要出事的。**

---

## 9.2 公示：这笔采购"算数"的时刻

**做什么**：把"谁中标、多少钱"挂出去，晾几天，接受质疑。

### ⭐ 这是整个流程里最重要的一个时间点

**【实测】** 集团所有的采购统计——一年买了多少、集采率多少、各二级集团排名——
**用的都是"公示时间"这个时间点。**

### 🤔 为什么不用签合同、不用付款、不用收货？

**【我的推断】**

**① 公示是唯一"确定的、公开的、单一"的时点。**
合同可能拖三个月才签，付款可能分期跨年，收货可能延期——**只有公示是钉死的**。

**② 和考核周期对得上。** 集团问"今年做了多少集中采购"，
要的是"**今年定下来多少**"，不是"今年付了多少钱"。

**③ 公示是法律意义上的落地。** 公示期一过没人质疑，这件事就不可翻案了。

> 🔑 **给产品新人的忠告**：**只要涉及"钱的统计口径"，先问"按哪个时间点算"。**
> 这套系统里所有的报表分歧，八成出在时间口径上。

---

## 9.3 质疑与澄清

公示期内，落标的供应商可以提出质疑："凭什么是他？"
采购方必须答复。**这是供应商唯一的救济渠道。**

> **【我的推断】** 有质疑渠道，公示才有意义。
> 否则公示就只是"通知"，不是"接受监督"。

# 十 · 第八幕：收尾

| 环节 | 发生什么 |
|---|---|
| **发中标通知书** | 正式通知中标人，对方要回执确认 |
| **签合同** | 进入合同模块 |
| **下单 / 履约** | 供货、验收 |
| **退保证金** | 没中标的原路退回；中标的转履约保证金或退回 |
| **付款 / 开票** | 结算 |

### 关于退保证金的一个细节

**本次规划要求"校验退费账户与原缴费账户一致性"。**

> 🤔 **【我的推断】这一句话背后是一类真实的资金风险。**
> 供应商可能在这几个月里改了银行账户信息——如果不校验，**钱就退到新账户去了**。
> 万一那个新账户是被人改过的，就是一起资金事故。
> **"原路退回"这四个字是财务和审计的红线。**

# 十一 · 横切线：供应商的一生

前面讲的是"一笔采购"的一生。这一节讲"一个供应商"的一生——**它和主流程是平行跑的**。

```
注册 → 入网申请 → 入网审核 → 成为平台供应商
                                   │
        ┌──────────────────────────┼─────────────────┐
        ▼                          ▼                 ▼
   入围某品类              参与招标/供货        扩充产品目录
        │                          │
        ▼                          ▼
   进入入围目录            履约评价打分 → 分级评定
                                   │
                                   ▼
                        不良行为记录 → 冻结 / 拉黑 → 整改 → 解冻
                                   │
                                   ▼
                              年度审核（年审）
```

**页面**：企业端 → **供应商管理**（信息管理、评价模板、评价任务、在线评分、等级查看、冻结、拉黑、黑名单）

## 几个值得理解的设计

### 冻结 vs 拉黑

**【我的推断】** 冻结是"暂停营业"（有问题，先停下来整改，改好了能恢复）；
拉黑是"吊销执照"（严重违规，长期不合作）。
**分两档是因为绝大多数问题不至于判死刑**——一刀切拉黑，最后没人敢管，规则形同虚设。

### 拉黑有"系统自动"和"接口同步"两种来源 **【实测】**

除了人工拉黑，还有系统自动触发的，以及从外部名单同步进来的。

> 🤔 **【我的推断】** 自动拉黑对应的是"触发了明确规则"（比如中标后弃标、连续评价不合格）——
> **规则明确的事情就不该让人来判断，因为人会讲情面。**
> 接口同步对应的是"国家失信名单、集团黑名单"——**外部权威说了不行，我们没有裁量空间。**

### 本次规划里的"黑名单管控强化"

要求：**黑名单状态的供应商不能修改基础信息。**

> 🤔 **【我的推断】这一条一看就是被现实教育过的。**
> 被拉黑的公司改个名字、换个法人，摇身一变又能入网了——**这叫"换马甲"，是黑名单制度最大的漏洞。**
> 锁死基础信息修改，就是堵这个洞。
> **这类需求通常都很小，但价值极高，因为它们都是血的教训。**

# 十二 · 另一个世界：云采商城

到这里，招采平台讲完了。**但集团还有另一套东西，叫云采商城。**

---

## 12.1 它长什么样

**像企业版的京东。** 搜索、看商品、加购物车、下单、等收货、对账开票。

---

## 12.2 🤔 为什么不都走招标？规矩不是更严吗？

**【我的推断】 因为流程是有成本的。**

买 20 个订书机，走一遍"发公告→报名→开标→评标→定标→公示"，
**光是走流程的人力成本就远超货值**，还要占用专家资源。

所以集团的策略是分层：

| | 招采平台 | 云采商城 |
|---|---|---|
| 买什么 | 金额大、非标、要谈的 | 金额小、标准品、随时要的 |
| 一次交易耗时 | 几周到几个月 | 几分钟 |
| 靠什么保证不出事 | **流程**（竞争 + 审批 + 公示）| **价格透明**（多渠道比价）+ 事后对账 |

---

## 12.3 一个可能颠覆你认知的事实

**【实测】** 云采商城**自己不备货**。它的商品来自 **九个渠道**：
自有框架协议供应商、**京东**、京东福利、**震坤行**、**鑫方盛**、**欧菲斯**、**西域**、**得力**、内部协同。

> 🔑 **这一条彻底改变了对商城需求的理解：**
> - **"搜索权重优化"不是在优化自家几千个商品的排序，是要在混了京东、震坤行、西域的商品池里排序。**
> - **"一键批量比价"比的是同一个东西在京东卖多少、震坤行卖多少、自有框架卖多少。**
> - **"同品类低价识别·全网最低"里的"全网"，指的就是这九个渠道。**
>
> 🤔 **【我的推断】商城的定位其实是**："一个带审批和对账的企业版比价下单入口"。
> 它的价值不在于自己有多少货，而在于**把员工的零星采购收拢到一个能管、能比价、能对账的口子里**。
>
> 这也解释了商城那一堆需求的共同主题：搜索准不准、比价方不方便、目录管不管得住、对账顺不顺——
> **全是"怎么让员工少花钱、财务少费事"，没有一条是"怎么招标"。**

---

## 12.4 招采和商城的接头处

两个世界有两个连接点，值得记住：

1. **合同推送商城**：招采这边招出来的框架协议供应商，把合同推到商城，员工就能直接下单了。
2. **商品上架需求 → 归集寻源**（本次规划新增）：员工在商城搜不到想要的东西，可以提报需求，
   系统汇总之后**回到招采平台去寻源**。
   > **【我的推断】这一条很有意思，它把两个系统串成了闭环**：
   > 商城暴露需求 → 招采解决供给 → 供给回到商城。

# 十三 · 十二个"为什么"

把前面散落的设计逻辑集中回答一遍。**这一节最适合拿去和业务方对答案。**
以下全部是 **【我的推断】**。

**1. 为什么审批环节这么多？**
因为采购是"花别人的钱办别人的事"，天然缺乏节约动机和责任约束。审批是补上这两样的手段。

**2. 为什么编制和审批必须是不同的人？**
"自己批自己"是所有采购舞弊的起点。这是内控第一条铁律，系统层面焊死比制度约束可靠得多。

**3. 为什么审批权限被切得那么碎？**
审批权是风险权，必须能单独授予且不夹带。而"干活"的权限可以很大——干活不产生风险，批准才产生。

**4. 为什么招标至少要三家？**
两家不叫竞争，叫商量。三家开始，串通的协调成本明显上升。

**5. 为什么评分规则必须在收标前定死？**
规则能事后定，招标就是假的。这是原则问题，不是流程问题。

**6. 为什么随机抽专家不用审批，指定专家要审批？**
随机本身就是防腐机制；能挑人就有寻租空间。这条规律在系统里到处都是。

**7. 为什么技术标和商务标要分开评？**
人看到价格后，技术判断会被污染，而且当事人无法自察。

**8. 为什么评委要匿名？**
防的不是"认不认识"，是权威压制导致的意见趋同。五个独立判断才比一个判断可靠。

**9. 为什么统计口径用公示时间？**
它是唯一确定、公开、单一的时点，且对得上考核周期。

**10. 为什么小额采购不走招标？**
流程有成本。20 块钱的东西走 2000 块钱的流程，本身就是浪费。

**11. 为什么切换公司之后菜单全变了？**
因为"岗位"是挂在公司上的。切公司 = 声明"我现在以哪个身份操作"，每次操作都有明确身份归属。

**12. 为什么系统里有那么多"兜底状态"（比如保证金的"线下处理"）？**
因为现实总有系统处理不了的情况。**但兜底一旦存在就会被滥用，最后变成主路径。**
这类状态往往就是下一轮需求的来源——**看到就要警惕。**

# 十五 · 附录 B：黑话词典

| 词 | 说人话 |
|---|---|
| **寻源** | "找供应商买东西"这整件事的统称 |
| **采办方案 / 采购方案** | 采购的正式计划书：买什么、怎么招、怎么评分。**招采平台最核心的单据** |
| **标段** | 把一个项目切成几块分别招，可以分别给不同供应商 |
| **技术标 / 商务标** | 技术标看方案资质业绩；商务标看价格和条款 |
| **流标** | **整个标**没招成（人不够、都不合格），要重招 |
| **废标** | **某一家**的投标被判无效，其他人继续 |
| **围标 / 串标** | 几家供应商私下串通，轮流中标、故意抬价。采购领域最严重的违规 |
| **入网** | 供应商注册进平台，审的是"你这家公司真不真、干不干净" |
| **入围** | 通过某品类的能力审核，审的是"你能不能干这一类活" |
| **年审** | 每年重新审一遍供应商资质还有没有效 |
| **保证金 / 标书费** | 保证金=投标押金（要退）；标书费=买招标文件的钱（一般不退）|
| **限价 / 控制价** | 采购方设的价格上限，超过直接废标 |
| **公示** | 把中标结果挂出去晾几天接受质疑。**统计口径里最关键的时间点** |
| **质疑澄清** | 供应商对结果有异议提出来，采购方必须答复 |
| **监标人** | 全程在场的第三方见证者，不打分不决策 |
| **强制揭示** | 投标人不上线时，强行解密其文件的动作，**必须审批** |
| **二级集团 / 板块** | 集团下面的水泥集团、地产集团、新材集团这一层 |
| **集中采购（集采）** | 把多家企业的同类需求合并起来统一采购，为了压价和管控 |
| **框架协议** | 先谈好价格和条款，之后按需下单，不用每次重新招 |
| **SRM** | 供应商关系管理，就是"供应商管理"那一整套 |
| **驾驶舱** | 领导看的大屏看板 |

# 最后：三句话带走

1. **这套系统不是"买东西的工具"，是"证明我们买得干净、算得清的工具"。**
   看到觉得多此一举的步骤，先问"它在防什么、在留什么证据"。

2. **凡是"人可以自由选择"的地方，必有一道审批。**
   这条规律在这套系统里命中率极高，可以拿来预测功能设计，也可以拿来发现缺口。

3. **规则必须先于报价存在。**
   评分模板要在发公告前定死，这是招投标的根本原则。任何可能让规则"事后可调"的改动，都是原则性问题。
