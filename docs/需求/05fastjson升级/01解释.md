1.x 的 toJavaObject 在遇到 JSONObject → Map 时，根本不走"写字再读字"这一步。它内部检查了一下：
// fastjson 1.x 内部大致逻辑：
如果源是 JSONObject，目标是 Map → 直接引用拷贝，Date 还是 Date
如果源是 String，目标是 Map → 才会序列化+反序列化

2.x 重写了这个逻辑，统一先序列化：
// fastjson 2.x 内部大致逻辑：
不管源是什么 → 先序列化成 JSON 字符串 → 再反序列化成目标类型
所以同一个方法名 toJavaObject，1.x 对 JSONObject → Map 是浅拷贝，2.x 变成了先写字再读字。Date 就在这个"写字"环节丢了。
