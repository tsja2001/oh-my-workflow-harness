# Fastjson2 2.0.62 安全漏洞（RCE）· 当前项目处置方案

> 日期：2026-07-28 ｜ 工具：cc
> 状态：已核实漏洞与项目暴露面；**官方补丁版本尚未发布**，方案为"先缓解、后升级"；缓解措施尚未实施，等拍板。
> 一句话：你们在的 fastjson2 **2.0.62 确认有 RCE 漏洞**，官方还没出修复版本，**当前先开 SafeMode 缓解**（你们不用 AutoType，几乎零副作用），**待官方发版再升级**。

## 1. 结论先行

1. **2.0.62 中招**：官方确认 Maven 最新版就是 2.0.62（2026-05-05），仍含此漏洞。你们正在用。
2. **暂无版本可升**：修复 PR `#7695` 未合并主干；官方补丁版本截至 2026-07-27 **尚未发布**。所以"升级到修复版"这条路**现在还没目标版本**。
3. **正解 = 先缓解 + 后升级**：
   - **立刻**：开 `SafeMode`（JVM 参数，运维改，不用改代码/不用重新编译）+ WAF 拦 `@type`。
   - **后续**：盯官方发版，出了修复版再改 parent 一处版本号升级。
4. **你们开 SafeMode 几乎零副作用**：代码扫描确认业务不用 AutoType、不依赖 `@type` 多态，SafeMode 只焊死攻击路径，不打断业务。

## 2. 两个漏洞别搞混

2026 年 7 月同时有两个 fastjson 漏洞在传，容易混：

| | 漏洞 A | 漏洞 B（本文处理的） |
|---|---|---|
| 影响范围 | **fastjson 1.x**（1.2.68–1.2.83） | **fastjson2 ≤ 2.0.62** |
| 你们的关系 | 当初升级到 2.x 就是为躲它 | 升到 2.x 后，2.x 自己又爆的 |
| 官方对策 | 1.x 不修，迁 fastjson2 | 有修复 PR，但**未发版** |
| 现状 | 已解决（已升 2.x）✅ | **待处置** 🔴 |

> 注意：网上"fastjson2 不受影响"的说法是针对**漏洞 A** 讲的（2.x 没有 1.x 那个老毛病），**不等于 2.x 没有漏洞 B**。

## 3. 漏洞本身（给技术领导）

- **类型**：远程代码执行（RCE），全 JDK 通杀，无需认证、无需已知危险类、默认配置即可触发，危害高。
- **成因**：2.x 在"AutoType 已禁用"的校验分支里，用输入串的增量 FNV-1a 哈希去比对默认接受哈希，**命中后没有再核对实际文本是否等于白名单类名**。攻击者可对任意前缀做 FNV chosen-prefix 碰撞，把 URL 形态字符串塞进上下文类加载器 → 任意代码执行。
- **关键点**：**默认配置就中招**，"我们没开 AutoType"并不能自动免疫——这正是它危险的地方。`SafeMode` 才是真正关掉这条路的开关。
- **利用成熟度**：POC 未公开（但修复复杂度低，窗口期要抓紧）。

## 4. 当前项目暴露面（代码扫描实测）

扫描范围：`01zhaocai-end` 全部 Java 源码 / pom / 配置。

| 查什么 | 结果 | 含义 |
|---|---|---|
| 版本控制点 | `scm-cloud-parent/pom.xml:65` 一处 `<fastjson.version>2.0.62</fastjson.version>` | 全项目统一，升级只改这一处 |
| 用的哪个包 | 全是兼容包 `com.alibaba.fastjson.*`（805 文件），原生 `fastjson2.*` 0 处 | 底层引擎仍是 fastjson2，**照样受影响** |
| 是否配过 SafeMode | ❌ 全项目**没配过** | 缓解开关还没用 |
| 业务是否开 AutoType | ❌ **没有**（无 `setAutoTypeSupport` 等） | 开 SafeMode 不影响业务 |
| 是否依赖 `@type` 多态 | ❌ **没有**（源码 0 处 `"@type"`） | 拦 `@type` / 开 SafeMode 都不打断业务 |
| fastjson 解析调用点 | **752 处** | 用得多，不能排除个别吃外部输入 → 有暴露面，必须缓解 |

**结论**：暴露面真实存在（752 处解析），但因为不用 AutoType/`@type`，**缓解成本极低、风险极小**，该做、值得做。

## 5. 处置方案

### 5.1 【立刻·主力】开 SafeMode —— JVM 启动参数

给**每个 Java 服务**的启动参数加上（运维在 K8s deployment 的 `JAVA_OPTS`/env 里加，**不用改代码、不用重新编译、不用重新打 jar**）：

```
-Dfastjson2.parser.safeMode=true
```

- 作用：彻底禁用 AutoType（含漏洞走的暗道），从根上杜绝此类 RCE。
- 因为你们不用 AutoType/`@type`，业务不受影响。
- **兜底**：你们用的是兼容包，保险起见可**同时**再加一条老包名的开关：`-Dfastjson.parser.safeMode=true`（两条都加，谁生效都行）。
- **验证生效**（缓解上线后必做）：对某个会用 fastjson 解析的接口，发一条带 `@type` 的测试 JSON，确认被拒绝/报"autoType is not support"。只看服务没报错不算数，要看 `@type` 确实被挡。
- **灰度**：先在 **test 环境或一个服务**开、观察半天没异常，再逐步全量，别一次全推。

> 若个别服务加 JVM 参数不方便，可退而在公共启动处用代码开一次全局开关（需重新编译该公共模块）：
> `com.alibaba.fastjson.parser.ParserConfig.getGlobalInstance().setSafeMode(true);`

### 5.2 【立刻·补刀】WAF 拦截 `@type`

由安全/网关团队在 WAF 加规则：**拦截请求体里 key 含 `@type` 的 JSON**。

- 你们业务不用 `@type`，**误杀风险极低**。
- 属于纵深防御，和 SafeMode 双保险；SafeMode 一时铺不全时，它能先挡在门口。

### 5.3 【后续·根治】等官方补丁版本，升级

- 目前**没有已发布的修复版本**（PR #7695 未合并，见 issue #7702）。**不要凭猜升到某个不存在/未验证的版本号。**
- 盯官方发版：fastjson2 Releases 页 / issue #7702 出现修复版本（预计 2.0.63 或更高）后，改 **`scm-cloud-parent/pom.xml:65`** 一处 `<fastjson.version>` 即可，全项目跟随。
- 升级后走正常回归（尤其别再引入类似上次"日期变 String"的兼容问题），SafeMode 可继续保留做纵深防御。

### 5.4 不要做什么

| 别做 | 原因 |
|---|---|
| 退回 fastjson 1.x | 1.x 有更严重且**官方不修**的 RCE（漏洞 A），是往火坑跳 |
| 凭记忆升到某个"修复版本号" | 官方补丁还没发版，随便升可能升到不存在或没修的版本 |
| 只想着"我们没开 AutoType 所以没事" | 此漏洞**默认配置即中招**，不开 AutoType 也不免疫，必须靠 SafeMode |
| 等官方发版再一起弄 | 补丁遥遥无期，窗口期内先用 SafeMode 把洞堵上 |

## 7. 结论

> "我们在的 fastjson2 2.0.62 有个高危 RCE 漏洞，官方修复 PR 还没合并、正式补丁版本没发布，所以暂时没有安全版本可升。当前处置是先缓解、后升级：立刻给所有 Java 服务加 `-Dfastjson2.parser.safeMode=true` 启动参数把 AutoType 彻底禁掉，再让 WAF 拦 `@type` 请求；我扫过代码，我们业务不用 AutoType、不依赖 `@type`，所以开这个开关不影响功能、风险很低。等官方发布修复版本，再改 parent 一处版本号统一升级。"
