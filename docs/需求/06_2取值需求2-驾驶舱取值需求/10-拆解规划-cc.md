# 第一部分：写给你看的

## 1. 这个需求到底是做什么

把“金隅集团集采管理驾驶舱”页面上那些 KPI 数字，从旧的缓存表/硬编码换成从真正的业务数据实时算出来。主要取两个来源：
- 《集采管理业务统计报表》（ES 统一货架 `centralized_procurement_report`）——算金额类指标；
- 《集采业务台账-集采日计划统计台账》——算响应率、完成率、执行率、滞后率。

## 2. 产品需求逐条翻译

| 产品原话 | 大白话翻译 | 谁来做 |
|---|---|---|
| 头部：集采累计总金额、集采计划累计数量 | 2026.1.1 到查询日前一天的集团级集采金额、计划数量 | 后端 |
| 中间：日集采、月度集采、季度集采、年度集采金额 | 不同时间窗口的集采金额，要扣掉非平台录入的机电四大类/煤炭、云采机电四大类 | 后端 |
| 左1：集采类目分项金额 | 煤炭、钢材、润滑油、电线电缆、轴承及备件、办公设备、办公文具 7 个类目的金额 | 后端 |
| 左2：集采计划执行分析 | 响应率、完成率、执行中率、滞后率 | 后端（调用 order 已有接口或读台账） |
| 右下：集采情况分析 | 水泥北分、机电公司、金隅云采 三个口径的金额 | 后端 |
| 上线企业 | “开发手动更新，无需开发” | 无需开发 |

## 6. 你需要知道的背景知识

- **ES 统一货架**：所有集采交易金额最后会进 Elasticsearch 的 `centralized_procurement_report` 索引，字段包括 `bookTime`（公示/下单时间）、`taxTotal`（交易金额）、`dataSource`（FP/YC/MT/JD/ZC）、`isCentralized`、`categoryCode`、`supplierCode`、`buCode`。
- **D1/D2/D3 扣除项**：06 首页为了去重/去噪，算集采额时要扣掉：非平台录入的机电四大类（D1）、非平台录入的水泥集团北分煤炭（D2）、云采平台的机电四大类（D3）。驾驶舱需求中间部分明确写要扣 D1/D2/D3。
- **SourceCollectionData 接口**：老驾驶舱和新门户通用的一种“键值对”返回结构，`typeCode` 决定查哪类数据。06 只改了 `kengk/mt/gc`，剩下 `centerHeader/categoryAmount/situA/doRate` 还是读旧缓存。

1. 开发范围 = 仅本次需求文档中的驾驶舱 KPI；`kengk/mt/gc` 在 06 已交付，本次不动。
2. 新代码贴合 06 首页风格，像素级模仿 `CentralizedProcurementPortalServiceImpl` 的 ES filters + sum 聚合写法。
3. 不硬编码业务枚举；供应商/板块编码用常量并注释来源。
4. 金额返回万元两位小数，比率返回百分比两位小数。

- 后端：`scm-source-source`（路由）、`scm-source-chase`（ES 聚合计算）、`scm-order-report`（日计划率，已存在接口，只需 source 侧调用）。
