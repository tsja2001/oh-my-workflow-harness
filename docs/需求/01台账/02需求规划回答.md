# 集采日金额统计台账任务拆解计划文档

本文档用于把产品需求拆成可执行的开发计划。后续 AI Agent 或开发同事应先按本文档核对分支、环境、数据库和权限资源，再开始改代码。

## 1. 结论先行

本需求不是只改前端页面。它至少包含五类交付：

1. 后端新增“集采日金额统计台账”的数据表、DTO、Controller、Service、Mapper，支持查询、新增、修改、删除、导出。
2. 新增菜单“集采业务管理台账 / 日金额统计台账”，并把菜单、接口资源授权给“集采管理-执行单位集采管理岗”。
3. 新增或配置数据字典：集团集采类目、所属板块。如果已有字典，优先复用，不能在代码里写死中文。
4. 接入组织机构控件：集采执行单位、采购企业从组织机构选择；采购企业变更后自动带出所属板块。
5. 每日 24:00 通过公司已有 XXL Job 体系刷新集采驾驶舱对应数据。

推荐后端落点是 `01zhaocai-end/scm-source-all`，具体放在 `scm-source-source` / `scm-source-source-api`。原因是现有“集采驾驶舱”数据模型和接口已经在这个模块：

- `scm-source-source/src/main/java/com/pcitc/scm/source/source/model/SourceCollection.java`
- `scm-source-source/src/main/java/com/pcitc/scm/source/source/model/SourceCollectionData.java`
- `scm-source-source/src/main/java/com/pcitc/scm/source/source/repositories/SourceCollectionMapper.java`
- `scm-source-source/src/main/java/com/pcitc/scm/source/source/service/impl/SourceCollectionDataServiceImpl.java`
- 驾驶舱查询接口：`SourceQueryController#cockpitCollectionData`，路径 `e/business/source/source/cockpit_collection_data_{typeCode}`

权限和菜单落点是 `01zhaocai-end/scm-ubm-all/scm-ubm-rbac`。菜单、角色、岗位不是纯前端静态路由，主要靠数据库表驱动。

## 3. 开发前必须向同事或领导确认的资源

由于本地无法完整启动公司微服务，不能把“本地启动成功”作为唯一质量门槛。正式开发前建议要齐以下资源：

1. 正确开发分支：尤其确认 `scm-cloud-starters-web` 和前端仓库应该基于哪个分支。
2. 开发环境地址：招采平台前端地址、后端网关地址、Swagger/Knife4j 地址、XXL Job 管理台地址。
3. 测试账号：至少需要一个拥有“集采管理-执行单位集采管理岗”的账号，以及一个无权限账号用于验证菜单和接口权限。
4. 数据库变更流程：新增业务表、菜单、岗位、角色、资源、数据字典、导出模板这些 SQL 应该由谁执行，是否需要 Liquibase/Flyway，是否允许提交 SQL 文件。
5. 组织机构控件字段约定：前端控件返回的是 `orgId/orgCode/orgName` 还是其他字段；后端用哪个字段查询所属板块。
6. 数据字典编码：集团集采类目的字典 `cate`、所属板块字典 `cate` 是否已存在；四大类目编码是否必须沿用现有驾驶舱编码。
7. 驾驶舱刷新口径：新录入的台账金额是只影响“日集采”，还是同时影响月度、季度、年度、类目分项金额、集采情况分析。
8. 删除规则：产品写“删除本行”，技术上建议逻辑删除；需确认是否允许物理删除。
9. 导出方式：普通列表导出可用统一导出注解；如果后续数据量很大，需要走平台异步导出。

本地仍然需要编译。不能完整运行微服务，不代表不用编译。至少要对改动仓库执行模块级 Maven 编译，例如在 `scm-source-all` 下执行相关模块的 `mvn -pl scm-source-source -am test -DskipTests` 或 `mvn -pl scm-source-web-jar -am package -DskipTests`。如果公司 Nexus 或 JDK 环境缺失，需先补齐 JDK 8、Maven 3.6.3 和内网 Nexus 访问。

现有驾驶舱数据主要在 `scm-source-source`：

- 明细表模型：`SourceCollection` 对应 `sc_source_collection`，字段包括类目、采购企业、含税金额、所属板块、拉取日期等。

### 5.2 流水号生成

需求格式：`JCRJE-年月日-三位流水`，如 `JCRJE-20260701-001`。

建议在 `scm-source-source` 新增类似 `SchemeCodeSequence` 的序列类，使用 `GIDService#createId`：

- `getPrefix()` 返回 `JCRJE-`
- `getCenterStr()` 返回统计日期 `yyyyMMdd-`
- `getSuffixLength()` 返回 3
- `getSeqDate()` 建议按统计日期当天重置，而不是按自然年重置

如果现有 `GIDService` 不支持按业务日期重置，需要改成事务内查询当天最大流水号并加数据库唯一约束兜底。这个方案要注意并发：新增时必须在唯一索引冲突后重试，不能只在内存里加一。

- 流水号：`ledgerNo`，模糊或精确需要产品确认，建议模糊。

- `executeUnitCode`、`categoryCode`、`statisticDate`、`purchaseCompanyCode`、`taxAmount` 必填。

- 保存时用字典接口校验类目和所属板块编码存在。

### 5.4 驾驶舱刷新

现有驾驶舱存在两种模式：

1. `collectionShow` 字典开关为 `1` 时，`SourceCollectionDataServiceImpl` 会实时调用 `SourceCollectionMapper` 的汇总 SQL。
2. 否则读取 `sc_collection_data` 表。

因此“每日 24:00 自动取前一日统计日期数据并自动更新集采驾驶舱”不能只写一个定时任务，还要同步调整驾驶舱读取口径。推荐方案：

1. 新增 `CollectionDailyAmountLedgerService#refreshCockpitByStatisticDate(String statisticDate)`。
2. 该方法汇总 `sc_collection_daily_amount_ledger` 中 `delete_sign = 0` 且 `statistic_date = 指定日期` 的数据。
3. 对现有驾驶舱动态 SQL 增加新台账数据的合并口径，至少覆盖四大类目：钢材、电线电缆、润滑剂、轴承及备件。
4. 如果生产环境 `collectionShow` 关闭，则同时 upsert `sc_collection_data` 里的对应数据项。
5. 定时任务只调用上述服务，不直接写 SQL。

需要产品或同事确认的口径：

- 台账金额是否只影响“机电公司四大类目日金额”，还是也参与驾驶舱累计总金额、月度、季度、年度。
- `JCRJE` 台账里的“统计日期”与现有 `sc_source_collection.final_time/pull_date` 的关系。不要把统计日期误当成现有最终完成时间。
- 四大类目编码是否沿用现有驾驶舱 SQL：钢材 `1501`、润滑剂 `1701`、电线电缆 `2302`、轴承及备件 `2502`。
- 机电公司编码是否就是现有 SQL 中的 `CN13000363`。不要硬编码，优先使用执行单位组织编码。

### 5.5 定时任务

`scm-cloud-source` 已引入 `xxl-job-executor-web-jar`，并在 `SourceApp` 导入 `XxljobExecutorWebConfig`。所以推荐使用 XXL Job：

- 新增 Job Handler，例如 `collectionDailyAmountLedgerRefreshJob`。
- 默认无参数时取 `LocalDate.now().minusDays(1)`。
- 支持传参 `yyyy-MM-dd`，便于补跑。
- 调度中心配置 Cron：`0 0 0 * * ?`。
- Job 内打日志：开始日期、汇总条数、汇总金额、upsert 结果、异常堆栈。

不要优先使用 Spring `@Scheduled`，除非确认该服务没有接入 XXL Job 或调度中心不允许新增任务。

2. 静态检查：确认 Controller 入参注解符合导出组件要求，列表方法不要错误混用 `@RequestBody`。
3. SQL 自查：所有查询都带 `delete_sign = 0`，日期范围包含边界，金额字段使用 `BigDecimal`。
4. 并发自查：流水号生成有唯一索引兜底。
5. 权限自查：无权限账号看不到菜单，直接调接口应失败；有岗位账号可查询和操作。
6. 导出自查：导出字段顺序和需求一致，日期和金额格式正确。
7. 驾驶舱自查：手工新增统计日期为 `2026-07-01` 的四大类目数据后，补跑 `2026-07-01` 任务，检查驾驶舱数值变化。

开发环境联调用例：

- 新增一条记录，流水号格式为 `JCRJE-yyyyMMdd-001`，发布时间和创建人正确。
- 同一统计日期连续新增多条，流水号递增到 `002/003`。
- 修改执行单位、类目、统计日期、采购企业、金额、所属板块后，发布时间和操作人更新。
- 删除后列表不可见，导出不可见，驾驶舱刷新不再计入。
- 查询条件单独和组合均有效。
- 导出只导出查询结果，不导出全量无关数据。

## 9. 对后续 AI Agent 的实现要求

1. 先确认分支再改代码，尤其不要在 `scm-ubm-all` 的旧 `dev` 上开发。
2. 改动范围要收敛在 `scm-source-all`、权限 SQL/配置、必要前端仓库；不要顺手重构无关模块。
3. 新增代码要贴合现有风格：MyBatis-Plus Model/Mapper/Service/Controller，`Result.success`，`DefaultPageBean`，`PageList`，`BeanUtils.copyProperties`。
4. 不要硬编码中文枚举。类目、所属板块、执行单位均应存编码和名称，显示用名称，查询用编码。
5. 所属板块以后端组织接口查询结果为准，前端传值只能用于回显。
6. 导出走统一导出组件；如果发现数据量超过普通导出承载，再改异步导出。
7. 定时任务走 XXL Job；不要在没有确认的情况下新增 `@Scheduled`。
8. 所有数据库变更要提供可回滚 SQL 或至少列出回滚方式。
9. 最终提交前必须列出实际改动仓库、分支、编译命令和结果。
