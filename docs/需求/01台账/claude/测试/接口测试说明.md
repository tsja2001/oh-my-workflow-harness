# 集采日金额统计台账 · 接口自测说明（跑通流程用）

> 目标：Jenkins 部署后，用 curl 验证"新增 → 查询 → 详情 → 修改 → 删除"这条链路通了。
> 不需要配菜单权限（平台接口只校验"登录了没"，不校验菜单）。只要用你的 test 账号拿到"登录通行证"（token）即可。

1. 表已建好：`scm_source_test.sc_collection_daily_amount_ledger`（我已经建好，见 `../sql/01_create_ledger_table.sql`）。

## 二、最省事的做法：给我一段"Copy as cURL"，我来生成测试命令

你不用自己拼 curl。回来后按这三步：

1. 浏览器打开并登录 test 前端：`http://10.0.54.16:32740/`（账号 10930002）。
2. 按 F12 打开开发者工具 → 切到 **Network（网络）** 标签，随便点一个已有的招采页面（让它发一个后端请求）。
3. 在 Network 列表里找一条请求路径里带 `source` 的（比如某个 `/e/business/source/...`），**右键 → Copy → Copy as cURL**，把复制到的一大段贴给我。

这段里含有 test 环境的真实网关地址和你的登录 token。我拿到后，会把它改成调用下面这几个新接口的命令，直接发你运行。

## 三、新接口清单（我做的）

所有接口都是 POST。网关前缀以你复制的 cURL 为准（形如 `http://10.0.54.16:xxxxx/gateway/.../e/business/source/...`）。

| 功能 | 路径 | 请求体示例 |
|---|---|---|
| 新增 | `/e/business/source/collectionDailyAmountLedger/add` | 见下方 body-add |
| 查询列表 | `/e/business/source/collectionDailyAmountLedger/queryPageList` | 见下方 body-query |
| 详情 | `/e/business/source/collectionDailyAmountLedger/detail` | `{"ledgerId":"<从查询结果里拿>"}` |
| 修改 | `/e/business/source/collectionDailyAmountLedger/modify` | 在详情 JSON 上改金额等字段回传 |
| 删除 | `/e/business/source/collectionDailyAmountLedger/delete` | `{"ledgerId":"<从查询结果里拿>"}` |

**body-add**（新增一条 2026-07-01 机电公司钢材台账）：
```json
{
  "executeUnitCode": "JDGS",
  "executeUnitName": "机电公司",
  "categoryCode": "1501",
  "categoryName": "钢材",
  "statisticDate": "2026-07-01",
  "purchaseCompanyCode": "TSFGS",
  "purchaseCompanyName": "唐山分公司",
  "taxAmount": 500.00,
  "buCode": "SNJT",
  "buName": "水泥集团"
}
```
预期：返回 `{"code":"...success...","data":"JCRJE-20260708-001"}` 之类，`data` 是自动生成的流水号。

**body-query**（按类目查）：
```json
{"currentPage":1,"limit":10,"model":{"categoryCode":"1501"}}
```
预期：`data.root` 里能查到刚才新增的那条，字段齐全，`ledgerId` 就是详情/修改/删除要用的主键。

## 四、验证要点（链路算通的标准）

1. 新增返回流水号 `JCRJE-年月日-001`；连续新增两条，第二条是 `002`（按天递增）。
2. 查询能查到、字段正确、`createByName` 是你的账号（说明 token 生效、审计字段自动填充）。
3. 详情按 `ledgerId` 能回显。
4. 修改金额后，再查金额已变、`publishTime` 更新。
5. 删除后再查，该条不在列表里（逻辑删除，数据库里还在但 `delete_sign=1`）。
