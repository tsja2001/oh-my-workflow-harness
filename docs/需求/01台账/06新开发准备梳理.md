# 06 新人开会确认版：集采日金额统计台账

这份文档不是给老 Java 开发看的，是给你下午和领导、同事沟通用的。目标只有一个：把“AI 开发前必须问清楚的事”问明白。

你不需要现场讲很多代码细节。你需要讲清楚：这个需求会影响哪些地方、现在不确定的是什么、不确定会导致 AI 不知道怎么开发什么。

## 先把全局讲明白

这次需求看起来是“新增一个台账页面”，但实际牵涉 5 件事：

1. 新增一张业务表：存“某一天、某执行单位、某类目、某采购企业”的交易金额。
2. 新增后台接口：让前端能查询、新增、修改、删除、导出这张表。
3. 新增前端页面入口：菜单、按钮、岗位权限要配好，否则页面看不到、按钮点不了。
4. 影响集采驾驶舱：每天 0 点要把前一天数据更新到驾驶舱。
5. 配置资源：组织机构、类目、所属板块、数据字典、导出模板、测试账号、数据库脚本都要有人确认。

所以当前最大问题不是“代码怎么写”。代码可以交给 AI。

当前最大问题是：公司还没明确“这张新台账和现有驾驶舱数据之间到底是什么关系”。

这句话下午可以直接说：

```text
我现在最需要确认的是：新台账只是一个新增管理页面，还是以后驾驶舱也要以这张新台账作为数据来源。这个不确认，AI 写出来的刷新逻辑可能方向错。
```

## 你要先理解的几个系统概念

### 1. 台账是什么

台账可以理解成“业务明细表”。

这次的“集采日金额统计台账”大概是一行一条记录：

```text
2026-07-01 + 某集采执行单位 + 某集采类目 + 某采购企业 + 金额
```

它不是驾驶舱本身。驾驶舱是展示看板，台账是底层数据之一。

### 2. 驾驶舱是什么

驾驶舱就是大屏/看板，展示汇总金额、分类金额、分析图。

当前代码里已经有集采驾驶舱接口，不是新做。它现在会从已有表里算金额。

你要问清楚：这次新台账上线后，驾驶舱还是继续用原来的表算，还是改成用新台账算。

### 3. 定时任务是什么

需求里说“每日 24:00 自动取前一日数据并自动更新驾驶舱”。

这不是前端页面自己干的，也不是用户点按钮干的。

后端项目里接了 XXL Job。你可以把 XXL Job 理解成“公司统一的定时任务后台”。它负责每天 0 点叫后端跑一次某个方法。

所以要确认：

- 后端方法由 AI 写。
- XXL Job 任务由谁配置。
- 任务每天几点跑。
- 跑失败了谁看、怎么重试。

### 4. 导出模板是什么

导出模板不是让你找一个 Excel 文件。

当前项目的 Excel 导出列配置在数据库表里。简单说就是：

```text
哪一列叫“统计日期”，对应后端字段 statisticDate
哪一列叫“交易金额”，对应后端字段 taxAmount
```

这些列配置通常在模板表里维护。

所以你要问：导出模板谁配、模板编码叫什么、要不要我提供字段清单。

### 5. 网关、Swagger、XXL Job 地址分别是什么

这三个东西不是一回事。

后端网关地址：前端调后端接口时经过的统一入口。你测试接口时也可能要走它。

Swagger / Knife4j 地址：接口文档页面，可以看有哪些接口、参数怎么传，也能手动调接口。

XXL Job 地址：定时任务管理后台，用来配置“每天 0 点跑哪个后端方法”。

下午你可以问：

```text
请分别给我 test 环境的后端网关地址、Knife4j 地址、XXL Job 调度中心地址和账号权限。
```

## 现在代码能确定什么

这些是我从代码里确认的，你不需要全讲，但心里要知道。

1. 后端启动服务是 `scm-cloud-source`。
2. 业务代码主要在 `01zhaocai-end/scm-source-all`。
3. 这次新增台账大概率放在 `scm-source-source-api` 和 `scm-source-source`。
4. 当前已经有集采驾驶舱接口。
5. 当前已经有一套“昨天数据汇总”的代码雏形，会汇总寻源、SAP、订单、绿色通道数据。
6. 当前已经接入 XXL Job，不建议前端注册定时任务，也不建议 Java 写死本地定时器。
7. 当前项目有通用 Excel 导出，导出列要配模板表。

换句话说：

```text
AI 开发 CRUD 页面接口不难；真正要确认的是业务口径、权限配置、数据来源、驾驶舱刷新关系。
```

## 必须向公司确认的 12 个问题

下面这些是优先级最高的。你下午可以照着问。

### 1. 新台账的数据是人工填，还是系统自动生成？

为什么要问：

如果是人工填，AI 要做新增、编辑、删除，并重点校验用户输入。

如果是系统自动生成，AI 要写汇总逻辑，从已有业务数据里算出来，人工编辑可能不该开放。

建议问法：

```text
这张“集采日金额统计台账”的数据，是业务人员手工维护，还是系统每天自动汇总生成？如果两者都有，手工维护和自动刷新谁优先？
```

### 2. 新台账和驾驶舱是什么关系？

为什么要问：

这是最核心的问题。

可能有三种答案：

1. 新台账只是新增页面，驾驶舱不改。
2. 新台账的数据要同步到驾驶舱缓存表。
3. 驾驶舱以后直接从新台账统计。

三种答案对应三种不同开发方案。

建议问法：

```text
新台账上线后，集采驾驶舱的数据来源是否要改？驾驶舱是继续用现有汇总表，还是改成从 sc_collection_daily_amount_ledger 统计？
```

### 3. 每天 0 点自动更新到底更新哪张表？

为什么要问：

需求写“更新集采驾驶舱”，但驾驶舱只是页面，不是表。后端必须知道要更新哪张数据库表。

当前代码里已有：

- `sc_source_collection`：集采明细/汇总来源表。
- `sc_collection_data`：驾驶舱缓存数据表。
- 你计划新增 `sc_collection_daily_amount_ledger`：日金额统计台账表。

建议问法：

```text
每日 0 点任务跑完后，期望写入哪张表？是写新台账表、写驾驶舱缓存表 sc_collection_data，还是更新现有 sc_source_collection？
```

### 4. “统计日期”按什么日期算？

为什么要问：

“7月2日 0 点取 7月1日数据”看似清楚，但业务数据里可能有很多日期：

- 采购完成日期。
- 定标完成日期。
- 订单收货日期。
- SAP 过账日期。
- 业务发布时间。
- 台账手工填写日期。

如果日期口径错，金额就会错。

建议问法：

```text
统计日期具体按哪个业务日期？是自然日、定标完成日期、订单收货日期、SAP 日期，还是台账上人工填写的日期？
```

### 5. 交易金额是什么口径？

为什么要问：

金额字段不能只叫“金额”，要确认：

- 含税还是不含税。
- 单位是元还是万元。
- 是否四舍五入。
- 保留几位小数。
- 是否只人民币。
- 负数、冲销、退款怎么算。

建议问法：

```text
交易金额是含税金额吗？数据库保存单位是元还是万元？保留几位小数？退款或负数金额是否纳入统计？
```

### 6. 同一天同维度能不能有重复记录？

为什么要问：

这决定数据库要不要加唯一约束，也决定新增时要不要报错。

例如：

```text
统计日期 + 执行单位 + 类目 + 采购企业
```

如果这四个字段相同，是否只能有一条金额？

建议问法：

```text
同一个统计日期、同一个执行单位、同一个集采类目、同一个采购企业，是否只能有一条台账记录？如果重复提交，是覆盖还是报错？
```

### 7. 集采执行单位从哪里选？

为什么要问：

前端页面可能用组织机构控件。后端要知道保存哪些字段。

建议问法：

```text
集采执行单位从哪个组织树选择？前端控件会返回哪些字段？至少是否有 orgCode、orgName？
```

### 8. 采购企业从哪里选？

为什么要问：

采购企业也可能来自组织机构，但不一定和执行单位同一棵树、同一权限范围。

建议问法：

```text
采购企业是否也从组织机构选择？它和集采执行单位是否用同一个组织控件？保存 orgCode/orgName 还是 companyCode/companyName？
```

### 9. 所属板块是自动带出还是手工选？

为什么要问：

代码里组织信息有 `belongBuCode`、`belongBuName`，说明所属板块可能可以从组织带出。

如果自动带出，AI 要调用组织接口或根据前端返回字段保存。

如果手工选，就需要字典或下拉数据。

建议问法：

```text
所属板块是根据采购企业或执行单位自动带出，还是用户手工选择？如果自动带出，以哪个组织为准？
```

### 10. 集采类目来自哪里？

为什么要问：

当前代码里有些集采类目是写死的，比如煤炭、钢材、润滑剂等。但新页面不能随便写死，除非公司明确。

可能来源：

- 数据字典。
- MDM 物料分类。
- 现有集采物料范围表。
- 固定几个枚举。

建议问法：

```text
集采类目下拉框的数据来源是什么？是数据字典、MDM 物料分类、集采物料范围，还是固定枚举？请给我编码和名称口径。
```

### 11. 权限怎么配？

为什么要问：

代码写完不代表页面可用。没有菜单权限，页面看不到；没有按钮权限，新增/删除/导出不能点；没有数据权限，查不到正确数据。

建议问法：

```text
这个新页面需要配置哪些菜单和按钮？“集采管理-执行单位集采管理岗”能看到哪些数据范围？权限由谁配置，我需要提供哪些菜单编码、按钮编码、接口地址？
```

### 12. 导出模板谁配？

为什么要问：

AI 可以给出字段，但通常不能直接知道公司 test 环境模板表由谁维护。

建议问法：

```text
Excel 导出模板是开发写 SQL 配置，还是后台页面配置？模板编码叫什么？导出列顺序和列名由谁确认？
```

## 你原笔记里的问题逐条解释

### “需要测试权限账号”

你问得对，而且这是必须项。

你要的不是随便一个账号，而是能测试这个需求的账号。它要具备：

- 能登录 test 前端。
- 能看到新增菜单。
- 能操作新增、编辑、删除、导出按钮。
- 数据范围符合“集采管理-执行单位集采管理岗”。

否则 AI 开发完，你只能证明接口能跑，不能证明业务权限正确。

### “后端网关地址”

这是后端统一入口。

你本地知道服务叫 `scm-source-web`，但 test 环境前端通常不是直接访问这个服务，而是通过网关转发。

你要这个地址是为了：

- 前端联调知道请求打到哪里。
- 你用 Postman / Knife4j 测接口知道调哪个环境。
- 出问题时能判断是网关拦了，还是业务服务报错。

### “Swagger / Knife4j 地址”

这是接口文档页面。

你要它是为了：

- 看接口路径。
- 看请求参数。
- 手动测试接口。
- 给 AI 对照已有接口风格。

如果公司没开 Knife4j，也要问是否有其他接口文档方式。

### “XXL Job 调度中心地址”

这是定时任务后台。

需求里“每日 24:00 自动更新”就要靠它。

你要它是为了确认：

- test 环境有没有任务后台。
- `scm-source-web` 执行器有没有注册。
- 新任务由谁配置。
- 能不能手动触发一次测试。

你不用现在深入 K8S。K8S 是部署和看日志相关，下次再整理没问题。

### “数据库连接方式”

你要问的不只是数据库地址。

你实际要确认：

- 新表建在哪个库。
- 你有没有权限查表结构和数据。
- 建表脚本谁执行。
- 菜单、权限、字典、导出模板配置在哪个库。
- test、uat、prod 是否都要脚本。

不要让同事在聊天里发密码。你只要问“我通过什么方式连接，权限怎么开”。

### “集团集采类目、所属板块、字典表”

这句话要拆成 3 个问题。

集团集采类目：页面上的“类目”下拉框数据从哪来。

所属板块：这条台账属于哪个业务板块，是自动从组织带出，还是用户选择。

字典表：如果类目、板块、状态这些是固定选项，是否通过 UBM 数据字典维护。

你下午不要只问“我要不要字典表”。要问：

```text
哪些字段是下拉选择？每个下拉的数据来源分别是什么？
```

### “导出模板怎么配”

这表示 Excel 的列不是代码里随便写死，而是通过模板配置控制。

你要确认：

- 导出文件名。
- 导出列名。
- 导出列顺序。
- 每一列对应后端哪个字段。
- 模板编码。
- 谁配置。

如果没人配置，AI 写了导出接口也可能导不出列。

### “组织机构控件前端返回哪些字段”

这是前后端联调问题。

后端保存执行单位、采购企业，最好保存编码和名称。

但前端控件可能返回：

- `orgId`
- `orgCode`
- `orgName`
- `companyCode`
- `companyName`
- `belongBuCode`
- `belongBuName`

字段名不同，AI 写的接口参数就不同。

你要问前端或同事：

```text
组织机构选择控件选中后，提交给后端的 JSON 长什么样？请给一个示例。
```

### “定时任务是前端注册，还是 Java 写死”

按当前项目看，都不是。

更准确说法是：

```text
Java 写一个可被调用的方法，XXL Job 后台配置每天 0 点调用它。
```

所以你要问的是：

- 是否复用已有汇总任务。
- 是否新增任务。
- 任务参数怎么配。
- 谁负责在 XXL Job 后台配置。

### “实时汇总和读缓存表没听懂”

用一句话理解：

实时汇总：用户打开驾驶舱时，后端现场从明细表算金额。

读缓存表：定时任务提前把金额算好写进一张结果表，用户打开驾驶舱时直接读结果。

区别：

- 实时汇总数据更“现算现用”，但慢，SQL 压力大。
- 读缓存表页面更快，但依赖定时任务跑成功。

当前代码两种方式都有。

你要问领导的是：

```text
新台账加入后，驾驶舱要实时从台账表统计，还是每天 0 点先汇总到缓存表，驾驶舱只读缓存？
```

## 这次应该让 AI 开发什么

在公司问题确认前，AI 现在能稳妥做的是：

1. 新增台账表对应的后端实体、DTO、Mapper、Service、Controller。
2. 做分页查询、新增、修改、删除、详情。
3. 预留导出接口。
4. 按确认后的字段写建表 SQL。

暂时不应该让 AI 贸然做的是：

1. 改驾驶舱统计口径。
2. 改现有定时任务。
3. 写死集采类目。
4. 写死所属板块。
5. 假设权限规则。

原因是这些都依赖公司业务口径。

## 问完后给 AI 的开发口径

你下午问完后，最好整理成下面这种格式给 AI：

```text
确认结果：
1. 新台账数据来源：人工维护 / 系统自动生成 / 两者都有。
2. 驾驶舱关系：不改驾驶舱 / 从新台账实时统计 / 定时汇总到缓存表。
3. 统计日期口径：xxx。
4. 交易金额口径：含税/不含税，单位 xx，精度 xx。
5. 唯一规则：统计日期 + 执行单位 + 类目 + 采购企业 是否唯一。
6. 执行单位字段：前端返回 xxx。
7. 采购企业字段：前端返回 xxx。
8. 所属板块：自动带出/手工选择，来源 xxx。
9. 集采类目：来源 xxx。
10. 导出模板：模板编码 xxx，列顺序 xxx。
11. 权限：菜单编码 xxx，按钮 xxx，岗位 xxx。
12. 定时任务：复用/新增，XXL Job 由 xxx 配置，cron xxx。
```

AI 有了这些，才适合正式改代码。
