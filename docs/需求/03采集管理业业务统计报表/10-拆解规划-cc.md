# 第一部分：写给你看的

## 1. 这个需求到底是做什么

给领导做一张**集采业务的汇总账本**：集团下面各企业买东西有 5 条渠道（招采平台自己招标、线下买完回来补录、云采商城下单、煤炭走 SAP、机电走自己系统），现在领导想在一张表里看到所有渠道的每一笔集采交易，能按企业/板块/时间/供应商筛，能导 Excel。

打个比方：**5 条河（5 个数据来源）汇进一个水库（ES 搜索库），报表页面从水库里取水**。每天定时"抽水"（定时任务把当天新增的交易数据抽进水库）。

**你这期的任务只有一条河：非平台录入**。搞懂它的水从哪来、怎么流、抽哪些进水库。

## 3. "非平台录入"业务逻辑全景（核心交付）

**非平台录入 = 系统里的"供应商绿色通道"模块**（代码里叫 greenChannel，接口路径里的 Ftp/FPT = 非平台 的缩写）。

**它是干嘛的**：有些采购没走招采平台流程（比如线下直接谈的、或从 SRM 等外部系统来的），事后要把结果补录进平台备案。补录的内容 = 跟哪个供应商、买了什么物料、花了多少钱。

**完整流程（每步都有代码证据）：**

```
① 企业经办人在页面填单（或 SRM 系统通过接口推过来）
   └ 填：供应商、采购业务名称、采购业务分类(集团集采等)、总金额 + 物料明细清单
   └ 存进两张表：主表 sc_supplier_green_channel（一单一条）
                明细表 sc_supplier_channel_projects（一单多条物料，channel_id 关联）
   └ 系统自动生成采购业务编号，格式如 10930000-XJ-FPT-2026-0028
     （公司编码-采办方式-FPT-年份-流水号）
   └ 代码：SupplierGreenChannelServiceImpl.createGreenChannel（页面）
          / createGreenChannelForOuterInterf（SRM 接口）

② 提交后自动发起审批流（approve_status=0 审批中）
   └ 代码：startWorkFlowGreenChannel → 工作流平台

③ 审批有了结果 → 工作流回调 greenChannelApprove
   └ 通过：approve_status=101，**并发 MQ 消息把这单推进 ES**（已有的一套同步，见第 5 节）
   └ 拒绝：approve_status=102
   └ 代码：SourceEnrollServiceImpl.java 第 1864-1884 行
   └ ⚠️ 回调只改审批状态字段，updateById 时框架自动刷新 update_time
     —— 所以"审批结束日期"目前 = 主表的 update_time（现有交易报表也这么取的）

④ 《采购寻源-非平台采购业务查询》页面 = 只查 approve_status=101（审批通过）的单子
   └ 代码：queryGreenChannelListFtp（就是产品文档里贴的那个接口）
   └ "查看-合作项目"弹窗 = getGreenChannelDetail，从明细表取物料清单
```

**测试库数据现状**（scm_source_test，2026-07-17 实查）：主表 311 条（审批通过 238 / 审批中 65 / 拒绝 8），物料明细 669 条。

## 6. 三个数据质量地雷（我实测出来的，必须确认）

1. **主键会撞车**：测试库里"同一单+同一物料描述"重复的有 **17 组**。用"业务编号+物料描述"当主键，重复的行会互相覆盖只剩一条，**金额就统计少了**。（另有 3 条物料描述是空的。）→ 问题 1
2. **类目基本是空的**：669 条明细里 **625 条（93%）没有类目编码/名称**——存量数据录入时就没填。报表的"类目编码/类目描述"两列会大面积空白。→ 问题 2
3. **同事现有定时任务的增量口径有缺陷**：它按"**创建时间**=昨天"扫数据，但绿色通道单子从创建到审批通过往往隔好几天——昨天审批通过、但上周创建的单子，永远不会被扫到（创建那天扫的时候它还没审批通过）。**新报表照抄这个口径会持续漏数据。** 应该按"审批结束时间=昨天"扫（或复用审批回调的实时推送）。→ 问题 6

## 7. 你需要知道的背景知识（大白话）

- **ES（Elasticsearch）**：专门做"快速搜索汇总"的数据库，好比图书馆的索引卡片柜。报表数据从 MySQL 抽进 ES，是因为跨 5 个来源的组合查询用 MySQL 会很慢。里面的"索引(index)"≈MySQL 的表，"文档"≈行，"主键(_id)"相同就覆盖（所以重复抽水不会存两份——但也是"主键撞车会丢数据"的原因）。
- **MQ（消息队列）**：系统内部的"传声筒"。审批通过的瞬间丢一条消息进去，另一个程序听到后把这单推进 ES——这叫实时推送。
- **XXL-JOB（定时任务平台）**：公司统一的"闹钟系统"，在管理页面上配"每天几点跑哪个方法"。本项目入口叫 sourceJobHandler，参数格式"服务名-方法名-JSON参数"，配好后它会自动调用后端对应方法。同事说的"做定时任务"就是指这个。
- **字典**：全公司下拉框选项的集中仓库。"采购业务分类"的 4 个选项就存在字典里（编码 101~104），代码里存编码、页面上显示名称。
