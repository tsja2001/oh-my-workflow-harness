# 云采平台板块名称不一致 · 现状说明

> 日期：2026-07-23  
> 工具：codex  
> 当前状态：原因和代码状态已核实；只读排查，未改代码、ES 或 Git 分支。  
> 下一阶段：和云采开发同事确认按板块字典统一名称，并补跑覆盖现有两条 YC 数据。

## 一句话结论

这不是下拉框少了“冀东水泥”，而是**同一个板块编码 `BU002` 被写成了两个名字**：

- 云采数据写入 ES：`BU002 / 冀东水泥`
- 所属板块字典：`BU002 / 水泥集团`

筛选实际按编码 `BU002`，所以选择“水泥集团”已经能查到那两条显示为“冀东水泥”的云采数据。问题在**显示名称不统一**，不在筛选功能。

## 当前实测

| 检查 | 结果 |
|---|---|
| 云采数据 | 2 条，都是 `dataSource=YC` |
| 云采板块 | `buCode=BU002`、`buName=冀东水泥` |
| 下拉字典 | `BU002=水泥集团`，没有“冀东水泥” |
| 选择“水泥集团”+“云采平台” | 能查到上述 2 条 |
| 只选 `BU002` | 共 6 条，同时出现“水泥集团”和“冀东水泥” |

## 原因

前端下拉框读取 `Owningplate` 字典，显示字典标准名“水泥集团”，提交编码 `BU002`：

- 前端：`centralizedProcurementReport/index.vue:170-180`
- 后端：`SourceMetaQueryServiceImpl.java:1643-1646` 按 `buCode` 精确筛选

云采写入代码没有再按字典统一名称，而是直接把组织接口返回的：

```text
belongBuName = 冀东水泥
belongBuCode = BU002
```

原样写进 ES。证据：

```text
scm-order-all origin/test@bdcf979e9
CentralizedProcurementReportServiceImpl.java:308-311、335-361
```

非平台和招采写入侧已经采用另一种做法：保留 `buCode`，再按 `Owningplate` 字典把 `buName` 统一成标准名。

## 建议怎么处理

不要往下拉框再加一个“冀东水泥”，否则同一个 `BU002` 会出现两个选项。

推荐让云采写入侧统一规则：

1. 继续使用组织接口返回的 `belongBuCode=BU002`。
2. 用 `BU002` 查 `Owningplate` 字典。
3. ES 的 `buName` 统一写“水泥集团”。
4. 修复后重跑现有两条订单；ES 主键不变，会直接覆盖旧名称。
