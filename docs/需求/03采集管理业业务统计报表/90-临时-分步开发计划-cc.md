## 一、一句话目标

做一张汇总 5 类采购来源的"大账本"报表。数据先从 MySQL 抽出来、按统一字段存进 ES（一个公共"货架"），
以后报表页面统一从 ES 查询和导出。**我们这次只负责其中"非平台录入(FP)"这一路。**

## 二、分工（2026-07-21 更新，很重要）

| 事项 | 谁负责 |
|---|---|
| 非平台录入(FP) 抽数 → 写 ES 的代码 | 我们（AI 代写） |
| **ES 索引的创建** | **改为我们自己**（同事只给了字段模型设计，不再等他先部署建索引） |
| 部署、执行同步、验证 | 我们自己 |
| 同事那边（订单 IN 等其他来源） | 同事另外做，和我们各写各的代码，只共用同一套 ES 字段和索引名 |

> **和旧计划的唯一变化**：旧计划让同事先部署、我们的模型设 `createIndex=false` 只写不建。
> 现在我们全包，所以我们的 ES 模型**自己创建索引**（Spring 启动时按模型自动建好索引和字段结构）。少了一个"等同事"的卡点。

## 三、分几步（一步一验证，一步一份文档）

### 阶段一：手动把一小批 FP 数据写进 ES　←　现在这里

- **做什么**：在 `scm-source-all` 加一个手动接口，能传一个日期范围，把符合条件的非平台录入数据抽出来、按统一字段写进 ES。
- **验证**：调一次接口 → 查 ES 对账（MySQL 几条物料，ES 就几条）；再调一次同样日期，看 ES 数量不涨（证明重复不会重复写）。
- **产出文档**：`20-开发交接-cc.md`（做了什么 + 新代码跟读 + 你要做的清单）。

### 阶段二：补历史 + 每天自动同步

- **补历史**：手动把 2026-01-01 到上线前一天的数据一次性灌进 ES。
- **定时任务**：加一个每天凌晨自动扫前一天审批通过数据的 XXL-JOB；保留"手动补跑任意日期"能力。
- **验证**：定时任务能自动跑、能补指定日期。
- **产出文档**：阶段二开发交接 + 跟读。

### 阶段三：查询 + 导出 + 前端页面

- 在 `scm-report-all` 做从 ES 查询/分页/导出，前端做报表页面，菜单权限找张雨配。
- ⚠️ 这一步分工还没书面定死，等前两步 ES 数据链路稳了再确认归属。

## 四、闸门原则

**一次只做一个阶段，上一阶段验收通过才做下一阶段。** 现在只允许在阶段一，不把定时任务、查询、前端混进第一批代码。
