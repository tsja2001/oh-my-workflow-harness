# 第一章 先搞懂这家公司是怎么买东西的

## 1.1 公司结构：三层

金隅集团是个国企航母，底下十来个二级集团（也叫"板块"，系统里叫 BU），每个板块底下挂着几十上百家成员企业。招采平台的组织表里实测 854 家企业、13 种板块编码：

```
金隅集团（总部，BU001）
 ├─ 冀东水泥（BU002）── 唐山冀东水泥、冀东水泥滦州、天津冀东水泥……几百家
 ├─ 冀东集团（BU004）
 ├─ 地产集团（BU006）
 ├─ 投资物业集团（BU007）
 ├─ 新材产业化集团（BU005）
 ├─ 天津建材集团（BU008）
 ├─ 混凝土集团（BU003）、财务公司（BU009）、建研总院（BU010）、京才、党校、冀东国贸……
```

"BU"这个词后面到处出现（影响范围编码填的就是 BU 码），记住 = **二级集团/板块**。

## 1.2 为什么会有"集采"这个东西

854 家企业各买各的钢材 → 谁都谈不出好价钱、审计还难管。所以集团说：**某几类东西，你们不许自己买，统一由我指定的单位去买**。这就是集中采购。

三个动机：**压价**（打包成大单好砍价）、**合规**（国资采购是纪检审计重点，集中留痕）、**数据**（集团得知道自己一年买多少钢，才有明年谈判的底气）。

对二级集团单位来说，"集采率"（集采金额 ÷ 总采购额）是**自上而下的考核指标**——这就是为什么后面所有报表、台账、管控都围绕它转，也是这次需求"要分清集团集采/二级集团集采/区域集采"的根本原因：**不同层级的成绩要分开算**。

## 1.3 现在被"集采"管着的都是哪些东西

按这次会议的说法（录音 00:00:29 起），现在集团级集采管控的是这几大类：**煤炭、钢材（黑色金属）、电线电缆、轴承、办公用品、办公设备、挥发油**。

管控的粗细不一样：
- **黑色金属**：不是整个类目都管，是**按一个个物料编码**管的（精确到"哪种钢材"）；
- **办公用品、办公设备**：按**二级类目**管（整个类目一网打尽）。

记住这个区别——"按物料"和"按类目"两种粒度并存，就是现在台账的玩法，也是这次要升级的点。

## 1.4 两个特殊的公司（整个业务的"设计原点"）

| 公司 | 是谁 | 管什么 |
|---|---|---|
| **机电公司**（唐山冀东机电设备，编码 12300000） | 集团指定的执行单位 | 钢材、润滑剂、电线电缆、轴承"四大类" |
| **北分**（金隅冀东水泥北京分公司，10010072） | 集团指定的执行单位 | 煤炭 |

"执行单位"= **替全集团去买东西的那家公司**。企业们提需求，执行单位集中去谈、去签、去分货。这两家在后面到处出现，看到它们就知道"哦这是集团级集采的接盘侠"。

# 第二章 "买东西"其实有五个入口

这是整个业务地图的骨架。集团的钱从五个完全不同的地方流出去，平台要把它们全都看见：

| 入口 | 外号 | 是什么 | 谁在用 |
|---|---|---|---|
| ① **招采平台**（主流程） | 正规军 | 完整的招标/询价流程 | 大额、需要公开采购的项目 |
| ② **云采商城** | 企业版京东 | 挂商品、在线比价、直接下单，不走招标 | 标品、小额（办公用品这类） |
| ③ **非平台录入**（绿色通道） | 补丁 | 没走系统就买了的，事后补录 + 审批 | 紧急采购、独家供应、历史合同延续 |
| ④ **煤炭 SAP** | 外来户 | 煤炭天天大宗买，不适合招标，在 SAP 里走采购单，系统每天自动推流水过来 | 只有煤炭、只有北分 |
| ⑤ **机电手工台账** | 手工账 | 机电公司四大类采购根本不在这套系统里发生，让人每天填一个日汇总金额进来 | 只有机电公司 |

**为什么 ④⑤ 会存在**（这是最容易被新人看不起、其实是老江湖的设计）：
- 煤炭是水泥厂的命根子，**每天**都在拉货按天结算——一年招几百次标是不可能的，它天然活在 ERP 里；
- 机电公司的钢材生意在它自己的体系里跑，把整套系统接进来要半年，给一个页面让人每天填个数只要一周。
- **"台账"的本质：用极低的成本，把系统外的业务拉进数字化考核。** 先有数、再有精度。

所以看到"台账"别急着觉得low——它是务实的补丁。但也要分清（第七章专门列）。

## 2.1 云采商城再多说两句（和这次需求关系最大）

云采不是一个独立公司做的系统，它和招采**同一套后端、同一个代码仓库群**，只是换了门脸：
- 招采前端在 `32740` 端口那堆模块（采购计划、采购方案……），云采前端在 `30370` 端口（商品管理 productMgt、商城 mall……）；
- 后端各自一组微服务：招采的寻源在 `scm-source`，云采的商品/类目在 `scm-product`，订单在 `scm-order`。

云采和集采的关系：**云采商城本身就是集团搭的集中采购平台**——上面的商品是集团统一谈过价、供应商统一准入的，所以在云采上下单这个动作**本身就已经是集采**，不需要再打"是否集采"标记（统计口径里云采全量算集采）。

云采还有一套自己的"采购范围管理"（哪些类目的商品允许上云采/必须走云采），带**"是否强控"**字段、按强控与否走两套审批模板——**这次需求里的"是否强管控"就是把这个已经在云采跑起来的玩法搬到招采**。需求文档里"（同云采）"三个字指的就是它。

## 2.2 非平台录入（绿色通道）的微妙之处

它不是采购工具，是**合规兜底**：不给出口，人就在系统外买完彻底不录，集团就永远看不到这笔钱。所以设计是"先放你买，事后必须补录、必须审批"。

**这次需求里它和集采的交叉**：补录时也要选物料、也要过一遍"是不是集采"的校验（现在它表单上有个灰色的"是否集采"单选框，和计划/方案一样是系统自动盖的章）。第二期要把它放开成可改。

# 第三章 招采主流程：一张单子的完整旅程

入口①展开就是招采平台的主流水线。**这次需求的"三单校验"卡在其中三个节点上**，所以必须把这条线走熟：

```
【企业采购员】
  1. 采购计划        "我要买什么、买多少、什么时候要"（需求单）
       │ 提交时 ★盖章点1：系统查集采台账 → 盖"是否集采"
       │ 审批通过后：
       │   ├─ 普通需求 → 转给企业自己/相应单位编制方案
       │   └─ 集采需求 → 转"采购待办"给【集采执行单位】★这就是"执行单位在线确认计划"
  2. 采购方案        "怎么买"：选寻源方式、定资格条件、写标的
       │ 提交时 ★盖章点2：再查一遍台账盖章
       │ （集采且有计划的，页面直接提示"请联系集采执行单位组织采购"——企业就别自己往下走了）
  3. 寻源            按方案选的方式走流程：
       │   招标 / 询价 / 竞争性谈判 / 竞争性磋商 / 单一来源 / 竞价
       │   （供应商报名、报价、开标评标都在这阶段）
  4. 定标 + 公示     确定中标供应商和价格，对外公示
  5. 合同            中标后签合同（合同模块）
  6. 订单/履约       下单、收货、对账（订单中心）
```

三个盖章点（计划、方案、非平台录入）**调的是同一个后端接口**，逻辑是同一个：
拿单子上的物料/类目去《集采范围台账》里对——
- 全对上 → 盖"是否集采=是"；
- 全对不上 → 盖"否"；
- 一部分对上 → 弹框报物料名："集采和非集采不允许同时采购"（让你拆单）。

盖章之后"是否集采"这个字段在页面上是**灰的**（只读）——这就是需求里说要"放开可编辑"的那三个点。

**每个单子审批走几级、谁审，不在这套代码里**——代码只负责把"是否集采"之类的字段**推给工作流平台**（集团外部的一套流程引擎，叫 DPS），流程模板是产品/实施在平台上画出来的。这次需求"强管控改成否要向上一级审批"，就是：我们把新字段（层级/强弱）也推过去，产品那边在平台上画新的分支。

# 第四章 集采管控这台机器：现在怎么转、要怎么改

## 4.1 现在这台机器（《集采范围台账》=它的规则卡）

把现在的一切想象成一张**贴在墙上的采购黑名单**：

- **录入方式**：Excel 导入（页面上没有"新增"按钮，只有导入/导出/批量删除）；
- **每行规则**长这样：类目（只能填二级）/ 或物料编码 + 影响范围（BU 码，斜杠拼一串）+ 执行单位；
- **生效方式**：导入即生效，全集团一律适用；
- **删除**：物理删除，删了就像从没存在过；
- **最大的秘密**：影响范围那列**校验时根本不看**——写"只管冀东水泥"，物业集团来买照样被盖章。纯摆设。

现在 uat 上 7343 条规则，全部是二级类目。

## 4.2 改完之后（这次需求的全貌）

还是那张清单，但从"黑名单"升级成一套**分级管理制度**（红头文件）：

| 维度 | 变化 |
|---|---|
| 谁定的规矩 | 每条规则标层级：**集团集采 / 二级集团集采 / 区域·企业集采** |
| 管多细 | 类目可以填到**末级**（树有的杈到三级、有的到四级） |
| 管谁 | 影响范围真正生效：集团=全部企业；二级集团=指定 BU 下属企业；区域=区域编码下的企业 |
| 规矩多硬 | **强管控**：企业可把"是否集采"改成否，但要向上一级审批（企业发起→二级集团审；二级集团发起→总部审）；**弱管控**：可改，改完走原流程 |
| 生命周期 | 删除=失效留痕（记录失效时间+状态），校验只认"生效"的规则 |
| 谁去执行 | 集团级配执行单位（机电/北分接盘）；二级集团/区域级**不需要**执行单位（自己的事自己办） |

**"区域"是什么**（会上定的方案）：组织树上没有"区域"这种节点，区域是贴在企业身上的标签——组织单元管理里每个企业有个"所属区域编码"（如唐山分公司=TSQY 唐山区域、冀东水泥黑龙江=JHQY 吉黑区域）。区域集采=填一个区域码，系统找出所有挂这个标签的企业来管。
**但这个标签 73% 的企业没填，填了的还有脏的**（拿公司码当区域用的、错别字的）——产品说他去找管组织主数据的人（小慧）推进补全。

## 4.3 为什么集团现在要搞这个（9 月底的背景）

录音最后交代了：集采平台底层已经有了，**集团 9 月底要发文在全集团推广集采管控**。推广的前提是各二级集团上报自己的集采范围——也就是说上线后会有一波"每个板块把自己的规则导进来"的操作。这就是为什么：
- 必须支持"二级集团集采"这一层级（现在只有集团级）；
- 必须能管到末级（各板块的规则不会都那么粗）；
- 必须有强弱之分（一刀切强管控，业务上转不动）；
- 9 月底上线，倒排三周开发。

# 第五章 底座：撑着这一切的主数据和基础设施

这一章解决"谁给谁供数据"的关系问题。

## 5.1 两份组织、两棵树（最容易串的地方）

**组织有两份**：招采侧一份（854 家）、云采侧一份（804 家，产品会上演示组织页面时打开的其实就是这份——它挂在云采的 30370 端口下）。两边 95% 重合但各自维护，字段都一样（都有"所属区域编码"）。**采购计划/方案/盖章用的是招采侧那份**——所以区域集采要看招采侧的标签填没填，云采侧维护了不算数。

**类目有两棵树**：
- **物料分类树（MDM 主数据里的）**——招采这边真正用的。物料挂类目、台账校验、计划方案里的类目全是它。四个层级，末级 1170 个。
- **云采后台类目树**——云采商城品类管理用的那根树（产品会上演示的"参考云采"就是它）。
- 两棵树 95% 一致（同一份数据的两个副本），**招采这棵还更全一点**。所以"参考云采"不用真的去连云采，把招采自己"只能选二级"的限制放开就是"管到末级"。

**一个物料长什么样**（MDM 主数据，24 万条）：编码、名称、单位、税率，加上四级类目（一级/二级/三级/四级码）——100% 的物料有二级类目，95% 有三级，39% 有四级（有的树杈本来就不到四级）。

## 5.2 字典（管理后台配的下拉选项）

两个和这次需求直接相关的字典：
- **《采购业务分类》**：101 集团集采 / 102 二级集团集采 / 103 区域集采 / 104 分散采购——和新的"集采目录层级"几乎一一对应，而且方案表里字段是现成的（只是从来没人填，1.7 万张方案只有 5 张有值）；
- **《集采执行单位》**：机电公司、北分两家（盖章时还有个豁免：执行单位自己下单，不算集采）。

## 5.3 工作流（DPS）

审批流程的引擎在集团统一的工作流平台上，**不在这套代码里**。代码的职责是发流程时把单据字段打包传过去（现在已传"是否集采"），平台上的模板引用这些变量画跳转条件。新需求要加传"层级/强弱"，流程模板由产品那边配。

## 5.4 数据的"两条读法"

业务数据写进 MySQL，但报表/列表查询走 Elasticsearch，中间靠定时任务凌晨同步。这就是为什么"今天录的单子报表上后天才能稳"——以及为什么台账类的东西常做成**实时读表**（保存即发布）而不是进 ES。

# 第六章 把所有叫"台账"的东西一次理清

| 名字 | 在哪 | 干什么 | 和本次需求的关系 |
|---|---|---|---|
| **《集采范围台账》** ★ | 运维中心/MDM 下，`procurementCatalogMgt` | **集采规则清单**（哪些东西必须集采） | **就是这次要改的东西** |
| 集采日金额统计台账 | 业务管理台账 | 机电公司每天手工填四大类成交金额 | 无关（那是统计补丁） |
| 集采日计划统计台账 | 同上 | 孤儿功能，基本没用 | 无关 |
| 煤炭坑口日指标台账 | 同上 | 每天填煤价坑口价 | 无关 |
| 价格趋势维护台账 | 同上 | 维护钢价走势给驾驶舱画图 | 无关 |
| 云采"后台类目管理" | 云采 30370，品类管理 | 云采商品类目树维护 | 只是被拿来当"末级类目长什么样"的参考 |
| 云采"采购范围管理" | 云采，procurementScopeConfig | 云采自己的集采范围+是否强控 | **抄它的作业**（强管控玩法） |

一句话防混：**"范围台账"管规则（买之前判断），"金额台账"管统计（买完记账）。** 这次只动前者。

# 第八章 术语词典（按拼音排序，随身携带）

| 词 | 人话 |
|---|---|
| BU / 板块 / 二级集团 | 一个意思：冀东水泥、地产集团这一层。影响范围编码填的就是 BU 码 |
| 采购计划 vs 采购方案 | 计划="要买什么"（需求）；方案="怎么买"（选寻源方式、定规则） |
| 集采 / 集中采购 | 这类东西不许自己买，统一由指定单位买 |
| 集采范围台账 | "哪些东西必须集采"的规则清单，本次需求本体 |
| 集采目录层级 | 这条规矩是谁定的：集团 / 二级集团 / 区域·企业 |
| 集采执行单位 | 替大家去买的那家（机电公司=四大类，北分=煤炭）；计划审批后转采购待办就转给它 |
| 集采率 | 集采金额÷总采购额，考核指标，一切报表的终极服务对象 |
| 强管控 / 弱管控 | 规矩硬不硬：强的能改但要惊动上级审批；弱的改了没事 |
| 末级类目 | 分类树每个杈的最底一层（有的到三级有的到四级，共 1170 个末级） |
| 三单 | 采购计划、采购方案、非平台录入——三个盖章点 |
| 是否集采 | 系统盖在单子上的章，现在灰色不可改，二期按强弱放开 |
| 区域 | 不是组织节点，是企业身上的"所属区域"标签（唐山区域 TSQY 等），73% 没填 |
| 绿色通道 / 非平台录入 | 买了没走系统，事后补录+审批的兜底通道 |
| 云采 | 集团自营商城（企业版京东），下单即集采 |
| 影响范围 | 这条规矩管哪些企业（按 BU 或区域码）——现在是个摆设，这次要让它真的生效 |
| 管后不管前 | 规则变了只影响新单子，跑着的老单子不动 |
| 期初上线 | 上线那天给历史数据补默认值（7343 条老规则得填上新必填字段） |
| DPS | 集团统一的工作流引擎，审批流程画在那边，代码只递变量 |
