## 一、结论：三选一，不是「换个画图工具」

原来那套字符画的问题**不是丑，是结构上修不好**：中文字符在等宽字体里占 2 列，但 AI 写的时候按「一个字 = 一格」数，所以框必然错位；改一个字的宽度要重算整行。AI 不擅长数字符宽度，而字符画 100% 依赖这件事。

但解法不是「全部换成 mermaid」。扫完这三份文件，15 张图里只有 9 张真的是流程图：

| 这张图在讲什么 | 用什么 | 本次占几张 |
|---|---|---|
| **东西之间怎么流**（A→B→C，有分支） | `mermaid flowchart` | 7 |
| **谁问谁答、谁等谁**（有方向、有先后） | `mermaid sequenceDiagram` | 2 |
| **什么条件走哪条路**（判定逻辑） | **markdown 决策表** | 3 |
| **一堆带数字的条目**（排名、清单、配置值） | **markdown 表格** | 3 |

**判据一句话：能画出箭头的才叫流程图；剩下的硬画成图，读的人要多翻译一层。**

你自己在 `13` 里早就把一张表当成了唯一事实源（「❓答案回来后只改 `13` §1 那张表」）——那就是证据。

## 三、给 AI 的 mermaid 写作约束

**没有这几条，AI 会画成意面或者画出你看不见的语法错误。** 建议原样贴进 `AGENTS.md`。

1. **节点 ID 只用 ASCII**（`a1` / `SRM` / `GW`），中文一律放进 `["..."]` 里。裸写中文 ID 会撞关键字。
2. **尖括号必须转义**：`<host>` 要写成 `&lt;host&gt;`。mermaid 默认按 HTML 解析标签，不转义会**整段静默消失**——这是最阴的坑，报错也不报。
3. **一张图只讲一件事，≤12 个节点**。超了拆图，用 `①②③` 编号互相指。
4. **判定深度超过两层 → 停，改写决策表。**
5. **换行用 `<br/>`，强调用 `<b>` / `<i>`**。不要为了排版把一个节点塞成 10 行——`视图5` 那个 10 行服务清单节点就把整张图拉得很高，那种情况应该拆成 `subgraph` 里的独立小节点。
6. **布局推断要留痕**：原图没画的边，用 mermaid 注释 `%% 推断：…` 写在图里。渲染时不显示，但 diff 和 AI 都看得见。
7. **改图不覆盖**：同一张图出第二版，按 §5「只增不覆盖」新建文件，别在原文件上洗掉上一版。

**踩过的两个小坑**：`❓` 这类 emoji 在无字体的 headless 渲染里会变成方框（`本企业 ❓4` → `本企业 []4`），VS Code 预览一般正常；给 `subgraph` 连边时，该 subgraph 内的 `direction TB` 会被忽略。

## 四、VS Code 要装什么

**必装一个**：`bierner.markdown-mermaid`（叫 **Markdown Mermaid**）。
VS Code 自带的 Markdown 预览**不认 mermaid**，装完这个才会渲染。装好后 `Cmd/Ctrl+Shift+V` 开预览即可。

```
ext install bierner.markdown-mermaid
```

可选：

| 插件 | 什么时候要 |
|---|---|
| `shd101wyy.markdown-preview-enhanced` | 要把图**导出 PNG/SVG/PDF** 交给华姐或产品时。功能重，和上面那个会抢预览，二选一 |
| `yzhang.markdown-all-in-one` | 表格自动对齐、`Alt+A` 选中列。本方案大量用决策表，很值 |

**看这次改造效果的正确姿势**：在文件树里右键 `原-xxx.md` → 「选择以进行比较」，再右键 `改-xxx.md` → 「与已选项目进行比较」。左右对照最直观。

## 五、两个校验脚本（就在本目录）

写文档时顺手跑，**别相信 AI 说「语法没问题」**。

```bash

# 1) 把每个 ```mermaid 块真渲染一遍，0 失败才算完
python3 校验mermaid.py

# 2) 核对改造没把图外的正文弄丢
python3 核对正文未丢失.py
```

`校验mermaid.py` 依赖 `/home/t/projects/work-wsl/.tmp-mermaid/`（本次装的 mermaid-cli + 复用 playwright 的 chromium，已 gitignore 范围外的临时目录）。
**如果你决定采纳这套方案，这两个脚本该提进 `scripts/`** —— 按 `AGENTS.md` §6 的判据，「每次改图都要回忆怎么跑校验」就是工具缺口。

验证结果：

- **渲染**：15 张全部通过（0 失败）。
- **正文**：3 个文件共 775 行图外正文，**真丢失 0 行**；`13c` 有 1 行报「挪进图内」——那是 §5.2 那句 ⚠️ 被有意合并进序列图的 `Note`，内容完整，不是丢失。
- 核对脚本用两级判据：先查「图外正文」是否原样还在；查不到就把整份文件（含图内）压成归一化文本再按子句兜底找。所以**看到「挪进图内」不用管，看到「真丢失」才要回去核对**。
