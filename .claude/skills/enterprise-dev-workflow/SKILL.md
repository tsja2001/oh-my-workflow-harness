  AI代开发企业级后端需求的全流程工作法：用户不懂目标语言/框架（如Java微服务），AI负责全部技术执行（读代码、查库、写代码、编译、提交），
  用户负责拿AI整理的问题去和产品/领导/同事对接。覆盖需求拆解→问题收敛(带逐字话术)→答案回收→开工侦察→照样板开发→
  隔离编译验证→干净提交test→Jenkins部署与接口链路验证，以及多AI阶段接力的文档交接规范。只要用户在企业代码库（如 work-wsl / zhaocai 招采平台）
  提出任何开发类请求——贴了一段产品需求、问"这个需求怎么做/怎么拆"、要整理问同事的问题、要写代码/建表/提交/部署/测接口/跑通流程——都要使用本skill，
  即使用户没提"流程"两个字。用户纯粹闲聊或只问概念解释时不用。

本文件只是**项目级加载器**，正史在仓库里（便于所有 AI 工具共享和 git 管理）。触发后立即：

1. 读仓库根 `AGENTS.md`——唯一必读入口（红线、任务分级、文档六段制、"遇到什么事翻哪一份"的索引表）。
2. 读 `skills/enterprise-dev-workflow/SKILL.md`（相对仓库根）——怎么把需求推到线上验证通过。
3. 按阶段需要再读同目录 `references/`：`doc-templates.md`（文档模板）、`env-playbook.md`（脚本没封装的命令）、`prompts.md`（跨工具接力提示词）。
4. 具体规矩**按需**查 `ai-docs/`（团队规矩 / 协作规矩 / 安全红线 / 系统地图 / 代码库地图 / 本地运行手册 / 工具箱），**不要开工前通读**。

不要只凭本加载器的描述行动；一切以正史文件为准。
