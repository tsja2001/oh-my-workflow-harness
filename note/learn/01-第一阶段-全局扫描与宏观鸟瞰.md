# 第一阶段：全局扫描与宏观鸟瞰

本阶段目标：先站在楼顶看项目，不钻进每个房间。你要先知道“有哪些服务、谁负责启动、谁负责业务、基础设施在哪里”。

## 1. 项目顶层结构

这个仓库大体可以看成四块：

```text
work-wsl
├── 01zhaocai-end      后端源码、公共组件、业务模块
├── 02zhaocai-front    前端项目
├── 03zhaocai-start    启动工程、部署工程、中间件启动包
└── note               学习笔记
```

这里的“启动工程”可以理解成外壳：它负责把服务跑起来；“业务源码”可以理解成发动机：真正的业务逻辑大多在 `01zhaocai-end`。

## 2. 构建工具与模块分布

后端主要使用 Maven（Java 项目常用构建工具，负责下载依赖、编译、打包），前端使用 Vue CLI + npm（前端项目常用构建方式，负责启动开发服务器、打包静态资源）。

| 区域 | 构建方式 | 作用 |
| --- | --- | --- |
| `01zhaocai-end` | Maven | 后端业务源码、公共依赖、公共组件 |
| `03zhaocai-start/scm-cloud-starters-web` | Maven | 后端微服务启动聚合工程 |
| `02zhaocai-front/scm-vue-all-mall-portal` | npm / Vue CLI | 商城门户前端 |
| `03zhaocai-start/scm-cloud-starter-vue/scm-cloud-statics` | Maven | 静态资源服务或前端静态包承载 |
| `03zhaocai-start/scm-cloud-starters-elasticsearch` | Docker/配置包 | Elasticsearch 启动相关资源 |

关键文件：

- `01zhaocai-end/scm-cloud-parent/pom.xml`：后端顶层父 POM，统一 Java、Spring Boot、Spring Cloud、数据库、缓存、搜索等版本。
- `03zhaocai-start/scm-cloud-starters-web/pom.xml`：可运行微服务的聚合 POM，列出了主要启动模块。
- `02zhaocai-front/scm-vue-all-mall-portal/package.json`：前端依赖和启动脚本，例如 `npm run serve`、`npm run build`。

## 5. 注册中心、配置中心与环境

大多数启动模块都依赖：

```text
spring-cloud-starter-alibaba-nacos-config
spring-cloud-starter-alibaba-nacos-discovery
```

结论：

- 注册中心：Nacos Discovery。服务启动后把自己的地址注册到 Nacos，其他服务不用写死 IP。
- 配置中心：Nacos Config。数据库、Redis、网关路由等配置可以从 Nacos 拉取。
- 默认 profile：多数服务使用 `${APP_PROFILE:dev}`，也就是没指定环境时默认走 `dev`。
- 开发环境 Nacos：多处 `bootstrap-dev.yml` 指向 `10.0.54.19:8848`，namespace 多为 `scm-jdsn`。
- 测试环境 namespace：多为 `scm-jdsn-test`。
- 预发环境 namespace：多为 `scm-jdsn-uat`。
- 生产环境 namespace：多为 `jdsn-prod`。
- 公共配置：大多数服务加载 `global-config.yaml`；商城网关和商城 UBM 加载 `global-mall-config.yaml`。

要注意：很多数据库、Redis、MQ 细节不在本地 `bootstrap.yml` 明文里，而是在 Nacos 的 `global-config.yaml` 里。这就像项目把“公共水电配置”放到了物业公告栏，本地代码只写了公告栏地址。

## 6. 数据库、缓存、消息队列与搜索

从本地 POM 和配置可以确认：

- 数据库类型：MySQL。多数业务服务依赖 `mysql-connector-java`、`scm-cloud-dependencies-orm`、`dynamic-datasource-spring-boot-starter`。
- 数据库库名：本地可见的部分配置出现过 `scm_ubm`、`scm_ubm_v3`、`scm_source`、`scm_srm`，但主启动服务多数库名预计来自 Nacos 公共配置，本地不能完整确认。
- 缓存：Redis。多数服务依赖 `spring-boot-starter-data-redis` 和 `scm-share-cache-web-jar`。
- 消息队列：代码依赖中有 RocketMQ/ONS，并且多个服务引入 `scm-share-mq-web-jar`，说明系统有异步消息能力。
- 搜索：多个业务服务依赖 Elasticsearch，尤其商品、供应商、寻源、报表等模块。
- 定时任务：`scm-cloud-scheduling` 是 XXL-JOB 调度服务，多个业务服务也引入 `xxl-job-executor-web-jar`。

## 7. 网关情况

项目有两个网关：

- `scm-cloud-gateway`：后台侧统一入口。
- `scm-cloud-gateway-mall`：商城侧统一入口。

它们都使用 Spring Cloud Gateway（请求转发网关），并依赖 Nacos Discovery（服务发现）和 Sentinel（限流熔断）。网关源码重点看：

- `03zhaocai-start/scm-cloud-starters-web/scm-cloud-gateway/src/main/java/com/pcitc/gateway/GatewayApp.java`：后台网关启动类，导入网关配置、缓存、认证 Feign。
- `03zhaocai-start/scm-cloud-starters-web/scm-cloud-gateway-mall/src/main/java/com/pcitc/gateway/GatewayApp.java`：商城网关启动类。
- `01zhaocai-end/scm-gateway-all/scm-gateway/src/main/java/com/pcitc/scm/gateway/filter/GatewayRewriterFilter.java`：网关全局过滤器，负责请求头、Token、路径等处理。
- `01zhaocai-end/scm-gateway-all/scm-gateway/src/main/java/com/pcitc/scm/gateway/config/GatewayConfig.java`：网关配置属性，对应 `scm.gateway.config`。

“过滤器”可以理解成安检口：请求进入服务前，先检查通行证、补充请求头、改写路径，再放行。

## 9. 你现在应该建立的整体印象

这个项目是一个供应链/采购商城类系统，采用 Spring Cloud 微服务架构。外部请求先进入 Vue 前端，再通过 Spring Cloud Gateway 进入后端服务；服务启动和服务发现依赖 Nacos；业务服务之间通过 Feign/HTTP 同步调用，也可能通过 RocketMQ 异步传递事件；数据主要落在 MySQL，热点数据和会话放 Redis，搜索和报表类能力会用 Elasticsearch。

可以把它想成一座商场：网关是总入口和安检，认证服务负责发通行证，UBM 管人员和组织，SRM 管供应商，Source 管采购寻源，Contract 管合同，Order 管订单，Product 管商品，MySQL/Redis/MQ/ES 是商场背后的仓库、便签、快递站和搜索台。
