# 工作规范与习惯（活文档）

> 记录公司规矩、用户习惯、协作约定。**任何 AI 发现新的可复用规矩就当场追加**（日期 + 工具代号 + 一行事实）。
> 旧条目被推翻时直接改写或删除，不留矛盾。用户也会直接改这份文件。

## 1. 用户画像与沟通方式

- Node/前端背景，不懂 Java/Maven/Spring，无法审查代码。**AI 的可信度 = 可验证性**：结论必须落到"某文件某行"或"一条查询结果"。
- 一律大白话；新技术名词第一次出现给比喻（驾驶舱=领导看的大屏；Jenkins=自动打包发布的流水线机器人）。
- 代码学习先讲业务全景和改动边界，再讲关键调用链、框架机制，最后按需解释 Java 语法；不要从文件第一行开始逐段翻译。
- 必须标明“本次新增 / 修改既有代码 / 项目或公司公共能力 / 第三方依赖”，用用户熟悉的 Node/前端技术类比时同时说明类比边界。
- 用户追问暴露出稳定认知缺口时，成熟解释回写同一份 `50-代码复盘与学习` 文档；以用户能复述主链路、说出边界并在 IDEA/Git/数据库重新定位证据为验收。
- 要用户去问人的，给**逐字话术** + 预判对面反问的应答表。
- 需要用户动手的事（点 Jenkins、复制 token、找人）**攒成清单一次性给**，过程中不零碎打断。

## 2. 分工边界

- AI 全包：读代码、查库（scripts/dbq.sh）、查 ES（scripts/esq.sh）、写代码、编译验证、git 提交推送、curl 测试（scripts/api.sh）、写所有文档。
- 只有用户能做：点 Jenkins 构建；和产品/领导/同事沟通；管理页面上的点击配置；提供/刷新凭据（ai-docs/creds.env 的 TOKEN）。
- **任务分级**：查任务（只读，不留档）／小改（写 `ai-docs/工作日志.md` 一条）／完整需求（全套交接文档）。细则见 skill 协作底座"任务分级"。

## 3. 公司规矩（已核实）

- **分支**：新需求从 prod 拉 feature 分支 → 开发提交并推送 → `merge --no-ff` 进 test（test 只是测试部署分支，不在 test 上直接写代码）。未上线功能的补丁基于 test 拉子分支（prod 上没有那些文件）。merge 会带脏历史时改用 `cherry-pick -x`。
- **分支命名（用户要求 2026-07-10）**：像人写的、参考团队风格（同事惯用拼音/缩写+姓名缩写如 zhq/bydw）；**一个大需求只开一个长期分支**，其下所有修改共用（如台账 `feature/taizhang-yang`，姓氏后缀 `-yang`）；不要一个小改动开一个新分支、不要 AI 味命名。
- **部署**：Jenkins（jenkins.jdsn.com）由用户点构建。scm-source-all 的任务参数：GIT_BRANCH=test、VERSION=1.0.0-JDSN-TEST-SNAPSHOT。K8s 控制台（KubeSphere，地址见 creds.env）看运行日志排错。
- **编译**：同事从不本地编译（跨模块 SNAPSHOT 漂移，全量编译本来就是坏的）。自己代码用隔离 javac 验证即可（skill env-playbook §6）。
- **鉴权**：平台接口登录即可调（permitAll 白名单 + anyRequest().authenticated()），菜单权限只管导航显隐 → 没配菜单也能 curl 先测。
- **数据库**：开发直连 test 库（凭据见 creds.env；业务库 scm_source_test、字典/组织库 scm_ubm_test）。prod 库不碰。
- **发版纪律（重要）**：正式发版时 SQL 和字典/导出模板配置都要**交给负责人执行/添加**，所以开发过程中必须把执行过的每条 SQL、每个字典项、每个模板配置**记录存档**（放本需求文件夹 `sql/`，按序号分：①DDL ②必需配置数据 ③演示数据单独成文件）。空表会让前端/大屏难看的场景（尤其驾驶舱）要备几条演示数据，演示数据是否进生产=高感知问题要问。
- **接口路径规矩（2026-07-21 cc 实测）**：网关**不剥前缀**，Controller 必须自己把完整路径写进 `@PostMapping`，形如 `e/business/source/<业务>/<方法>`（对外）或 `obs/business/source/...`（对内）。用 `scripts/api.sh POST /e/business/source/...` 调。
  **反例**：`scm-source-chase` 里旧的 `TradeDataReportController` 用 `/api/trade-data-report/...`，这种路径**网关根本路由不到**（实测 404，报错 path 显示 `/scm-source-web/e/business/source/api/...`），只是同事留的本地调试入口。新写接口不要照抄它，照抄 `e/business/source/chase/...` 那批。
  另注：往网关随便发一个不存在的路径可能返回 `{"status":true,"code":"000000","data":"ok"}`，**不要把这个当成调用成功**，要看返回内容是不是你接口自己的。
- **配置页面**：数据字典 `http://10.0.54.16:30370/ubm/index.html#/basicMgmt/dictionary`；导出 excel 模板 `http://10.0.54.16:30370/platform/index.html#/statics/list`。
- **菜单/岗位权限**：找群里的**张雨**配置。
- **提交风格（用户要求 2026-07-13）**：只用 `feat: 简短表述` 或 `fix: 简短表述`，只写一行、像同事随手提交。不要 scope 括号、正文要点、完成清单、`Co-Authored-By`，不要写得太详细、太工整；例如 `feat: 增加坑口台账`、`fix: 修复导出时间`。

## 4. 问题分级（什么问人、什么自行拍板）

**必须问**（阻塞或高感知）：
- 业务口径：数据从哪来/到哪去/两套数据听谁的/历史数据怎么办。
- 影响领导/产品直接看到的数字或页面效果。
- 跨团队接口字段（前端控件传什么）。
- 不可逆或动共享代码的操作。
问的时候给背景三句话 + 逐字话术 + 预设答案（把开放题变判断题）。

**自行拍板**（低感知 + 可逆 + 有行业默认）：
- 行业惯例：逻辑删除、金额两位小数、编码+名称双字段存储、显示用名称查询用编码。
- 内部实现选型（工具类、查询写法）、文案措辞、产品感知不到的细节。
- **拍板必须留痕**：写进 `10-拆解规划` 的"自行拍板记录"表（决定 + 理由 + 猜错的返工代价）。

## 5. 编译分级

- **可免编译**（说明理由即可）：只改注解字符串里的 SQL 文本、纯文档/SQL 脚本/配置、不新增 import 的字面量修改。
- **必须隔离 javac**：新增 .java 文件、新增 import/依赖、改方法签名、跨模块引用。命令见 skill env-playbook §6。
- 永远不要求修好全量 mvn 编译；报错文件全是别人的 = 环境漂移，不是我们的错。

## 6. 敏感信息纪律（红线）

- 全部凭据只存 `ai-docs/creds.env`（已 gitignore）。不进代码、不进提交、不进其他文档、不在聊天里要同事发密码。
- TOKEN 过期由用户从浏览器 F12 复制刷新（Copy as cURL 里 Authorization bearer 后面整串）。
- **禁止直接 `cat` 任何可能含令牌的配置文件**（2026-07-21 cc 教训）：`~/.npmrc`、`~/.m2/settings.xml`、`~/.docker/config.json`、`.git-credentials` 等都可能存明文 token。本次为查 npm 私服地址直接 `cat ~/.npmrc`，把 `_authToken` 打进了终端，已请用户轮换该 npm token。
  正确做法：只取需要的那一行且脱敏，如 `grep -o '^[^:]*//[^:]*' ~/.npmrc`（只看 registry 域名），或 `npm config get registry`。
- 前端项目的 `public/statics/config.js` 也可能有硬编码登录令牌；默认按敏感配置处理，不打印内容、不随需求代码提交，只看 `git status` 判断是否被改动。
- **禁止对 `source creds.env` 的脚本用 `bash -x` / `set -x` 调试**（2026-07-20 oc 教训）：trace 会把 DB/ES/K8S 密码和 TOKEN 全打印到终端，污染聊天记录。调试改用 `echo "$VAR"` 只看变量名是否为空，或临时把脚本里的 `source creds.env` 换成硬编码假值再 `-x`。
