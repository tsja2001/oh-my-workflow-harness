## 0. 三十秒速查表

| 我想干什么 | 怎么做 |
|---|---|
| 这个业务（方案/计划/合同…）有没有审批流、回调到哪 | `bash scripts/wf.sh biz [test\|uat]`（=业务库 `scm_ubm_<env>.scm_wf_template`） |
| DPS 上现在有哪些流程模板 | `bash scripts/wf.sh templates [env] [关键字]`（live 控制台 API） |
| 某业务实际起流程时用的是哪个模板码（四级降级结果） | `bash scripts/wf.sh records [env] [业务类型]`（`scm_wf_template_record` 按 `template_start_code` 聚合） |
| 流程分支条件能引用哪些变量 | `bash scripts/wf.sh metas [env]`；业务侧塞值的代码见 §4 |
| 现在全平台有哪些单子卡在审批、卡在谁手里 | `bash scripts/wf.sh todo [env] [条数]`（DPS 待办监控） |
| 一张单子的流程走到哪了 | `bash scripts/wf.sh trace <businessId> [env]`；要看得更细用控制台（下行） |
| 亲眼看流程图 / 查审批历史（人工操作） | `bash scripts/wf.sh open [env]` 打印入口；登录填法见 §1 |
| 环境体检（能不能连上/登上的总开关） | `bash scripts/wf.sh doctor` |
| 新单据要接审批流，改哪几个地方 | 见 §6「新接一种单据的固定套路」 |

## 1. 控制台入口（人工看图、查实例用）

## 2. 一页架构（谁在干活）

```
业务服务(scm-source/srm/product/order/contract/professor/devops)
  │  Feign: scm-workflow-feign → scm-workflow-web(9800, 代理不是引擎)
  │  起流程: /c/business/workflow/dps/processStart (异步: 先落库+MQ)
  ▼
scm-workflow-web
  │  查 scm_wf_template(business_type) 定模板码 → 四级降级拼码(见§3)
  │  HTTP+Basic: POST {dps.url}/init/start  (dps.url 在 Nacos scm-workflow-web.yaml)
  ▼
DPS 引擎(独立产品, K8s: scm-workflow-dps, 控制台 dps.scmflow-*.jdsn.com)
  │  需要选人时反查招采: /obs/business/workflow/user|org|role|position/* (scm-workflow 提供)
  │  节点办完回调: /obs/business/workflow/callBack/* 或 /wf/approve*Callback
  ▼
scm-workflow-web 收回调 → wf_instance + MQ(WORKFLOW_FINISH)
  → 按 scm_wf_template_record.callback_method 三段式(app-模块-方法)
  → AIM 引擎反射调用业务方 @TypeMapping/@MethodMapping 方法(如 approveScheme)
  → 业务更新单据状态(通过/驳回)
```

要点：**审批几级、谁审，不在这套 Java 代码里**——是产品/实施在 DPS 控制台画流程图配的；
代码侧只负责①把分支变量（metas）传过去 ②接回调改状态。

## 3. 模板路由：businessCode 怎么变成具体流程

1. 业务方起流程只传 `businessCode`（如 `SCHEME`）+ 变量；`categoryCode` 一律不传。
2. scm-workflow 查 `scm_wf_template`（`template_version=1`，多条时用 `use_template_code=1` + 传码匹配）拿到 `template_code`。
3. `sign_version=1`（新模板）时按**四级降级**在 DPS 找图（`DPSProcessServiceImpl.tenantWorkflowTemplate`，
   dps 工程码 `01zhaocai-end/scm-workflow-all/.../DPSProcessServiceImpl.java:1370`）：
   `码-BU-AUTHLEVEL-ORG` → `码-BU-AUTHLEVEL` → `码-BU` → `码`（机构模板 ownKind=0 优先，公共模板 organiseId 固定 `#templateorgId#`）。
   BU/AUTHLEVEL/ORG 取自**发起企业**在 `ubm_organization_manage` 的 `belong_bu_code/auth_level/org_code`。
4. 实际命中的码回写 `scm_wf_template_record.template_start_code`——**查真值用 `wf.sh records`，别靠猜**。
5. 【推断】DPS 引擎内部还有一层应用映射（`dps_wfd_appmapping`）：test 待办里 2023 年老单显示
   `CGFA_SP_01`（采购方案的老编码）而业务侧送的是 `SCHEME`——映射表在线上引擎库里，本机
   `dps_test` 库是旧库没数据（无法证实：线上库位置未核实，见 10-调查 §7）。

## 4. 流程变量（分支条件的数据来源）

- 定义在 DPS「字段管理→字段定义」（`wf.sh metas`，test 现 13 个：isCollection、memberCode、
  biddingType、isRegionPur、isEntrust、estimatedAmount、signEstimatedAmount、isAllPlan、taxTotal、
  totalAmount、isExpired、yunweiType、isAutoApproval）。
- 塞值代码在业务侧 Builder：`01zhaocai-end/scm-source-all/scm-source-wf/.../SourceWorkflowAdapterBuilder.java`
  （isCollection 在 :156/:235/:319 一带）。**加新变量 = 照抄一段 AppMetasData + DPS 字段定义页加字段 + 流程图里引用**。
- 注意 GreenChannel（非平台录入）单独塞 `isCompany`/`totalAmount`（`..._GreenChannel.java:129-172`），
  和方案/计划不共用那套变量。

## 6. 新接一种单据的固定套路（改哪几处）

1. `scm-workflow-base-api/.../enums/WfBusinessTypeEnum.java` 加枚举（code 别学 COSTPAY 写裸字符串）。
2. 业务仓加一个 `XxxWorkflowAdapterServiceImpl_<Type>`（照 `..._Scheme.java` 抄：组装 ProcessStartAO + metasList + extMap）。
3. `scm_wf_template` 配一条：business_type=新码、`callback_method` 三段式 `<app>-<typeMapping>-<methodMapping>`（如 `source-schemeService-approveScheme`）。
4. 业务 Service 接口方法标 `@TypeMapping`/`@MethodMapping` 接收回调（CallbackApproveAO，approveResult 101=通过/102=退回）。
5. 产品/实施在 DPS 控制台画流程图（模板分类→机构模板→画图→发布），变量引用 metas。
6. 提醒：`/processStart` 是**异步**的——提交成功 ≠ DPS 已有流程，卡在 0 看 `wf_instance.ins_status`。

## 7. 常见排查场景

| 症状 | 先看哪 |
|---|---|
| 单子提交了没审批/没待办 | `wf.sh trace <id>` 看 wf_instance 两行有没有、ins_status；卡 0 = MQ 消费失败，去 K8s 看 scm-workflow-web 日志 |
| 审批通过了业务状态没变 | 回调链断了：wf_instance 有没有 WORKFLOW_FINISH；record 的 callback_method 三段式对不对；业务方 AIM 方法有没有报错 |
| 待办列表有单子点进去报错 | businessId 前缀约定（ext018/019/020 那套，见 10-调查 §5） |
| test 和 uat 流程不一样 | `wf.sh templates test X` vs `templates uat X` 对比；模板是逐环境手工配的，**不会自动同步** |
| 要知道"这个流程几级、谁审" | `wf.sh open` 人工看图，或 `wf.sh todo` 看同类单当前卡在哪些节点（activityName 列就是节点名） |
