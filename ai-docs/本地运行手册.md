# 本地运行手册（编译 / 起服务 / 前端构建 / IDE）

> 什么时候读：要验证自己写的 Java 代码、要在本机把服务跑起来调接口、要构建前端、要配 IDEA 的时候。
> **先看 §0 的一句话结论**，多数情况一条命令就够了，不用往下读。

## 0. 一句话结论

| 我想干嘛 | 一条命令 |
|---|---|
| 验证我改的 Java 代码没问题 | `bash scripts/jc.sh <仓库目录> <改过的.java 文件...>` |
| 本机跑起 scm-source 调接口 | `bash scripts/srun.sh build` → `start`（**必须后台运行**）→ `wait` → `status` / `logs` / `stop` |
| 验证前端改动 | 进对应仓 `npm run build`（**不要用 `npm run lint`**，插件没装，会报 `command "lint" does not exist`） |
| 跑一小段 Java 试验 | 写 `/tmp/*.java` 再 `javac` + `java`（**本环境没有 `jshell`**） |

## 2. 隔离编译（Phase 6 的落地）

**先分级**：改注解字符串里的 SQL、纯文档/SQL/配置、不新增 import 的字面量修改 → **可免编译**（说明理由即可）。
新增 `.java`、新增 import/依赖、改方法签名、跨模块引用 → **必须隔离编译**。

```bash
bash scripts/jc.sh 01zhaocai-end/scm-source-all \
  01zhaocai-end/scm-source-all/scm-source-chase/src/main/java/.../XxxServiceImpl.java
```

实测耗时：`scm-report-all` 约 7 秒，`scm-source-all` 约 32 秒。
脚本会**自动区分"你的文件的报错"（退出码 1，必须修）和"别人文件的环境漂移报错"（退出码 0，可忽略）**。

### 脚本替你封掉的三个坑（自己手拼 javac 时会全踩）

1. **classpath**：`mvn dependency:build-classpath` 在本环境走不通（3.8.7 封 http + 反应堆兄弟模块没发到 Nexus，`-pl` 解析必失败）。
   可行法是直接拼：`find ~/.m2 -name '*.jar'` 全量 + 兄弟模块 `target/classes`。classpath 超命令行长度限制，用 `@argfile` 传参。
2. **`-sourcepath` 的目录层数**：`模块/src/main/java` 在第 4 层，`find -maxdepth 3` 会**静默取空**，
   导致 argfile 参数错位，报莫名其妙的 `invalid flag`。（argfile 里任何一个选项的值为空都会引发同类错位。）
3. **javac 只对显式列在命令行上的源文件跑注解处理器**——这是最要命的一条。
   Lombok `@Data` 实体如果只靠 sourcepath 隐式加载，**getter 一个都不生成**，会报一大片
   `cannot find symbol` / `invalid method reference`，极易误判成自己写错（首次遇到时 372 行报错，实际代码没问题）。
   → 用到的实体源码（`Source.java` / `DealDetail.java` / `SupplierGreenChannel.java` 之类）必须一并**显式列在 javac 后面**。
   另外，兄弟模块 `target/classes` 里的实体常是**旧版缺新字段**，显式交源码也能让最新定义覆盖旧 class。

## 3. 本地起 scm-source（连 test 的 Nacos/库/ES）

```bash
bash scripts/srun.sh build [模块]   # 改了某模块：装该模块到 .m2 + 重打 fat jar（默认 scm-source-chase，各约 1 分钟）
bash scripts/srun.sh start          # ★ 必须经 Bash 工具 run_in_background=true 调用
bash scripts/srun.sh wait           # 前台轮询到 Started/8110（最多约 150s）
bash scripts/srun.sh status | logs [n] | stop
```

### 三条铁律

1. **绝不能 `nohup java &` 塞进一次性的 `wsl.exe -- bash 脚本`。**
   wsl.exe 一返回，WSL 就回收该后台进程——日志 0 字节、进程秒死，排查能白费半天。
   正解是脚本里前台 `exec java`，由 Bash 工具的 `run_in_background=true` 持有 wsl.exe 保活。
2. **不改仓库任何 git 跟踪文件。** 别靠改 pom / 改 `application.yml` 来"修"问题。
   所有适配只走三处：① 本机 `~/.m2` 缓存；② 外部 `-D` / 环境变量；③ 分支切换（要用户确认）。
3. **点火绝不能漏 `register-enabled=false`**，否则本机实例会被登记进目标环境的服务发现，**可能劫持真实流量**。
   固定参数：`APP_PROFILE=test` + `-Dnacos.ip=<test nacos>` + `register-enabled=false` + fastjson safeMode（脚本已内置）。

### 心智模型

- **源码层** `01zhaocai-end/scm-source-all`（47 模块反应堆，主业务）
- **启动壳层** `03zhaocai-start/scm-cloud-starters-web/scm-cloud-source`，主类 `com.pcitc.scm.source.starter.SourceApp`，
  fat jar `target/scm-source-web.jar`（约 242MB），端口 `8110`，context `/scm-source-web`
- **运行环境层**：配置/DB/ES/Redis/MQ 全在 Nacos `scm-jdsn-<env>`，本机 resources 只有 bootstrap，没有 `application-*.yml`。
  **跨服务（auth/dict/order/gateway）不在本地起**——它们在目标环境集群里跑，Pod IP 从本机可达，本地实例作为消费者带 token 直接调。

改单模块只需 `mvn -pl <模块> install` + `mvn -pl scm-cloud-source package`，**不用全量 47 模块**。
更细的排障信号与副作用管控见 `docs/需求/07开发本地运行java环境/`（10 号是机械步骤，13 号是心智模型）。

## 4. 前端构建

- 版本必须对：Node `14.21.3` / npm `6.14.18`。
- **私服地址**：公网源会因私有包（如 `scm-table@1.0.1-jdsn-beta`）报 `ETARGET`；
  文档里的 `nexus.jdsn.com` **不可用**、`nexus.jdsn.com.cn` 拉 npm 包返回 **502**；
  可用的是锁文件里那个内网地址 `10.0.66.31:50118/repository/npm-jdsn-public/`。
- 验证方式是 `npm run build`（`npm run lint` 在 `scm-vue-all-procurementscheme` 和 `scm-vue-hpc` 上都不可用）。
- **Node 14 项目里不要直接调全局 `playwright-cli`**：它装在 mise Node 24 下，受当前 nvm Node 14 影响会报 `Unexpected token '??='`。
  要用就显式用 Node 24 跑 CLI 并传 `--browser=chromium`，项目本身保持 Node 14。
- `public/statics/config.js` 按敏感文件处理：不打印内容、不随需求代码提交（[安全红线 §2](安全红线.md)）。

## 5. IDEA（Windows 侧 IDEA + WSL 代码）

- 项目 SDK：`corretto-1.8 Amazon Corretto 1.8.0_492`，语言级别 `8`。每个模块的"模块 SDK"都用"项目 SDK"，
  **不要让某些模块单独用 Java 11/17**。
- **WSL Maven 的 localRepository 陷阱**：如果 WSL 的 `settings.xml` 显式写了 `/home/t/.m2/repository`，
  IDEA 2026.1 可能误转成 `C:\home\t\.m2\repository`，WSL 又把它当相对路径，于是在项目根生成一个同名字面目录。
  → 去掉 `localRepository` 显式项、用 WSL 默认仓库，并关闭 IDEA 的"本地仓库"覆盖，再重新加载 Maven。
