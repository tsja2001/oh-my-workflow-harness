# 前端页面定位 —— 「这个功能/这个接口，对应前端哪个页面文件」

> 建立日期：2026-08-07 ｜ 工具：cc ｜ 入口脚本：`scripts/fe.sh`
> 适用：任何 AI 接到「帮我找某个服务/功能对应的前端页面」「这个接口是哪个页面在调」「这个页面的代码在哪」。
> **动手前先看这里，别上来就全树 grep。**

---

## 0. 先看这个：三条最常用的命令

```bash
bash scripts/fe.sh find 坑口                     # 知道中文名，找页面文件
bash scripts/fe.sh api pageListAgg_collectionProduct   # 知道接口，反查是哪个页面
bash scripts/fe.sh url '/procurementScheme/index.html#/xxx/yyy'   # 手里有浏览器地址
```

输出直接给到「菜单中文名 / URL / 前端仓库 / 路由定义第几行 / .vue 文件路径」，可以直接 Read。

---

## 1. 为什么需要这个东西（别跳过，这几条解释了以前为什么老找不着）

| 难点 | 具体情况 |
|---|---|
| 仓库多且重复 | `02zhaocai-front/` 下 **27 个前端仓**，另外 `scm-vue-all/` 里还有 **25 个同名旧仓**。同一个页面在新旧两处都能搜到，搜到旧的就白改了 |
| 路由多 | 全部 **1274 条**路由，其中顶层新仓 746 条 |
| 中文↔英文断层 | 菜单是中文（「集采物资报表查询」），代码里全是英文（`collectionProduct`），关键词对不上 |
| URL 前缀不等于仓名 | 页面地址是 `/procurementScheme/index.html#/...`，但 `vue.config.js` 里 `publicPath` 全是 `'./'`，**配置里根本没有这个前缀**，它是 nginx 部署目录名。所以没法从配置反推仓库 |
| 有一类页面代码里根本没有 | 「动态页」的路由是 `/dynamicPage/:module/:type` 这种壳子，页面长什么样、调哪些接口，全写在**后端下发的 JSON 配置**里。在前端源码里搜接口名 → 永远搜不到 |
| 本地分支会骗人 | 各前端仓可能停在某个交付分支上（例如 `scm-vue-all-procurementscheme` 现在是 `taizhang-prod-yang`），页面在别的分支上就是"找不到" |

`fe.sh` 把这些一次性解决：**离线三张表 + 一张动态页接口表**，查的时候不用登录、不用全树搜索、秒回。

## 2. 数据从哪来 / 四张表

`bash scripts/fe.sh build [test|uat]` 生成，约 3 秒。生成物都在 `ai-docs/`，已随文档仓提交，**新会话的 AI 可以直接 grep，不用重新 build**。

| 文件 | 内容 | 规模 |
|---|---|---|
| `前端页面地图.tsv` | 菜单中文全路径 → URL → 仓库 → 路由定义位置 → .vue 文件 | 156 条叶子菜单 |
| `前端路由索引.tsv` | 全部路由 → 仓库 → 路由定义位置 → .vue 文件（含菜单里没有的详情页/弹窗页） | 1274 条 |
| `前端上下文对照.tsv` | URL 里的 `/xxx/index.html` → 哪个前端仓库 | 20 个 |
| `前端动态页接口.tsv` | 动态页/报表页 → 它实际会调的后端接口（从配置 JSON 抓的） | 30 条 |

怎么对上号的：

```
菜单树接口 /c/business/ubm/MenuMgr/queryMenuTree
        ↓ 拿到 156 条「中文菜单名 + 页面URL」
   URL：/procurementScheme/index.html#/businessManagementLedgerJC/coalPitDailyIndicator
        │                              └─────── 路由（# 后面这段）
        └─ URL 上下文
        ↓ 拿路由去 52 个仓的 src/router/*.js 里精确匹配
   命中：scm-vue-all-procurementscheme/src/router/index.js:719
        ↓ 顺着那条路由的 component: () => import('../views/...')
   页面：src/views/businessManagementLedgerJC/coalPitDailyIndicator/index.vue
```

**多仓命中怎么裁决**（脚本已内置，知道原理便于判断可信度）：
1. 精确路由命中 → 顶层新仓优先于 `scm-vue-all/` 旧聚合仓；
2. 用第 1 步的结果给「URL 上下文 → 仓库」投票，得到可信的对照表；
3. 只有壳子路由能命中的（动态页），按第 2 步的对照表选仓；
4. 一条精确路由都没有的上下文（如 `expertMgt`，本地压根没克隆这个前端仓）→ 按仓名猜，表里明写「按仓名猜」，**别当结论用**。

## 3. 各子命令

### `find <关键词>` —— 最常用

中文菜单名、路由、文件名都能命中。分两段输出：先是有中文名的正式菜单页，再是路由索引里的命中（含菜单里没有的详情页）。

```bash
bash scripts/fe.sh find 坑口
bash scripts/fe.sh find 集采          # 中文名不确定就用短词，别用长句
bash scripts/fe.sh find coalPit
```

> 关键词要短。菜单叫「集采物资报表查询」，你搜「集采报表」是搜不到的；搜「集采」就全出来了。

### `url <页面URL或路由>` —— 手里有浏览器地址栏那串

```bash
bash scripts/fe.sh url '/procurementScheme/index.html#/businessManagementLedgerJC/coalPitDailyIndicator'
bash scripts/fe.sh url '#/dynamicPage/report/collectionProduct'
```

参数化路由（`/reportForms/:purchaseRepot`）会自动套上，不用自己换算。

### `api <接口路径片段>` —— 后端接口反查页面

```bash
bash scripts/fe.sh api '/e/business/source/collectionDailyAmountLedger'
bash scripts/fe.sh api pageListAgg_collectionProduct
```

两路一起查：① 在前端源码里 grep 谁在调（自动排除 `node_modules`、`dist`、`router`）；② 查动态页接口表（这些接口在源码里搜不到）。找到文件后再顺着路由索引反推它属于哪个菜单。

> 搜不到就把关键词**改短**：前端常把接口路径拆成常量再拼接（`const API='/e/business/source/coalPitDailyIndicator'` 然后 `API+'/queryPageList'`），搜全路径会落空，搜 `coalPitDailyIndicator` 就中。

### `json <module>/<type>` —— 动态页专用

```bash
bash scripts/fe.sh json report/collectionProduct
```

输出这个页面会调哪些后端接口、有哪些表头字段。相当于把"看不见的页面定义"拉出来。

### `repo <URL上下文>` / `build [test|uat]`

```bash
bash scripts/fe.sh repo procurementScheme    # 这个前缀是哪个前端仓
bash scripts/fe.sh build test                # 重建四张表
```

**什么时候要重新 build**：切过前端分支、拉过新代码、菜单加了新页面。平时不用。

## 4. 两类"代码里找不到页面"的情况（重点）

### 4.1 动态页：页面定义在后端 JSON 里

菜单 URL 长这样 `#/dynamicPage/<module>/<type>`（还有 `dynamicMultipleTabs` / `dynamicReportPage` / `dynamicChart` / `dynPage` 几个变体）。

前端只有一个通用壳子 `src/views/dynamicPage/index.vue`，它开局请求：

```
GET /obs/json/plateform/<module>/<type>
```

拿回来的 JSON 里有 `headers`（表头）、`buttons`（按钮）、`initUrl` 和 `urls`（这个页面调哪些后端接口）。**页面长什么样、查什么接口，全在这份 JSON 里，改页面也是改这份 JSON，不动前端代码。**

配置的管理入口是菜单「平台管理 / JSON管理」（`/platform/index.html#/dynPage/staticdataCategory/tree`）。

真实例子（就是 2026-08-07 煤炭那个问题里的接口）：

```
菜单「报表查询 / 集采物资报表查询」
  URL   /procurementScheme/index.html#/dynamicPage/report/collectionProduct
  壳子  scm-vue-all-procurementscheme/src/views/dynamicPage/index.vue
  配置  /obs/json/plateform/report/collectionProduct
  接口  /e/business/report/source/pageListAgg_collectionProduct
        /e/business/report/source/aggComapny_collectionProduct
  后端  scm-report-all/scm-report-source/.../SourceQueryBuilderImpl_CollectionProduct.java
```

### 4.2 报表页：接口名是按路由参数拼出来的

菜单 URL `#/reportForms/<flag>`，路由是 `/reportForms/:purchaseRepot`，页面 `src/views/reportForms/index.vue`。它按 `<flag>` 拼接口：

```
/e/business/report/source/headList_<flag>       表头
/e/business/report/source/agghead_<flag>        聚合表头
/e/business/report/source/aggregation_<flag>    数据
/e/business/report/source/download_<flag>       导出
```

后端对应 `scm-report-source` 里的 `SourceQueryBuilderImpl_<Flag>`（`businessClass()` 返回的就是这个 flag）。所以看到 `xxx_collectionProduct` 这种接口名，`_` 后面那段就是页面标识。

## 5. 已知边界（表里会明写，别当 bug 报）

| 现象 | 含义 | 怎么办 |
|---|---|---|
| 「本地前端仓没有这条路由」 | 该前端仓没克隆，或**本地当前分支不含这个页面** | `git -C 02zhaocai-front/<仓> branch -a \| grep <关键词>` 看是不是在别的分支；例如集采台账那 3 个页面就只在同事的交付分支上 |
| 「仓库是按名字猜的」 | 这个 URL 上下文一条精确路由都没命中 | 目前只有 `expertMgt`（专家系统前端本地没克隆）、`supplierworkbench`、`workbench` 三个 |
| 「动态页(壳子路由...)」 | 定位到的是通用壳子，不是真正的页面内容 | 用 `fe.sh json <module>/<type>` 看配置 |
| 菜单树只有 156 条 | 菜单接口按**登录账号的角色**返回，admin 账号能看到的就这些 | 供应商端/专家端的页面可能缺；缺的用 `fe.sh find` 走路由索引那一段找 |
| 只覆盖招采平台 | 云采平台（`--platform cloud`）是另一套菜单，目前没纳入 | 需要时 `fe.sh build` 里换平台再抓一份 |
