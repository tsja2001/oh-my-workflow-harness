# 安全红线（细则）

> AGENTS.md §1 是必须背下来的六条；本文是**怎么做、为什么**的细则。踩过的都是真实事故，不是假想。

## 1. 凭据

- 数据库、网关、登录账号、K8s、Nacos、Jenkins、调度平台的凭据**只存 `ai-docs/creds.env`**（已 gitignore）。
  不进代码、不进提交、不进其他文档、不在聊天里要同事发密码。
- 业务 TOKEN 由 `scripts/auth.sh` 自动登录并缓存到 `ai-docs/.auth-cache/`（目录 700 / 文件 600，同样 gitignore）。
  `scripts/api.sh` 遇到 HTTP 401、`900301`、`ERROR_JWT_INVALIDITY`、`ERROR_JWT_401` 时自动重登并**只重试一次**。
- `creds.env` 里凭据值含 `$` 必须用单引号包裹（文件会被 bash `source`，`KEY=abc$XYZ` 会把 `$XYZ` 当变量展开，`set -u` 下直接报错）。
- 不要从项目文档站、代码默认值、Jenkins 日志或聊天记录里"补猜"凭据。

## 2. 禁止的调试与读取动作

| 禁止 | 原因 | 正确做法 |
|---|---|---|
| 对 `source creds.env` 的脚本用 `bash -x` / `set -x` | trace 会把 DB/ES/K8S 密码和 TOKEN 全打到终端，污染聊天记录（2026-07-20 oc 实际发生，已请用户轮换） | `echo "$VAR"` 只看变量是否为空；或临时把 `source creds.env` 换成假值再 `-x` |
| 直接 `cat` 可能含令牌的配置文件 | `~/.npmrc`、`~/.m2/settings.xml`、`~/.docker/config.json`、`.git-credentials` 都可能存明文 token（2026-07-21 cc 实际泄露了 npm token，已轮换） | 只取需要的那一行并脱敏：`npm config get registry`、`grep -o '^[^:]*//[^:]*' ~/.npmrc` |
| 打印前端 `public/statics/config.js` 内容 | 可能有硬编码登录令牌 | 默认按敏感配置处理：不打印、不随需求代码提交，只用 `git status` 判断是否被改动 |
| 把 token/Cookie 写进命令文本、文档或提交 | 会进 git 历史，删不掉 | 临时手工请求也只能让 shell 从受控缓存读 token |

## 3. 写操作与生产边界

- **远程 git**：`push`、动远程分支、提 MR 一律要用户当次明确同意。顶层文档仓和公司子仓都算。
- **生产**：prod 库、prod K8s、Jenkins 构建按钮、`mvn deploy` 到 Nexus，AI 一律不执行，只准备逐步骤清单交给用户/运维。
- **生产平台浏览器通道**（`scripts/browser-ro.sh`）是**只读**的：网络护栏放行登录和查询，拦截构建、执行、保存、发布、启停及一切增删改请求。
  **禁止绕过 `scripts/browser/readonly-guard.js`**。
- `skills/diagnose-scm-project` 全程只读：不触发构建、不重启/伸缩/删除 K8s 资源、不进容器、不发布 Nacos 配置、不启停任务、不写 MySQL/ES。
  证据指向要改东西时，停下来交给 `enterprise-dev-workflow` 或给用户准确的界面步骤。
- **生产 namespace 不从目录名猜**。`si-scm-product` 不能直接认定为生产（历史核查中主后端多为 0 副本，Jenkins 也没有常规 `*-web-prod` 任务）。

## 4. 数据库写操作纪律

- 写脚本默认**不 COMMIT**：先在事务里试跑看命中行数，异常先在同一连接 `ROLLBACK` 并反查旧值，再改脚本重跑。
- 每条改数据的 SQL 都要配一份**回滚 SQL**，一起存进主题文件夹 `sql/`（历史上 `bug处理/sql/` 就是修复+回滚成对存放）。
- 删数据要看清链路：**只删 ES 不够，定时任务会从源表同步回来**（2026-08-06 oc 实际踩过，源表和 ES 都要处理）。

## 5. Git 危险操作

- **查看/搜索其他分支的代码一律 `git show <分支>:<路径>` 或 `git grep <模式> <分支> -- ...`**。
  **严禁 `git checkout <分支> -- .`**——它会把该分支全部文件写进当前工作区并暂存进 index。
  2026-08-06 oc 因此把一个分支 138 个文件写进了另一个分支的工作区，靠 `git reset HEAD -- .` + `git clean -fd` 恢复，只花 10 秒但极险。
- 危险操作前先建本地 `backup/<说明>` 分支和 `.patch` 补丁文件。
- 多仓库工作区：**顶层目录可能根本不是那个 git 仓库**。`01zhaocai-end` 只是多个独立 Git 仓的容器目录，
  在它里面直接 `git show origin/test` 会误落到顶层文档仓并报"无此引用"；必须 `git -C 01zhaocai-end/scm-<业务>-all ...` 或进子仓。
