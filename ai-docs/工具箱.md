# 工具箱（有现成的就别自己拼命令）

> **动手前扫一眼这张表。** 这里每一个脚本都是因为某次踩坑才做出来的——自己手拼 curl / javac / SQL 会把那个坑重踩一遍。
> 所有脚本都自动读 `ai-docs/creds.env`，**不需要也不允许你自己传密码或 token**。

## 0. 接手一个新会话，先跑这条

```bash
bash scripts/doctor.sh            # 30 秒：工具链 / 凭据 / test 库 / ES / 每个公司子仓在哪个分支、脏不脏
bash scripts/doctor.sh --fetch    # 开工前再跑一次：真的 fetch，看有没有落后远端（skill Phase 4 的基线核对）
bash scripts/doctor.sh --auth     # 顺带做业务接口登录体检
```

**为什么值得跑**：历史上翻过的车里有两类是它专治的——
① 在一个比已部署 test 少两个提交的本地分支上开发了一轮，合回去才发现，白做；
② 子仓工作区是脏的却没注意，提交时夹带了别人的改动。

## 1. 查东西

| 想干嘛 | 命令 |
|---|---|
| 查 MySQL | `bash scripts/dbq.sh "SELECT ..." [库名]`，也可以传 `.sql` 文件 |
| 查 Elasticsearch | `bash scripts/esq.sh` (列索引) ／ `indices` `mapping` `count` `head` `one` `search` `agg` `get` `post` |
| 调业务接口（招采/云采，token 自动登录） | `bash scripts/api.sh POST /e/business/source/xxx '{"a":1}'` |
| 登录体检 / 强制重登 | `bash scripts/auth.sh doctor｜status｜login [test\|uat] [admin\|supplier]` |
| 找前端页面文件 | `bash scripts/fe.sh find <中文关键词>` ／ `api <接口片段>` ／ `url <页面地址>` ／ `json <module>/<type>` ／ `repo <URL上下文>` |
| 字段体检（填充率/分布/时间窗口） | `bash scripts/fieldcheck.sh <表> <字段> [库]` |

**`api.sh` 的可选参数**：`--env test|uat`、`--platform procurement|cloud`（也认 `zc`/`yc`）、`--account admin|supplier`。
默认 `test + 招采 + admin`，所以旧命令完全兼容。业务响应为 401 / `900301` / `ERROR_JWT_INVALIDITY` / `ERROR_JWT_401` 时**自动重登并只重试一次**。

**省 token 原则**：查 ES 先 `indices` 认索引 → `mapping` 认字段 → `head`/`one`/`search` 取数据。
不要上来就 `_search?size=1000` 把全表拉回来；统计用 `agg`，比 `search` 后再 jq 处理省 10 倍 token。

## 2. 写代码 / 验证

| 想干嘛 | 命令 |
|---|---|
| 隔离编译（证明自己的 Java 代码没问题） | `bash scripts/jc.sh <仓库目录> <改过的.java 文件...>` |
| 本地起 scm-source 调接口 | `bash scripts/srun.sh build｜start｜wait｜status｜logs｜stop` |

细节和坑见 [本地运行手册.md](本地运行手册.md)。

## 3. 排查线上问题（skill，不是脚本）

**症状驱动，先跑命令别先猜。** 入口 `skills/diagnose-scm-project/SKILL.md`，全程只读。

```bash
PROJECT="skills/diagnose-scm-project/scripts/project.sh"
bash "$PROJECT" doctor                                   # 先体检
bash "$PROJECT" trace api '/d/business/order/xxx/queryPage'   # 这个接口归谁管、代码在哪
bash "$PROJECT" trace page '/procurementScheme/index.html#/xxx'
bash "$PROJECT" diagnose release uat order               # 这次发布到底有没有到 K8s
bash "$PROJECT" diagnose runtime uat order               # Pod 健康吗
bash "$PROJECT" diagnose task uat order 216              # XXL-JOB 那次执行到底错在哪
bash "$PROJECT" compare config order test uat            # 哪些 Nacos key 不一致（不打印值）
bash "$PROJECT" ownership order centralPurchaseStatistics
```

需要更细的单项证据时才下沉到 `skills/diagnose-scm-project/scripts/platform.sh`（`k8s logs` / `k8s eslogs` / `jenkins evidence` / `nacos keys` / `scheduling jobs` / `docs search`）。

## 4. 只读浏览器通道

`bash scripts/browser-ro.sh` —— 需要看调度平台 / Nacos / Jenkins 页面时用。
各环境独立 profile，网络护栏放行登录和查询，**拦截构建、执行、保存、发布、启停及一切增删改**。
**禁止绕过 `scripts/browser/readonly-guard.js`**。Jenkins 从 WSL 直连会 502，统一走 Windows Chrome 桥接。

## 5. 什么时候该做一个新脚本

**判据：同一类操作做到第二遍，如果还要回忆参数、路径、顺序，或者要翻文档——这是工具缺口，不是记忆缺口。**

实证：`dbq.sh`/`esq.sh` 存在之后，查库查 ES 全程零事故；
而"隔离编译要显式列 Lombok 实体"这条**只写在文档里**，换个仓库照样重踩——直到做成 `jc.sh` 才真正封住。

发现缺工具就**直接告诉用户**（用户明确说过"别心疼提要求"，装一个工具往往省几十次绕路）。
新脚本放 `scripts/`，头部写清用法和它封掉的坑，然后在本文件加一行。

## 附：各脚本诞生原因（一句话）

| 脚本 | 封掉了什么 |
|---|---|
| `dbq.sh` | 每次手拼 mysql 连接参数；没装客户端时还要写 Java JDBC |
| `esq.sh` | 每次手拼 curl 查 ES，且容易一次拉回全表烧 token |
| `auth.sh` / `api.sh` | TOKEN 过期要用户去 F12 复制（现在全自动，用户不用管了） |
| `fe.sh` | 52 个前端仓（新旧同名）硬搜必踩错仓；URL 前缀不在任何配置里；「动态页」源码搜不到 |
| `fieldcheck.sh` | 需求指定的筛选字段其实几乎没数据，做完才被产品发现（真实案例返工三轮） |
| `jc.sh` | 全量 mvn 编译本来就是坏的；手拼 javac 有 classpath/sourcepath/Lombok 三个必踩的坑 |
| `srun.sh` | `nohup java &` 在 wsl.exe 一次性调用里会秒死；启动参数漏 `register-enabled=false` 会劫持真实流量 |
| `browser-ro.sh` | 需要看生产平台页面，又必须保证绝对不会误点写操作 |
| `doctor.sh` | 每个新会话都要手敲一遍的开工探针（环境/凭据/连通性/分支基线），且最容易漏掉"我是不是在陈旧分支上开发" |
