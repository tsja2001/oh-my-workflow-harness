> 什么时候读：接到一个接口路径 / 页面地址 / 报错，要判断"这归谁管、去哪查、连哪个库"的时候。

## 1. 两个业务平台

| 平台 | 是什么 | 网关路径前缀 | `api.sh` 参数 |
|---|---|---|---|
| **招采**（zc / procurement） | 主平台：寻源、招投标、订单、合同、供应商 | `/e/business/...` | `--platform procurement`（默认） |
| **云采**（yc / cloud） | 商城化采购 | `/c/business/...` | `--platform cloud` |

其他前缀（实测规律）：`/d/business/...` 内部/驾驶舱类查询，`/obs/...` 服务间对内调用。
**网关不剥前缀**——Controller 必须自己写完整路径，详见 [团队规矩 §6](团队规矩.md)。

## 2. 四套环境

| 环境 | 谁能动 | 干什么用 |
|---|---|---|
| **dev** | — | 基本不用 |
| **test** | AI + 用户随便动 | 日常开发、改数据、调接口、配字典/模板/菜单 |

### K8s / Nacos 命名规律

- Namespace：test = `si-scm-product-test`，uat = `si-scm-product-uat`。
  **prod 的 namespace 必须问运维，不从目录名猜**——`si-scm-product` 不能直接认定为生产。
- Nacos：namespace `scm-jdsn-test` / `scm-jdsn-uat` / `jdsn-prod`，group 固定 `common`，
  Data ID = `<spring.application.name>-<profile>.yaml`，例 `scm-source-web-test.yaml`。
- **K8s 日志有两条链路**：
  `k8s logs` 走 Pod log API，看**存活容器**的实时日志；
  `k8s eslogs` 走 KubeSphere 日志查询 API（集群 fluent-bit 全量采集进 ES），看**历史 / 跨副本 / 全文检索**——
  **Pod 滚动更新后旧日志只有 eslogs 能找回**。AI 一律用命令取日志，不要开浏览器点控制台。

## 4. 数据落在哪：MySQL 还是 ES

平台是**写 MySQL、查 ES** 的读写分离形态：业务表在 MySQL，报表/列表查询走 Elasticsearch，中间靠定时任务（XXL-JOB）同步。

**所以排查"页面没数据"要分三段看**：源表有没有 → 同步任务跑没跑 → ES 里有没有。
真实教训：需求指定的两个查询接口读的是某个 ES 索引，而该索引在 test 文档数是 **0**，真实数据在上游 MySQL 源表里——照需求原文实现会一条都同步不出来。

常见 test 索引：

| 索引 | 装什么 |
|---|---|
| `index_web_fpt_meta_test` | 绿色通道（非平台录入）主表 |
| `index_web_apply_meta_test` | 投标 |
| `index_web_collection_meta_test` | 集采 |
| `index_web_trade_data_test` | 交易报表 |
| `index_order_*_test` | 订单族 |
| `index_mall_product_*_test` | 商城商品 |

查库 `bash scripts/dbq.sh`，查 ES `bash scripts/esq.sh`（[工具箱](工具箱.md)）。
**ES 分页/导出默认上限 10000**，多来源汇总很容易超，超了是**静默截断**。

## 5. 前端

- 一共约 **52 个前端仓**：`02zhaocai-front/` 下 30 个当前仓 + `02zhaocai-front/scm-vue-all/` 下 26 个同名旧仓。
  **硬 grep 必踩错仓**——找页面一律先 `bash scripts/fe.sh find <中文关键词>`。
- URL 长这样：`http://<host>/procurementScheme/index.html#/<路由>`。
  **`/procurementScheme/` 这个前缀不在任何配置里**（各仓 `publicPath` 全是 `'./'`，那是 nginx 的目录名），
  没法从配置反推仓库，只能拿路由去反查——这正是 `fe.sh` 存在的原因。
- **有一类「动态页」的页面定义在后端 JSON 里**（`GET /obs/json/plateform/<module>/<type>`），**前端源码搜接口名永远搜不到**。
  用 `bash scripts/fe.sh json <module>/<type>` 查。
- 报表页 `#/reportForms/<flag>` 的接口是按路由参数拼的（`headList_<flag>` / `aggregation_<flag>` / `download_<flag>`），
  后端对应 `SourceQueryBuilderImpl_<Flag>`。
- 原理与边界见 [前端页面定位.md](前端页面定位.md)；离线四张表是 `前端页面地图.tsv` / `前端路由索引.tsv` / `前端上下文对照.tsv` / `前端动态页接口.tsv`，
  新会话直接 grep 即可，**不用重新 `fe.sh build`**。地图反映**本地当前分支**，同事分支上的新页面会显示"找不到"。

## 6. 权限模型：为什么"切个公司菜单就变了"

**四层，且岗位是按公司挂的**（库 `scm_ubm_<env>`）：

```
用户 ubm_member
  └─(ubm_member_company)  这个人能切换到哪些公司；company_sign=purchaser 内部 / supplier 供应商
  └─(ubm_member_job)      ★ 带 company_id ——【同一个人在不同公司挂不同岗位】
        └─(ubm_job_role)  岗位 → 角色（岗位表 ubm_job_manage，含适用层级 group_codes=JT/GS/QY/BS）
              └─(ubm_rbac_role_menu) 角色 → 菜单（ubm_rbac_menu，按 group_name 分三个门户）
```

- **所以"切公司"= 换掉整套岗位 = 换掉整套菜单**，不是数据范围变一变而已。
- ⚠ **`ubm_member_job` / `ubm_job_role` 里 `delete_sign=0` 才是当前生效**，`=1` 是历史版本
  （改一次权限就把旧行标 1、插一条新的 0）。不带这个条件查权限必错。
- ⚠ **`ubm_rbac_menu.state=1` 才是启用**；uat 里"保证金审批""标书费审批"已停用，合并成"保证金/标书费审批"。
- **供应商主账号没有岗位记录**，菜单由 `company_sign=supplier` + 用户类型隐式决定；`ubm_member_role` 只用于供应商子账号。
- 部分业务逻辑**在 Java 里硬编码角色编码**（如 `user.getUserRoles().contains("ROLE_SCM_SJCX0003")`），
  改权限前用 `bash scripts/perm.sh codeuse <角色>` 扫一遍。
- 别手工翻这些表：`bash scripts/perm.sh`（[工具箱](工具箱.md)）。
