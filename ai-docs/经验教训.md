## SQL / 数据

- **2026-09-08 cc：test 和 uat 的索引可能不一样，「在 test 上测通了」不等于 uat 也过**——`sc_plan_product_range` 在 uat 有唯一索引 `range_product_idx (product_code, category_code)`，test 上只有 PRIMARY。结果是「同一物料存多行」这类需求在 test 上怎么测都通，一到 uat 就被唯一键挡回来，而且报错在数据库不在代码里，容易往代码上找半天。→ **凡是需求会改变「一张表允许存几行」的语义，动手前先在 test 和 uat 各跑一次 `SHOW INDEX`**，DDL 按两边都要执行来写。
- **2026-09-04 cc：prod 交接包的"预检闸门"挡不住跳步执行**——手册写"预检回传后才放行灌库"，但运维拿到 02 就直接跑了（02 里没有技术拦停手段）。→ 以后高风险交接包必须**把「导入后审计」脚本随包预生成**（像这次的 07：覆盖检测用 `ledger_no` 段 × `ledger_id` 前缀反查、基线从 _bak 快照补取），并在灌库脚本头部写明"跳过预检时改跑审计"。写库类交付默认按"预检一定会被跳过"设计。
- **2026-08-10 cc：`date` 类型列 vs 带时分秒的 java.util.Date，MyBatis-Plus `wrapper.eq` 永远查不中**，「先查后插」的幂等就退化成每次都插。凡是拿 `new Date()`/`Calendar.getInstance()` 当日期条件去比 `date` 列，先 `DateUtils.truncate(d, Calendar.DAY_OF_MONTH)` 截到零点，或在 XML 里写 `DATE(列)=DATE(#{})`。
- **2026-08-10 cc：`serial_number` 之类的唯一索引不认 `delete_sign`**——软删除的行仍占着号，而生成流水号的 count 通常只数 `delete_sign=0`，于是软删后再新增同日记录必撞唯一键。清重复脏数据时用物理删除（先导 INSERT 备份），别习惯性软删。
- **2026-08-05 codex：MySQL `INSERT ... SELECT * FROM (SELECT 字面量 UNION ALL ...)` 的首行必须给每列显式不同的别名**，
  否则多个 `'1'` 会被当成重复列名报 `Duplicate column name '1'`。派生表首行统一补 `AS` 别名。
- **2026-08-04 codex：MySQL 8.0.18 的迁移临时表有两类兼容坑**——临时表默认 `utf8mb4_0900_ai_ci`，和业务表 `utf8mb4_general_ci` JOIN 会报 collation 冲突，
  建表时必须显式指定字符集/排序规则；同一条复合 SELECT 多次引用同一个临时表会报 `Can't reopen table`，各项校验要拆成独立 SELECT 存会话变量。
- **2026-08-05 codex：Excel 导出的日期不能只看接口 JSON**。公共导出按模板 `field_name` 从 Fastjson 对象取字符串，
  原始 `Date` 字段会在 Excel 里变成 `Thu Jul ... CST ...`。Controller 已用 `@DateTransfer` 生成格式化别名时，模板要绑定别名并设为 `String`；
  没有别名时 DTO/VO 用 `@JSONField(format=...)` 且模块显式声明 Fastjson 依赖。**日期修复必须实际下载 Excel 检查单元格**，接口返回正常不代表导出正常。
- **2026-07-24 cc：MyBatis-Plus 不能直接在 wrapper 上接 `.or()`**（会把前后 AND 条件串成 OR），必须 `.and(w -> ...)` 包括号；
  判空要 `isNull` 和 `eq("")` 都写。
- **数据类需求最阴险的两个空值：权限字段和时间字段。** 这两个字段一为空，整行会被数据权限过滤和时间范围筛选直接吃掉，
  页面上彻底看不见**而且不报错**。编码类字段落在字典取值范围外则是"列表能显示、下拉框筛不出来"，同样难发现。

- **2026-08-24 cc：公司这套 MySQL 是 Percona XtraDB Cluster 且 `pxc_strict_mode=ENFORCING`，`CREATE TABLE ... AS SELECT` 会被直接拒绝**（`ERROR 1105 ... prohibits use of CREATE TABLE AS SELECT`）。写备份/快照 SQL 一律拆成 `CREATE TABLE 新表 LIKE 原表;` + `INSERT INTO 新表 SELECT ...;` 两句（已实测放行）。顺带两条同源事实：`dbq.sh` 走 mysql 批处理，**遇第一个错误即整体中止**，所以脚本报错时后面的 UPDATE 不会跑一半；库账号 `admin@%` 对 `*.*` 全权限，**test 和 uat 都能写，库名打错就是改错环境**。
- **2026-08-24 cc：改名类需求写回滚脚本，不能用"按新名字反向 UPDATE"了事**——新代码一上线，就会有数据**天生就叫新名字**，反向 UPDATE 会把它凭空改成一个它从没用过的旧名。回滚默认应走"改前快照表 + 按主键 JOIN 还原"，只碰当初确实叫旧名的行；反向 UPDATE 降级为备用且必须带时间或主键白名单。

## 读需求 / 对口径

- **2026-09-08 cc：产品说「这块是我们前台配置的事，你给我传个值就行」时，别直接信——先在代码里把那个值的『算→存→递→用』四段跟一遍。** 本次产品三次强调审批分支是他们配流程图，我据此把工作流那块估成「照抄两遍加变量」；实读代码发现「传值」在这套系统里是四段：**算**（判定接口现在只返回 0/1/名字串，要改返回结构，三个前端调用点跟着改）、**存**（5 张单据表各加 2 列）、**递**（4 个流程适配器重载）、**用**（`if(isCollection==1){ 查台账拿集采执行单位; 设待响应; }` 散在 6~7 处 —— **谁来接这张单子是业务代码，不是流程配置**）。→ 判据：**流程引擎只认它收到的变量；凡是「这张单接下来去哪、归谁」的逻辑，只要不是纯粹的审批人选择，十有八九落在业务代码里**，对方说的「配置」通常只覆盖最后一段。
- **2026-09-08 cc：改造一个「已有功能」之前，先查它核心字段的填充率——它可能根本没被用起来。** 本次要改的「是否集采」，uat 实测 `sc_plan_product.is_collection` **99.9% 为空**（78430/78521）、`sc_plan` 99.5% 空、待采购池里集采的行**总共只有 9 行**。两个结论同时成立：**改动风险比想象的小**（真跑过这条链路的单子只有几十张），**但测试数据一条现成的都没有**，用例矩阵的场景全部要自己造。这两件事都直接改排期和测试计划，而**一条 SQL 三十秒就能问出来**。（`fieldcheck.sh` 那条探针原本是给「需求里用来筛选的字段」设计的，这次证明对「要改造的业务字段」同样必须做。）
- **2026-09-08 cc：业务说的「重复 / 唯一」永远是「在什么范围内唯一」＋「上级占了位下级还能不能配」，不是「哪几个字段全等」。** 本次 AI 给的默认是「类目+物料+层级+影响范围四字段全等才算重复」，产品当面给的却是两条完全不同的规则：① 某类目/物料一旦被**上级层级**（集团集采）配过，**它及其所有下级**都不许再被任何人配（祖先占位，字段等值判重根本表达不了）；② 其余的判重粒度是**板块**——同板块内不许重复、**跨板块可以**，而且**区域配的规矩要先换算成它所属的板块**再比。→ 遇到「什么算重复」，别问「比哪几个字段」，要问**「在什么范围内不能重复」**和**「上级配了下级还能不能配」**，并当场让对方举一个「看着像重复但其实允许」的例子——这个例子会把范围和层级两件事一起问出来。
- **2026-09-08 cc：替产品拟「最稳」的默认值时，把他的目标函数也写进去——他可能宁可先炸也要先管住。** 本次期初「是否强管控」AI 默认填「否」，理由写得很充分（填「是」会让七千多条规矩对应的单子一夜之间全走最严那档、全集团审批链一起变长）；产品当面直接选「是」，原话是「我肯定是要试呀」。→ 默认值照给（开工要用），但**别在文档里把它写成「业务上唯一合理的选择」**，把两个选项各自的代价并列摆出来让他挑；否则会像这次一样，围绕错误的默认已经写了一圈风险论证和期初脚本形态，答案回来全要返工。
- **2026-08-12 cc：需求文档里的叙述性文字和公式冲突时，以公式为准。** 产品口头/开篇讲的"这个页面只统计 XX"往往是背景解释，不是筛选条件。按叙述去实现，容易得出"数据里做不到、卡开发"的假阻塞。拿不准就把两种读法各算一遍数摆给用户看，别先下结论。
- **2026-08-12 cc：需求里的「A 或者 B」只会放宽，永远不可能收紧。** 想真正收窄必须写「并且」。所以把"或者"后面的枚举值从 3 个删到 1 个，是**空动作**——数还是那些数。看到 `或者` 先判断这句是想放宽还是想收紧，写错位置很常见。（本次实例：`是否集采=是 或者 采购业务类型=集团集采`，两边选中同一批数据，差集 0 条。）
- **2026-08-12 cc：看到"减去 XXX"先问为什么减——去重和排除长得很像，条件写法完全不同。** 去重（同一笔交易被两个系统各记一遍）必然带"主体闸门"（供应商/执行单位=某某），排除（不该算的类目）不带。把去重项当成排除项理解，就会问出"云采上的轴承怎么没被扣掉"这种错问题（答案：那是别人卖的，只记了一次，扣它才是错的）。
- **2026-08-12 cc：产品给出两套算法并认为它们等价时，别问他"选哪个"，直接把差额逐笔拆开给他看。** 他的逐笔判断才是真正的口径定义。本次拆完后产品自己改出了更准的新版本，比替他选好得多。配套：被问"是不是我上周加的测试数据搞坏的"，查**录入人 + 录入时间分布**是最快的证伪方式（跨月多人 → 不是单次操作），再说明清了测试数据差额还在（结构性）。

- **2026-09-03 cc：产品问「能不能引用隔壁系统的 X」时，先去本系统的 MDM/主数据库里搜同名表，不要直接去对接隔壁。** 本次产品在会上纠结「招采能不能引用云采那棵类目树」，实测招采自己就有 `scm_ubm_*.mdm_material_class`（四级全、1445 条，与云采 `ic_product_category_back` 1415 条编码一致、1413 条名称也一致，两边都是从 MDM 同步的），而且树查询接口、逐级取父接口、前端树组件全都现成。**同一份主数据在多个子系统各存一份是这套平台的常态**，跨系统对接的问题十有八九是个假问题——`information_schema.TABLES` 按关键词扫一遍库名表名，比问人快。
- **2026-09-03 cc：数据模型从「一个 key 一行」放开成「一个 key 多行」时，先全仓库搜 `selectOne`。** MyBatis-Plus 的 `selectOne` 命中 2 行以上抛 `TooManyResultsException`，改造前跑得好好的（因为业务上恰好没有重复），改造上线当天就炸，而且炸在调用方（本次是三个单据提交页全部提交不了），排查时很难联想到是台账改造引起的。
- **2026-09-03 cc：产品说「这个字段现在控制 XX」时不要照单全收，去搜一遍谁在读它。** 本次台账「集采执行单位」列产品说控制在线确认计划，实测全仓库无任何业务逻辑读取，真正生效的是另一个字典。照他的说法去设计校验规则，会做出一条没有任何约束力的规则。

- **2026-09-04 cc：判断一个后端匹配/校验规则的实际行为，必须把调用方传的参数追到前端赋值那一行，只读后端 SQL 会得出反向结论。** 本次后端是 `categoryCode` 精确相等，库里台账存 4 位、物料末级是 6/8 位，据此我判「这条规则一条都命中不了」；实际前端在提交前执行了 `e.categoryCode = categoryPathCode.split('-')[1]`，**把参数统一归一成二级**，规则其实完全生效。凡是结论落在「XX 永远匹配不上 / 这个功能是坏的」这种断言上，先 grep 调用方，看那个字段进接口之前被谁改过——**前端做归一化再传给后端在这套系统里很常见**（同款还有 9 处 `substring(0,4)`）。
- **2026-09-09 cc：用户/产品报「某一格数据没更新」，第一个要分的不是"哪天的数据"，而是「那一格显示的是一个旧数字，还是 `- -`/空白」。** 本次商城首页「当日下单额」恒显示 `- -`，原因跟数据、跟定时任务都没关系：**前端绑的是后端接口从来没有的字段名**（`tradeData.dailyAmount` vs VO 的 `yesterdayAmount`），而格式化函数写的是 `if (val == null) return '- -'`，JS 里 `undefined == null` 成立 → **取不到字段和"业务上就是空"被同一个兜底糊掉了，既不报错也不留日志**。同一个接口在另一张报表页上用法是对的（标签「昨日交易额」+ `yesterdayAmount`），所以**接口是好的、坏的是那一个绑定**。→ 判据：凡是「四格里只有一格不对」，先并排比对**前端绑定的字段名**和**后端 VO 的属性名（含 `@JsonProperty`/`@JSONField` 别名）**，比查数据库快得多；写兜底时也别用 `== null` 一把吞，区分「字段不存在」和「值为 0」。

- **2026-08-31 oc：查「有没有定时任务/XXL-JOB 处理器」只搜业务仓会得出假结论"没有"。** 定时任务的真实入口是调度中心网页配置 + 公共组件 `scm-assemblies-all/xxl-job-executor` 的 `simpleJobHandler` 通用反射桥（参数=应用-Bean-方法-JSON），业务仓里通常一个 `@XxlJob` 都没有。先搜 scm-assemblies-all，再问用户"网页上配过什么任务"。

- **2026-08-24 cc：判断"某功能有没有上生产"之前必须先 `fetch`，否则 `origin/prod` 是本地陈旧缓存，会得出反向结论。** 本次用没 fetch 的引用查出"`origin/prod` 没有 `PriceTrendCockpitProviderImpl`"，据此写进报告说"生产图表没接台账、改名不影响生产"；`git-release.sh audit --fetch` 之后发现生产**早就接了**，结论完全反过来（同一工作区 `scm-vue-hpc` 的本地 prod 落后远端 90 个提交）。`doctor.sh` 不带 `--fetch` 时那一栏同样是缓存值。**凡是要写进文档或转述给别人的分支结论，先 fetch 再下判断。**

## Shell / 命令

- **2026-08-17 dsh：dsh 插件 client.js 有两套互不兼容的契约**——动态插件运行时按 ESM 加载（`export function apply`），而 profile bundle（`dsh plugin --profile web add` 装成自启动）由 web 前端按**经典 script** 加载，必须 `window.__ModuleLoader__.load({id, factory})` 注册，factory 里 `require('react')`、返回 `{name, inject, apply}`。写错不是"插件不生效"，是一个 `export` 语法错误炸掉整页插件启动（页面报错+断连风暴）。host 路由与 client 的 RPC→URL 映射要对齐（remote.list→/dsh-remote/api/profiles 这种错位只在 HTTP 回退分支暴露）。
- **2026-08-11 oc：Nexus 上 `com.baomidou:mybatis-plus-*:3.4.2` 的 pom 是残缺的**（376 字节，只有坐标没有 dependencies，被污染），本地 `~/.m2` 若也残缺 → 编译报 `package com.baomidou.mybatisplus.annotation does not exist`。修复：从 `repo.maven.apache.org` 下载官方 pom 覆盖本地（备份为 `.pom.broken`），删掉 `_remote.repositories` 和 `*.sha1` 再编译；不要尝试改依赖版本（版本是 bom 管的）。先 `mvn dependency:tree` 看实际解析版本，别被 `dependency:get` 拉的版本带偏。
- **动态 SQL 放进双引号 shell 参数时禁止裸反引号**（2026-07-31 codex）：反引号会先被 shell 当成命令替换，查询在到达 MySQL 前就已被破坏。
  能省略标识符引号就省略，必须保留时改用 `.sql` 文件。失败后先确认数据库没执行写操作。
- **WSL 默认 shell 可能是 zsh，循环变量不要命名为小写 `path`**（2026-07-30 codex）：`path` 是 zsh 与 `PATH` 绑定的特殊数组，
  赋值后 `git`/`npm` 会突然找不到。统一用 `file_path`。拼 `<ref>:<path>` 时变量必须加花括号（`"${ref}:模块/Dockerfile"`），否则冒号后会被当变量修饰符。

## 网络 / Clash

- **2026-09-04 oc：Clash 不路由 `*.scmflow-*.jdsn.com` 这类内网域名，走代理必 502 且会间歇性"偶尔通"。** 任何手拼 curl 访问 DPS/平台内网域名都要 `--noproxy '*'`；判"服务挂没挂"前先确认自己没走代理（`wf.sh` 已封装，但手拼时无护栏）。
- **2026-08-24 codex：判断WARP/VPN是“公司网络限制”还是“普遍被墙”，必须用同一终端、同一配置切手机热点做物理直连A/B。** 热点成功只能把差异缩到公司办公出口（防火墙、策略或上游线路），不能继续猜具体拦截层；同时入口IP ping超时也不能替代隧道Healthy和真实业务流验收。
- **2026-08-24 codex：strict-TUN里给WARP/另一层VPN写规则级 `DIRECT` 不等于物理直连。** 外层连接可能再次被TUN捕获；改成 `route-exclude-address` 后又可能暴露公司网络根本不放行WARP ingress。必须先备份、只排一端、用真实Connected/业务流验证；直连失败时应恢复原路，再考虑按 `PROCESS-NAME` 指定另一代理节点，不能继续扩大Cloudflare直连网段。
